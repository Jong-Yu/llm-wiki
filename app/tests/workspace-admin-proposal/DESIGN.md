# 서버 관리자 콘솔 시안

2026-11-18, 여섯 번째 설계. [통합 설계](../../../docs/domains/access/WORKSPACE_ADMIN_DESIGN.md)에 대응하는 검토용 UI이며 실제 관리자 인증·API·서버 저장은 연결하지 않았습니다. 기능·화면 검증은 사용자의 사용성 승인을 뜻하지 않습니다.

## 이번 수정 범위

2026-11-18 후속: 사용자 목록의 소속 워크스페이스 열에 폭을 더 배분하고 제목·소속 칩을 한 줄로 유지합니다. 좁은 폭의 긴 이름은 말줄임하며 추가 소속 수는 생략하지 않습니다. 전체 소속은 기존 사용자 상세에서 확인합니다.

시안은 일반 로그인에서 시작합니다. 로그인/배정 대기 하단의 `관리자 로그인`, 설정 → 서버·계정의 `서버 관리` 행에 있는 `관리자 콘솔 열기`가 동일한 독립 인증 화면으로 연결됩니다. 서버 주소와 관리자 키만 입력하며 일반 사용자 로그인·소속은 선행조건이 아닙니다. 시안 키는 `demo-admin`이며 실제 키를 입력하지 않습니다. 성공 후 공간 목록, 취소/관리 종료 후 원래 화면과 진입 버튼으로 돌아갑니다. 실제 제품의 관리자 메뉴·`/admin` 라우트·관리 API 연결은 남아 있습니다.

관리 서버 주소를 바꿔도 일반 연결·계정·선택 공간은 유지합니다. 관리 세션은 메모리에만 두고 절대15분 만료, 창 복귀와 저장 직전에도 만료를 확인합니다. 만료 후에는 관리 DOM을 제거하고 같은 서버 재인증 뒤 원래 페이지·초안을 복원합니다. 서버 범위가 바뀌면 이전 관리 자료·검색·초안·영수증과 늦은 응답을 새 범위에 적용하지 않습니다. 입력 키는 제출·취소 시 비우고 중복 제출과 취소 후 늦은 인증 성공을 차단합니다.

관리 메뉴는 워크스페이스와 사용자 두 개입니다. 별도 전역 이력 화면을 제거하고 각 대상의 `변경 이력` 탭에서 해당 공간 또는 사용자의 기록을 확인합니다. 공간 이력은 사용자로, 사용자 이력은 공간으로 검색 범위를 좁힙니다. 대상마다 필터와 페이지가 따로 유지됩니다.

배정의 `뒤로가기`는 권한 설정 → 배정할 공간/추가할 사용자 선택 → 실제 출발 화면 순서입니다. 선택과 권한 초안을 유지하며 공간 선택을 일반 워크스페이스 홈으로 표시하지 않습니다. 상위 breadcrumb는 복귀 경로를 해당 조상까지 잘라내므로 빠져나온 배정 화면으로 다시 돌아가지 않습니다. 주 메뉴 선택은 해당 목록으로 이동하며 과거 복귀 경로를 초기화합니다. 결과 단계는 권한 입력으로 되돌리지 않고 출발 화면으로 복귀하며, 미완료 작업에 재진입하면 보존된 결과를 표시합니다. 개별 쓰기를 진행하는 동안에는 헤더 뒤로가기로 작업을 떠나지 않습니다.

이력 행은 첫 줄에 행동·대상·관리자·시각, 둘째 줄에 실제 권한 추가/회수 또는 이름 전후를 배치합니다. 좁은 화면과 긴 변경 내용은 자연스럽게 줄바꿈하며 정보를 생략하지 않습니다. 아이콘 조작의 반복되는 상자 테두리를 제거하고 공통 제품의 투명 버튼·hover·focus 표현을 따릅니다.

## 관리 과업과 화면 흐름

- 권한 설정의 선택 대상 오른쪽 연필 아이콘은 상단 뒤로가기와 같은 선택 단계 이동이므로 제거했습니다. 선택 변경은 상단 뒤로가기를 사용하며 권한 초안을 유지합니다.
- **새 사용자 배정:** 사용자 목록의 전체/배정 대기/소속 있음 필터와 행의 배정 아이콘에서 시작합니다. 대상 사용자를 고정한 채 공간 검색 → 권한 설정 → 배정으로 진행합니다. 사용자 상세에서도 같은 과업에 진입합니다. 필터는 현재 페이지가 아닌 전체 가상 자료에 적용합니다.
- **기존 공간 관리:** 첫 화면은 공간명·멤버·최근 변경·조작이 정렬된 목록입니다. 공간을 열면 멤버 관리가 먼저 나오고 목록에서도 멤버 추가·이름 편집·이력으로 바로 이동합니다. 이름만 보여 주는 일반 탭과 큰 반복 제목을 제거했습니다. 새 공간은 이름/고정 ID로 빈 공간을 만든 뒤 멤버 관리로 이동합니다.
- **멤버 배정:** 공간을 고정한 채 여러 사용자를 선택하고 같은 권한을 정한 뒤 배정합니다. 기존 소속은 선택에서 제외하고 저장 직전에도 덮어쓰지 않습니다. 선택을 다시 조정해도 권한 초안이 유지됩니다. 동명 사용자와 공간은 검색 결과·선택 칩·결과에서 고정 ID로 구분합니다.
- **부분 결과:** 사람별 개별 모의 PUT 결과를 완료/실패/확인 필요/미실행 아이콘과 라벨로 구분합니다. 응답 유실은 해당 작업의 모의 영수증으로만 확인하며 현재 소속을 보고 성공으로 추정하지 않습니다. 확인 중 쓰기와 완료 대상 재전송은 하지 않습니다. 실패·미실행만 재시도하고 전부 성공해야 `완료`를 표시합니다. 미완료 결과는 같은 작업으로 돌아오면 메모리에 유지합니다.
- **권한과 이력:** 저장 전과 이력에서 실제 추가/회수 권한을 보여 줍니다. 일괄 배정도 사용자마다 감사 항목을 만듭니다. 대상 링크는 실제 상세로 이동하고 현재 필터값을 표시합니다. 사용자별·공간별 이력의 필터 수명을 분리합니다. 저장 후 실제 진입 화면으로 복귀하고 성공 안내에서 해당 맥락의 이력을 열 수 있습니다.

- **화면 분리:** 공간 목록 → 공간 상세 → 이름 편집/멤버 선택/권한 편집, 사용자 목록 → 사용자 상세 → 공간별 권한 편집을 각각 별도 페이지로 구성합니다. 이전 목록은 DOM에서 제거하며 복귀할 때 검색어·페이지·선택 행 focus를 복원합니다. 업무 모달은 사용하지 않습니다.
- **아이콘 행동:** 뒤로가기·추가·편집·제외·새로고침·열기·페이지 이동은 공통 Button과 Icon으로 표시합니다. 이름도 해당 상세로 이동합니다. 저장과 소속 제외 확인은 문구를 유지합니다. 툴팁은 hover/focus로 열리고 Escape로 닫힙니다.
- **검색과 규모:** 사람·공간 선택에 native select를 사용하지 않습니다. 이름/고정 ID 검색, 20개 결과, 이전/다음 페이지, 로딩·빈 결과·검색 해제·선택 칩을 제공합니다. 동명일 때만 고정 ID로 구분합니다. 기본 가상 자료는 12명/6공간, 스트레스 자료는 240명/60공간이며 운영 인원 상한을 뜻하지 않습니다.
- **제품 UI 일치:** 실제 `AppShell.module.scss`의 셸·헤더·사이드바·본문·상태줄·타이포를 가져오고 `TemplateWorkspace.module.scss`의 검색·목록·페이지 스타일을 사용합니다. 독립 관리 메뉴는 워크스페이스/사용자입니다. 개인 작업 공간 전환·문서·AI 메뉴는 없습니다.
- **정보 구조:** 목록은 대상 아이콘/이름/소속 칩/업무 권한 배지/행동으로 구분합니다. 권한은 자료·지식 검토·개인 작업의 세 그룹, 이력은 행동 아이콘·대상·변경 전후·수행 관리자·시각으로 표시합니다. 부서·설명·handle 같은 새 데이터 계약을 만들지 않았습니다.

## 재사용과 모의 범위

`Button`, `TextField`, `Tabs`, `StatusNotice`, `Icon`, `BrandMark`, 테마 토큰과 컨트롤을 재사용합니다. 기존 앱에 공통 IconButton/Tooltip/SearchField가 없어 시안의 작은 `IconAction`과 `EntityBrowser`가 해당 상호작용만 보충합니다. 아이콘 버튼은 실제 `AppShell.backButton`과 `AiSessions.moreAction`의 투명 기본 표현을 따르고 키보드 focus와 coarse pointer의 44px 행동 영역을 유지합니다. 사용자 아이콘은 설치된 `lucide-react`의 `UsersRound`입니다.

일반 AppShell 컴포넌트 전체에는 업무 탐색과 AI 상태가 포함되므로 관리 전용 JSX에 **그 컴포넌트의 실제 스타일 클래스**를 적용합니다. 프레임의 독립 높이와 좁은 헤더의 아이콘 영역만 시안에서 보정합니다. 1280px에서 실제 제품 TemplateList 기준과 헤더 52px, 사이드바 208px, 상태줄 26px, 본문 13px/20px, 검색 36px, 배경색이 일치합니다. 접힌 폭은 현재 제품 CSS의 64px를 따릅니다. 문서의 목표 60px로 제품 CSS를 덮어쓰지 않았습니다.

일반 설정 진입에는 실제 `AppShell`, `ServerAccessForm`, `Tabs`, `PersonalAiSettings`, `ThemeSettings`를 재사용합니다. `WorkspaceTools`에 관리 진입 행을 끼우는 슬롯이 없어 계정 카드 JSX만 같은 구조·스타일로 조립했습니다. 연결과 AI 상태는 `previewEnvironment.ts`의 모의 bridge를 사용하며 운영 설정은 바꾸지 않습니다. 공개 가이드와 일반 업무 탐색의 전체 동작은 이번 관리자 진입 시안의 검증 범위가 아닙니다.

가상 자료만 메모리에서 수정합니다. 생성 후 빈 공간의 멤버 관리로 이동합니다. 추가 멤버의 초기 권한은 읽기이며 배정 전에 변경할 수 있습니다. 9개 업무 권한은 관리자 권한과 별개이며 빈 배열도 편집할 수 있습니다. 비어 있지 않은 권한은 읽기 의존성을 검증합니다. 소속 제외는 자료 보존을 안내하는 별도 확인 페이지입니다. 이름 충돌 시 초안과 최신값을 보여 주고 명시적으로 다시 편집합니다. 배정 대기 총인원 API나 새 사용자 메타데이터를 가정하지 않습니다.

로그인/배정 대기/설정의 진입 상황과 테마·부분 실패·충돌·인증 만료·권한 없음·서버 연결 실패·관리자 미설정·240명 전환은 하단의 접힌 `시안 설정 · 가상 자료`에 둡니다. 관리자 키 입력란은 공개 시안 키만 로컬에서 비교하며 인증 토큰을 만들거나 네트워크를 호출하지 않습니다.

MemoryRouter로 일반 진입과 `/admin` 하위 페이지를 전환합니다. 호스트 상태는 **version 6**의 경로·출발 화면·검색·페이지·focus·필터·자료 모드만 받습니다. 이전 전역 이력 경로는 공간 목록으로 정규화하되 어떤 복원 주소도 관리 인증을 대신하지 않습니다. UTF-8 16KiB 상한을 넘으면 검색·복귀·필터를 제외한 안전한 탐색 상태로 축소합니다. 자기 송신 echo는 무시합니다. 키·관리 세션·만료시각·변경 자료·초안·부분 결과·영수증은 호스트에 저장하지 않으며 새로 로드하면 다시 인증해야 합니다.

## 실행과 검증

저장소 루트에서 Node 24와 기존 앱 의존성을 사용합니다. 별도 패키지는 없습니다.

```sh
node app/tests/workspace-admin-proposal/build.mjs /absolute/output/workspace-admin.html
node app/node_modules/typescript/bin/tsc -p app/tests/workspace-admin-proposal/tsconfig.json --noEmit
node app/tests/workspace-admin-proposal/verify-v6.mjs /absolute/output/workspace-admin.html
```

타입 검사·대상 Oxc lint/format·IIFE 빌드(약630KB)를 통과했습니다. [v6 브라우저 결과](verification/admin-console-v6/results.json)는 로그인/설정/대기 진입, 잘못된 키와 미설정·연결 실패·권한 거부, 취소 뒤 늦은 응답, 종료 뒤 원래 일반 계정 보존, 호스트/주소 복원에 의한 인증 우회 차단, 만료 뒤 이름 편집 초안 복원, 320/736/1280px 화면과 키보드 초점, 키/세션의 호스트 비저장을 확인합니다. 브라우저 오류·외부 요청은0입니다. 실제 서버 인증·인가의 증거로 확대하지 않습니다.

8묶음을 통과했으며 가상시계로 실제15분 타이머가 편집 활동에 의해 연장되지 않는 것까지 확인했습니다. 취소/관리 종료 후 세 출발 화면의 진입 버튼으로 초점이 복귀합니다.

실제 앱의 진입 버튼·관리 인증/API·보호된 세션 저장·운영 정책은 구현하거나 변경하지 않았습니다. 검색은 로컬 배열·지연을 모의하며 서버 페이징 성능의 증거가 아닙니다. 접근성은 이번 과업의 라벨·키보드·초점·재배치 부분 검증입니다.

## 이전 시안 증거

[첫 시안](verification/results.json), [v2](verification/admin-console/results.json), [v3](verification/admin-console-v3/results.json), [v4](verification/admin-console-v4/results.json), [v5](verification/admin-console-v5/results.json)와 각 캡처는 당시 근거로 보존합니다. 현재 변경 부분의 검증이나 사용자 승인을 뜻하지 않습니다. v5는 이력 약59px·투명 아이콘·배정 복귀를, v4는 실제 공통 프레임 치수를 검증했습니다. `baseline.tsx`, `frame.scss`, `list-baseline.tsx`는 이전 제품 기준 캡처용입니다. `previewEnvironment.ts`는 v6의 일반 설정 진입에도 사용하는 모의 bridge입니다. 이전 verify 스크립트는 해당 버전의 절차이며 현재 인증 진입은 `verify-v6.mjs`로 확인합니다.
