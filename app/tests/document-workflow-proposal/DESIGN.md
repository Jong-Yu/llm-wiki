# 문서 처리 작업 UI 비교 시안

상태: 검토용 제안. 제품 코드·IA·도메인 결정을 확정하거나 배포한 기록이 아니다.

## 1. 사용자 목표와 동선

문서를 등록한 뒤 어느 화면에 있든 현재 진행, 중단 이유, 보관된 결과와 다음 행동을 찾을 수 있게 한다.

- 등록 → 같은 문서의 작업 상세 → 생성된 Wiki·관계 확인으로 이어진다.
- 다른 화면으로 이동한 뒤에는 헤더, 작업 목록, 문서 목록·상세의 **작업 보기**에서 같은 작업 상세로 돌아온다.
- 작업 열기·뒤로가기·상태 새로고침은 새 변환이나 AI 실행을 시작하지 않는다.
- 최초 등록에서 요청한 원본 보관 → 완전한 문자 변환 → MD 저장 → 관계 자동 추출·저장 흐름을 유지한다.
- 기존 Wiki의 관계 재추출은 후보 생성 → 비교 → 명시 반영이다. 최초 등록과 같은 저장 행동으로 합치지 않는다.

## 2. 비교할 화면과 UI 제안

| 화면                | 제안                                                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 작업 목록           | 현재 단계가 있는 문서별 행과 진행 중·조치 필요·완료/기록을 제공한다. 실행 전 작업도 발견 가능하게 남긴다.                                 |
| 단일 작업 상세      | 제목·원본 판본·현재 상태·다음 행동을 먼저 보여주고, 변환/본문/관계 단계와 저장된 결과를 이어 배치한다. 오류 원문은 접힌 기술 기록에 둔다. |
| 문서 목록의 기존 행 | 현재 표와 원본/Wiki 구별을 유지한다. 처리 단계와 조치 필요 여부를 요약하고 동일한 작업 상세로 연결한다.                                   |
| 원본 상세·헤더      | 작업을 발견하는 진입점으로 사용한다. 별도의 진행 내용을 중복 작성하거나 등록 화면으로 되돌리지 않는다.                                    |

한 원본 판본의 **최신 시도**와 **이전 성공 결과**를 따로 보여준다. 이전 성공 때문에 최신 실패를 완료로 덮지 않는다.
작업 열람과 문제 해결은 다르다. 실패·부분 완료·저장 미확인은 열어 보거나 알림을 읽어도 조치 필요에서 사라지지 않는다.
첫 기능 범위는 문서 처리다. AI 세션을 전역 **작업** 진입점으로 정리하는 방향을 비교하되, 질문·산출물 등 모든 유형 통합은 후속 범위다.
기존 메뉴 전체나 다른 업무 화면을 새로 구현한 시안으로 설명하지 않는다.

## 3. 상태와 허용 행동

| 상태                        | 사용자에게 보일 사실                                         | 허용 행동·제약                                                                                     |
| --------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 실행 전 (`ready`/`queued`)  | 접수됐으나 실행하지 않음. 자동 예약 큐·순번을 뜻하지 않음    | 실행 조건 확인 후 명시 실행. 이미 요청한 최초 등록의 자동 추출은 유지                              |
| 진행 중 (`running`)         | 현재 단계, 실제 제공된 처리 단위/전체 단위                   | 작업 보기·상태 새로고침·이 기기 실행 중단. 중복 실행 금지                                          |
| 실패 (`failed`)             | 실패 단계·이유와 이미 보관된 자료                            | 변환은 **다시 변환**. 분석은 실행 조건 검사 후 **미완료 단계 실행**                                |
| 일부 완료 (`partial`)       | 저장 성공한 결과와 미완료·미독 범위                          | 변환 미독 확인·다시 변환. 불완전 변환으로 추출 진행 금지. 분석은 영수증 확인 후 남은 단계 실행     |
| 결과 미확인 (`unconfirmed`) | 저장 결과 확인 필요. 실패·미저장으로 단정하지 않음           | 동일 요청의 **결과 확인**만. 새 등록·변환·저장 재전송 금지                                         |
| 완료 (`complete`)           | 요청한 저장 단계가 영수증으로 확인됨                         | 생성 문서·관계·결과 열기. 후속 대조 진행과 전문가 검토 전 상태는 별도 표시                         |
| 중단·취소 (`cancelled`)     | 저장 결과는 보존됨. 로컬 중단과 서버 작업 취소는 효과가 다름 | 로컬 중단은 조건 확인 후 재개 가능. 서버 취소 job은 재개 불가. 시안의 중단 조작은 로컬 중단을 모의 |

차단·기준 변경·권한 문제는 조치 필요의 구체 사유로 남긴다. 전체 수가 없으면 완료율·예상 시간을 만들지 않는다.
**다시 변환은 새 시도**다. 기존 checkpoint는 부분 결과 보존용이며 중단한 페이지부터 재개한다고 약속하지 않는다.
완료는 구조·저장 확인이며 원문 의미 정확성이나 전문가 승인을 뜻하지 않는다.

## 4. 연결 계약: 재사용과 후속 작업

| 구분      | 현재 재사용 가능한 계약                                                                              | 제품 연결 전 필요한 검토                                                                                                         |
| --------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 원본 기준 | source ID·판본·SHA256·registration revision, 현재 사용자·공간·profile·접근 revision 검사             | 표시용 원본 판본 그룹과 실행 기준을 분리. 최신 revision으로 기존 기준을 바꿔 끼우지 않기                                         |
| 변환      | `SourceConversionService.start/read/cancel`, 진행 단위·보고·미독·진단. 취소는 정확한 request ID 대조 | 전역 변환 목록과 시도 색인 없음. 새로운 변환을 이전 시도에 덮어 표시하지 않을 연결 필요                                          |
| 분석      | 목록/상세/단계별 영수증, `inspectExecution` → `execute(expectedJobRevision, mode)`                   | 미확인 영수증·변경 기준·다른 실행권·서버 취소를 그대로 차단. 완료된 본문 재저장 금지                                             |
| 작업 식별 | 변환 request/reference, 분석 job/run/result ID와 원본 참조                                           | 전체 여정의 지속적인 작업 식별·단계·시도 연결 필요. 원본 판본만으로 여러 시도를 합치거나 connection ID를 영구 키로 사용하지 않기 |
| 재시작    | 변환 보호 기록의 request ID·source로 같은 서버 보고 GET 복구. 분석 job/영수증 재조회                 | 로컬 진행·실패 설명·전체 시도 이력 복원은 불완전. 자동 AI 재실행 없이 확인 필요 상태와 미해결 목록을 복원할 계약 필요            |

현재 완료 알림은 모든 작업의 영구 원장이 아니다. 읽음 기록을 작업 상태·미해결 판정의 근거로 사용하지 않는다.
시안의 `/tasks?task=…`는 합성 작업의 화면 주소이며 제품 라우트·서버 식별자 계약의 확정안이 아니다.
근거: [분석 계약](../../src/shared/contracts/analysis.contract.ts), [변환 계약](../../src/shared/contracts/sourceConversion.contract.ts), [분석 서비스](../../src/main/backend/AnalysisService.ts), [변환 서비스](../../src/main/backend/SourceConversionService.ts).

## 5. 시안 구성과 범위

- 실제 `AppShell`, `Button`, `HeaderActions`, `WorkspaceSection`, `DocumentLibrary`와 기존 스타일을 재사용한다. 새 작업 목록·상세는 제안 영역으로 구별한다.
- 현재 화면과 제안 화면에 같은 합성 제목·원본·상태·화면 크기를 제공한다. 실패 예시의 `worker_failed`도 원인 확정이 아닌 표시 검토용이다.
- 비교 자료와 상태 전이는 `model.ts`의 모의 자료다. 실제 AI·운영 API·사용자 자료를 읽거나 변경하지 않는다.
- 재시도·결과 확인·중단은 시안 상태 전이만 모의한다. 실제 실행·저장·재시작 복원 성공의 증거로 사용하지 않는다.
- [보관 시안](preview.html)은 당시 검토 결과를 담은 단일 HTML이며 외부 연결 없이 열린다. 상단의 현재 화면/개선안·상태 사례·테마를 선택할 수 있다. 비교 전환 때만 합성 상태를 탭 저장소로 한 번 넘기며 실제 앱 재시작 복원은 모의하지 않는다. 원본/문서/관계 상세는 복귀 동선만 확인하는 축약 모의이며 기존 AI 연결/사용량 표시는 유지한다.

Node 24를 사용하는 이 폴더에서 `node build.mjs`, `node verify.mjs`로 새 시안을 빌드·검증한다. 새 HTML과 검증 결과는 Git에서 제외된 `app/test-results/document-workflow-proposal/`에 저장하고 기존 `preview.html`·`verification/`은 보존한다. 두 명령의 첫 인자로 HTML 출력·입력 경로를, 검증 명령의 둘째 인자로 결과 폴더를 지정할 수 있다.

## 6. 검증 기록

[자동 검증 12묶음](verification/results.json), 시안 strict TypeScript·Oxc lint·포맷·단일 HTML 빌드가 통과했다. 외부 HTTP 요청과 브라우저 실행 오류는 0이다.

| 항목                     | 실제 결과                                                                                    |
| ------------------------ | -------------------------------------------------------------------------------------------- |
| 동일 제목·상태·크기 비교 | 현재 AppShell·등록 진행·문서 목록과 개선안 캡처. 재시도/신규 접수 상태도 모드 전환 중 유지   |
| 재진입과 복귀            | 검색·필터 있는 목록→작업→목록, 문서 행→작업→문서, 작업→원본/문서/관계→같은 작업 확인         |
| 상태와 행동              | 실패 열람 후 유지, 미확정 결과 조회만, 조건 확인→명시 실행, 실행 전/로컬 중단 구별           |
| 등록                     | 실제 폼의 텍스트·모의 PDF 접수→독립 상세, 다른 진행 작업 유지. PDF는 변환 단계로 시작        |
| 화면                     | 1280/720/320px 가로 넘침 없음, 상태바 링크 잘림 없음, 화이트/다크 실제 적용·키보드 초점 확인 |
| 수동 시각 확인           | 작업 목록·실패 상세·문서 상태·320px 목록·다크 실패 상세 확인                                 |

검증 과정에서 비교 상태 초기화·결과 복귀 누락·미확정 상태의 미저장 단정·다른 작업 선택·시안 도구 가림·좁은 상태바 잘림을 보완했다. 선택자가 숨은 option/중복 문구를 가리키거나 hash 이동만으로 초기화를 기대한 검증 코드도 수정했다.

실제 변환·AI·서버 저장·권한 격리·영구 시도 이력·앱 재시작 복원·Windows 실행·릴리스는 검증하지 않았다. 긴 원본명·내용 스트레스 및 전체 접근성 감사도 미수행이다. 제품 연결 전에는 4절 계약 검토와 실제 실행 검증이 남는다.
