# 1280×720 공통 레이아웃과 디자인 대조

2026-10-25 · Wiki UI App 구현 4. 공통 기반의 구현과 개별 화면의 후속 작업을 구분합니다. 기준 시안은 [토큰 원본](../design/tokens.json)의 `source.path`이며 SHA-256이 일치하는 파일을 실제 Electron에서 열었습니다. 운영 자료 대신 기존 격리 시험 서버의 자료를 사용했습니다.

후속 반영(같은 날, 구현3): 공통 Sidebar를 시안의 AI 작업·지식 탐색·위키 문서·검토함 네 메뉴, 새 AI 요청, 실제 방문한 화면의 최근 작업, 하단 변경 이력·작업 공간으로 정리했습니다. 분석 작업 목록·결과물·비교·질문 근거·대응·앱 정보는 각 관련 화면 안의 링크로 연결했습니다. 상단에는 실제 선택된 공간/관점과 연결 설정 진입점을 표시합니다. 따라서 아래 최초 대조의 “메뉴 수 차이는 유지”, “상단 컨텍스트 후속” 및 메뉴 교체 시 진입 상실 우려는 이 후속으로 해소되었습니다. 관점 변경은 기존 연결 설정 화면에서 수행하며, 최근 작업은 앱 실행 중 방문한 화면만 표시합니다. 시안 전용 “화면 구성 지도”는 제품 메뉴에 포함하지 않습니다.

## 적용한 공통 동작

| 실제 작업 영역 너비 | 배치 | 자료·초안 수명 |
| --- | --- | --- |
| 1200px 이상 | 화면별 기존 2분할 또는 3분할 | 기존 화면별 폭 유지 |
| 900~1199px | 목록 280px + 본문 또는 정보; 목록도 접을 수 있음 | 패널을 숨겨도 마운트·입력·스크롤 상태 유지 |
| 900px 미만 | 목록 / 본문 / 정보 중 선택한 한 영역 | Tab은 표시된 패널에만 접근; 크기 변경 중 입력 포커스 보존 |

1280px 내부 창에서 앱 메뉴 148px를 제외한 작업 영역은 1132px이며 기본 본문 공간은 852px입니다. 기존 3분할의 482px보다 본문 공간을 확보했습니다. 1440px 내부 창은 기존 3분할을 유지합니다. 임계값은 화면 해상도가 아닌 ResizeObserver가 측정한 작업 영역에 적용됩니다.

- `WorkspaceLayout` / `WorkspacePane` / `WorkspaceToolbar`: 공통 배치와 패널 선택, 도구 모음 안쪽 가로 스크롤. 패널 이동 자체는 API 요청이나 저장을 실행하지 않습니다. 검토함·변경 이력·질문 근거 준비는 `panes`로 목록/상세 두 영역만 사용합니다.
- 적용 화면: 문서, AI 작업, 분석 범위·산출물, 지식 탐색, 검토함, 변경 이력, 질문 근거 준비, 질문·대화, 결과물, 변경 비교, 조건·개념 대응의 11개 경로.
- 앱 프레임: 전체 화면 밖 스크롤을 막고 메뉴에 독립 스크롤을 적용했습니다. 현재 14개 경로의 진입점을 보존합니다. 낮은 창에서는 시작/설정 영역의 바깥 여백을 줄입니다.
- Dialog / Panel: 제목·닫기·하단 actions의 크기를 유지하고 본문이 스크롤됩니다. feature가 제출 버튼을 본문 안에 둔 경우 해당 버튼은 본문 스크롤로 접근합니다.
- Electron: 커서가 있는 모니터의 `workArea` 안에 초기 창을 배치하며 최소 크기도 작업 영역보다 커지지 않게 제한합니다. 물리 해상도·OS 배율·앱 내부 크기는 서로 다른 값입니다.

## 1920×1080 시안 대조

같은 콘텐츠로 전체 화면 픽셀 비교를 한 것이 아니므로 임의의 “괴리율 %”는 만들지 않았습니다. 실제 치수, 색상 규칙, 정보 구조와 진입 경로를 비교했습니다. 시안의 원본·사용자·판본·승인 상태는 가상 예시이며 제품으로 복사하지 않았습니다.

| 항목 | 시안 / 기존 상태 | 반영 또는 남은 차이 |
| --- | --- | --- |
| 공통 프레임 | 헤더 52px, 메뉴 148px | 실제 렌더링에서 동일함을 확인 |
| 문서 패널 | 목록 316px / 정보 334px | 1920에서 유지; 제품의 패널 높이 970px 확인 |

| 사이드바 밀도 | 시안 padding 14px/9px, 메뉴 12px; 앱은 24px/12px, 메뉴 14px | 시안의 여백·서체 크기로 정렬; 메뉴 수 차이는 유지 |

| 지식 탐색 | 최초 대조에서는 자료 범위 폼과 조회 결과가 중심이었음 | 병행 화면 작업에서 자료 선택 Dialog·개념 목록·중심 개념 지도로 보완됨. 공통 280/가변/390 폭과 좁은 창 전환을 함께 유지; 채워진 지도의 상세 시안 대조는 화면 담당 검증과 구분 |

시안의 창 외곽선 2px 때문에 내부 패널 높이는 제품과 2px 차이가 날 수 있습니다. 문서 시안에 표시된 단계 흐름 영역은 추가로 약 110px를 사용합니다. 이를 공통 프레임에 일괄 추가하면 기존 제품의 세로 공간과 다른 화면까지 바뀌므로 이번 작업에서 추가하지 않았습니다.

## 시안 메뉴를 그대로 적용할 때 사라지는 진입점

현재 구현은 메뉴를 삭제하지 않았으므로 이번 변경으로 새로 접근 불가능해진 화면은 없습니다. 다음 표는 **현재 AppShell을 시안의 4개 주요 메뉴로 단순 교체하고 기존 하위 화면 연결을 추가하지 않을 경우**의 위험입니다. URL이 있다는 사실만으로 사용 가능한 UI 진입점으로 보지 않습니다.

| 현재 화면 | 시안에서 의도한 자리 | 단순 교체 시 문제 / 필요한 연결 |
| --- | --- | --- |
| 질문·대화 `/conversations` | 시안 `chat`인 “AI 작업” | 현재 “AI 작업”은 `/analysis` 작업 목록입니다. 메뉴 이름만 복사하면 대화 진입이 사라짐. 대화·작업 목록을 모두 연결해야 함 |
| 결과물 `/saved-results` | AI 작업의 결과물·편집·반영 | 현재 독립 목록의 진입은 앱 메뉴에 있음. 대화/AI 작업에서 결과물 목록으로 연결 필요 |
| 변경 비교 `/comparisons` | 원문 변경·비교·검토 흐름 | 현재 독립 비교 목록의 진입은 앱 메뉴에 있음. 문서/결과물에서 기존 비교를 여는 경로 필요 |
| 질문 근거 준비 `/questions` | 질문 작성 범위·근거 선택 | 현재 별도 준비 화면의 진입은 앱 메뉴에 있음. 대화의 범위 선택과 연결 필요 |
| 조건·개념 대응 `/correspondences` | 문서의 “다른 업무 기준과 비교”, “문서 간 대응 제안” | 시안 버튼의 실제 이동/대상 전달이 아직 연결되지 않아 메뉴 제거 시 진입 상실 |
| 앱 정보 `/about` | 작업 공간/설정 내부 | 시안에는 별도 메뉴가 없음. 설정에 실제 링크를 만들기 전에는 유지 필요 |

분석 범위·산출물은 문서 정보 패널의 실제 링크, AI 작업 목록은 계획 화면의 실제 링크가 있어 별도 접근이 가능합니다. 서버 연결은 초기 화면과 오류 안내에서 열 수 있으나, 시안의 상단 연결 버튼·작업 공간 메뉴를 구현하기 전에는 현재 명시 메뉴를 유지하는 편이 좋습니다. 시안의 “화면 구성 지도”, 시연·강제 실패 버튼은 제품 화면으로 만들 대상이 아닙니다.

## 1920보다 큰 화면의 추가 확인

사용자의 후속 요청으로 최신 제품을 독립 빌드하고 14개 화면 × 4개 내부 창 크기, 총 56조합을 실제 Electron에서 확인했습니다. 공통 작업 화면 11개의 오른쪽 패널과 자식 콘텐츠가 모두 창 오른쪽 끝에 도달했고, 바깥쪽 가로 넘침은 없었습니다. 초기 창 크기는 최대 1920×1080으로 열리지만 사용자가 창을 확대하면 콘텐츠 배치는 남은 공간에 맞춰 확장됩니다.

| 앱 내부 크기 | 문서 중앙 너비 | 지식 지도 중앙 너비 | 작업 화면 오른쪽 외부 빈 영역 |
| --- | ---: | ---: | ---: |
| 1920×1080 | 1122px | 1102px | 0px |
| 2560×1440 | 1762px | 1742px | 0px |
| 3440×1440 | 2642px | 2622px | 0px |
| 3840×2160 | 3042px | 3022px | 0px |

메뉴148px, 문서 목록316px/정보334px, 지식 목록280px/근거390px는 고정이고 중앙이 나머지를 받습니다. 내용이 짧아 패널 내부에 흰 공간이 보이는 것과 작업 영역 자체가 확장되지 않는 문제는 구분했습니다.

최대 너비가 있는 일반 페이지는 예외입니다. 시작·앱 정보는 1000px, 서버 연결은 1120px에서 멈추며 왼쪽 정렬과 바깥 여백이 유지됩니다. 앱 정보의 실제 정보 표는 별도로620px입니다. 3440 너비에서 시작/앱 정보 페이지 오른쪽에는 약2029px, 서버 연결 오른쪽에는 약1909px가 남았습니다. 이 화면의 오른쪽 여백은 현재 CSS의 최대 너비 설정에서 발생합니다.

추가로 드러난 화면별 후속은 문서 본문의 긴 한 줄과 지도 확대 배율입니다. 3440/3840에서 문서 본문이 넓은 중앙을 그대로 써 읽는 줄이 길어지고, 지도 SVG도 가용 너비에 비례해 노드·글자가 커집니다. 본문 읽기 폭과 지도 확대 정책은 화면별 조정 대상으로 남깁니다. 이번 후속에서는 제품 스타일을 바꾸지 않았습니다.
