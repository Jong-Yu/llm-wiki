# LLM Wiki 단계 수행

## 1. 단계 확인

- 실제 작업 경로와 접근 가능 여부를 확인하고 적용되는 `AGENTS.md`를 읽습니다. 기본 규칙은 [루트 AGENTS.md](../../../AGENTS.md)에 있습니다.
- [PLAN.md](../../../docs/PLAN.md)의 현재 상태와 완료 조건, [DECISIONS.md](../../../docs/DECISIONS.md)의 관련 결정을 읽습니다.
- 사용자 요청에서 이번에 수행할 한 단계를 정합니다. 요청과 기록이 충돌하여 범위를 정할 수 없으면 해당 작업 전에 확인합니다.
- 기존 파일을 살펴 재사용할 곳과 필요한 최소 변경을 정합니다. 다음 단계의 구현은 포함하지 않습니다.

## 2. 구현

- 선택한 단계의 완료 조건에 필요한 변경만 수행합니다.
- 독립적으로 진행할 전문 작업은 [역할·협업 규칙](../../../AGENTS.md#역할별-서브에이전트와-협업)에 따라 위임합니다. 필요한 역할만 호출하고 파일별 담당자를 정합니다. 전문 에이전트가 다른 역할의 도움이 필요하면 기존 실행 에이전트에 질문하거나 범위가 한정된 하위 작업을 요청할 수 있습니다.
- 데이터 보존과 파일 역할은 루트 작업 규칙을 따릅니다. 중요한 선택과 이유는 결정 기록에 남깁니다.
- 실행 방법이 생기거나 달라지면 [README.md](../../../README.md)를 갱신합니다. 아직 없는 실행 명령을 만들어 적지 않습니다.

## 3. 검증

- 해당 단계의 완료 조건에 맞는 검증을 실제로 실행합니다. 문서만 변경한 단계는 링크·구조·내용 일관성 등 변경 범위에 맞게 확인합니다.
- 구현 단계에서는 정상 동작과 데이터 보존에 영향을 주는 실패 경로를 확인합니다. 기존 사용자 문서로 쓰기 검증을 하지 말고 격리한 테스트 데이터로 확인합니다.
- 온톨로지·추출 프롬프트를 변경하면 구조·인용 검증과 의미 검증을 분리합니다. 기존 [재서술·합성 자료](../../../evals/ontology_cases.json)는 고정 사례 회귀이며 실제 원문 이해의 독립 검증을 대신하지 않습니다. 개발 사례로 프롬프트를 개선할 때는 최대 두 번으로 제한하고 남은 문제를 보고합니다.
- 실제 원문 의미 평가는 [루트의 원문 분리 평가 규칙](../../../AGENTS.md#역할별-서브에이전트와-협업)과 [D-021](../../../docs/DECISIONS.md)을 따릅니다. 원본 보유 검증자와 수집·관계 생성자를 이전 이력 없는 새 세션으로 시작합니다. 검증자가 원문·출처·hash·비공개 확인 질문을 먼저 고정하고, 생성자에게는 원문과 추출 지침만 전달합니다. 결과 고정 후 검증자가 원문·제출·공개 스키마를 대조합니다. 검증자에게 추출 프롬프트·정답·이전 점수를 전달하거나 중간 협업으로 답을 맞추지 않습니다.
- 이 평가 모드에서는 하위 세션의 일반 문서 읽기를 허용 입력 읽기로 대체하고 부모가 필요한 작업 규칙을 직접 전달합니다. 검증 후 노출된 자료로 개선하면 개발 사례로 전환하며 새 원문·새 세션으로 다시 평가합니다. 공유 파일 권한 격리나 모델 오류의 독립성까지 확보했다고 기록하지 않습니다. 실행 방법은 [README](../../../README.md#역할별-에이전트와-의미-검증)를 따릅니다.
- v2 변경은 v1 읽기 호환·재추출 표시, 한정어 보존·범위 검사, 검토 후보 분리·위조 승인 거부, 원문 변경 후 관계와 후보의 stale 처리, 기존 버저닝·CAS·실패 보존을 확인합니다. 모델이 채운 모호한 후보와 가상 답은 실제 사용자 승인으로 기록하지 않습니다. 후보의 검토 적절성과 근거 관계의 의미 보존도 따로 평가합니다. v1의 정답표로 v2 의미를 채점하지 않습니다.
- 실제 수행한 검증 방법과 결과, 실패 또는 미실행 항목을 계획의 검증 기록에 남깁니다. 자동 형식 검사만으로 기능이나 연결까지 검증됐다고 간주하지 않습니다.

## 4. 정리

- 이번 작업에서 만든 불필요한 임시 산출물과 중복 문서를 정리합니다. 기존 사용자 파일과 위키 원본·히스토리는 보존합니다.
- 모든 완료 조건을 충족했을 때만 계획의 해당 단계를 완료로 표시합니다. 충족하지 못하면 진행 상태와 남은 항목을 기록합니다.
- 변경 파일, 검증 결과, 다음 작업을 짧게 보고하고 이번 단계를 마칩니다. 요청받지 않은 다음 단계는 시작하지 않습니다.
