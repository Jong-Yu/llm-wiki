# LLM Wiki 기능 명세

기준일: 2026-10-30

LLM Wiki는 자료를 보관하고, 원문에서 지식을 추출하며, 사람의 검토를 반영한 지식을 질문과 문서 작성에 사용하는 작업 공간이다. 이 명세는 현재 소스 코드의 제공 기능을 정의한다. 설치본의 반영 시점과 실제 환경 검증 여부는 기능 구현 여부와 구분한다.

## 1. 기능 구성과 제공 범위

주요 화면은 문서, 온톨로지, AI 채팅, 설정이다. 자료 등록과 산출물 편집은 해당 업무에서 열고, AI 세션과 분석 작업은 헤더와 대상 문서에서 확인한다. 문서 간 관계의 별도 탐색 화면은 현재 노출하지 않는다.

| 구분 | 의미 |
| --- | --- |
| 앱 제공 | Electron의 화면과 업무 처리 경로가 연결된 기능 |
| 서버 제공 | API 또는 MCP로 제공하는 기능. 앱의 독립 화면 제공을 뜻하지 않음 |
| 환경 한정 | 명시한 실행 환경에서만 제공하는 기능 |
| 미제공 | 현재 제품 범위에서 사용할 수 없는 기능 |

아래 기능 ID는 명세를 참조하기 위한 번호이며 API 식별자는 아니다. 사용자 흐름은 [기능 흐름](FLOWS.md), 추출 의미와 판단 기준은 [추출 방침](EXTRACTION.md), 저장·권한 계약은 [시스템 구조](ARCHITECTURE.md)를 따른다.

## 2. 연결과 실행 설정

| ID | 기능과 사용자 입력 | 처리와 결과 | 제공 범위와 조건 |
| --- | --- | --- | --- |
| F-01 | 가입·로그인: 서버 주소, 이름 | 서버 인증 후 허용 작업 공간을 열고 연결 정보를 보호 저장한다. 서버 주소와 이름을 기억한다. | 앱 제공. 현재 PoC의 이름 기반 인증이며 회사 SSO를 제공하지 않는다. |
| F-02 | 작업 공간 연결: 허용 공간 선택 | 현재 사용자·소속·업무 권한을 확인하고 해당 공간의 자료를 조회한다. | 앱 제공. 역할별 조회 관점 선택은 제공하지 않으며 공간의 기본 조회를 사용한다. |
| F-03 | AI 실행 설정: Codex 또는 Claude Code, 모델·실행 경로 | 개인 PC의 실행 환경을 진단하고 선택한 CLI로 질문·분석을 실행한다. | 앱 제공. Wiki 로그인과 AI 제공자 로그인을 각각 사용한다. 제공자별 실제 검증 범위는 10절을 따른다. |
| F-04 | 연결 해제·로그아웃 | 메모리의 연결을 무효화하고 자동 복원과 늦은 응답의 표시를 차단한다. 보호 저장 정리 문제는 별도로 알린다. | 앱 제공. 네트워크에 연결되지 않아도 로그아웃할 수 있다. |

## 3. 자료 등록과 분석

| ID | 기능과 사용자 입력 | 처리와 결과 | 제공 범위와 조건 |
| --- | --- | --- | --- |
| F-05 | 자료 등록: 제목, 파일 또는 직접 입력한 텍스트 | 원본과 판본을 보관하고 후속 처리의 기준을 만든다. | 앱 제공. MD·TXT·PDF·DOCX·XLSX와 지원 이미지 형식을 받는다. 원본 파일·첨부는 20 MiB 한도를 적용한다. |
| F-06 | 본문 변환: 보관한 원본 판본 | 개인 PC에서 텍스트와 Markdown 표현, 원문 위치, 변환 보고를 만든다. 원본 상세에서 결과와 미독 범위를 확인한다. | 앱 제공. MD·TXT는 원문을 직접 사용한다. OCR·파일 구조 변환의 완료는 의미 정확도 보증이 아니다. |
| F-07 | 기본 분석 준비: 등록 원본·변환 참조, 저장할 문서 | 단일 Wiki Markdown과 온톨로지의 분석 작업을 접수하고 입력·규약·대상 판본을 고정한다. | 앱 제공. ‘Markdown 준비 시작’으로 변환·작업 준비를 진행하고 ‘AI 본문 준비·관계 추출 실행’에서 모델을 호출한다. 불완전하거나 저장이 확인되지 않은 변환 보고는 완료 입력으로 전달하지 않는다. |
| F-08 | AI 분석 실행·재개: 준비된 작업 | 본문 준비, 관계 추출, 검사, 단계별 저장을 수행한다. 실제 저장 영수증으로 본문과 그래프의 완료를 각각 표시한다. | 앱 제공. 본문만 저장됐으면 부분 완료이며 같은 작업의 남은 단계를 확인·재개한다. |
| F-09 | 기존 지식 검색·대조: 새로 저장한 추출 결과 | 원래 추출 AI 세션에서 기존 지식을 검색하고 근거를 읽는다. 후보, 제외 이유, 미확인점, 사용한 근거를 개인 실행 이력에 보관한다. | 앱 제공. 개인 CLI의 새 분석 후처리이며 일반 MCP 그래프 저장의 자동 부수 효과는 아니다. 실행별 조회는 첫 검색·추가 읽기·재검색을 합해 최대 5회이다. 자동 개체 병합이나 대응 승인은 수행하지 않는다. |
| F-10 | 검색·대조 다시 실행: 저장된 대조 대상 | 현재 대상의 원문·주장·판단을 읽어 같은 AI 세션에서 새 대조 실행을 만든다. 이전 결과를 함께 조회한다. | 앱 제공. 원래 제공자·보호된 로컬 세션 기록·접근 범위가 일치해야 한다. 기록이 없으면 다른 세션으로 대신 실행하지 않는다. |

## 4. 문서 조회와 편집

| ID | 기능과 사용자 입력 | 처리와 결과 | 제공 범위와 조건 |
| --- | --- | --- | --- |
| F-11 | 문서·원본 탐색: 검색어, 필터, 페이지 | Wiki와 등록 원본을 구분해 목록·상태를 제공한다. 선택한 문서와 원본 판본의 상세를 연다. | 앱 제공. 검색의 누락·한도·읽기 실패가 있으면 불완전한 결과임을 표시한다. |
| F-12 | 원본 상세: 원본과 판본 선택 | 원본 미리보기·다운로드, 변환 보고, 분석 작업, 연결된 Wiki를 제공한다. | 앱 제공. 원본 파일 자체를 앱에서 편집하는 기능은 제공하지 않는다. |
| F-13 | Wiki 본문 편집: 제목·설명·태그·Markdown | 하나의 편집 초안으로 보존하고 저장 전 줄별 비교를 제공한다. 저장 시 기준 판본을 검사하고 수정 전 전체 파일을 이력에 남긴다. | 앱 제공. 문서 ID와 원본 참조는 읽기 전용이며 Wiki 파일은 UTF-8 1 MiB 한도를 적용한다. |
| F-14 | 변경 이력·충돌 비교·판본 복원: 판본 선택 또는 충돌한 초안 | 원문을 정규화하지 않는 줄별 비교, 변경 구간 이동, 문맥 펼침, 메타정보·본문 구분을 제공한다. 충돌 시 최신 본문을 읽고 입력을 재검토한다. 과거 판본 복원도 새 저장으로 처리한다. | 앱에서 이력 조회·비교 후 선택 판본을 복원한다. 미저장 초안은 보호하며 충돌·응답 유실 시 현재 본문을 명시적으로 다시 확인한다. 좁은 화면은 한 열 비교를 사용하며 큰 변경은 계산 한도와 묶음 비교를 알린다. |
| F-15 | 기존 문서 재추출: 저장된 문서, 현재 판단 | 고정 입력으로 새 추출안을 준비·실행하고 후보·검사 보고를 비교한다. 진단의 원문 인용·실제 후보를 확인하고 기존 후보 편집으로 이동한다. 사용자의 명시 적용으로 그래프를 갱신한다. | 앱 제공. 본문 편집만으로 추출을 자동 실행하지 않는다. 기준이 달라지면 적용을 차단하며 과거 판단은 재검토 상태로 보존한다. |

| F-18 | 전문가 업무 판단: 대상 주장, 판단 내용, 적용 범위, 이유 | 원문에 없는 업무 판단을 별도 출처의 정책 이벤트로 기록하고 적용 상태를 표시한다. | 앱 제공. 전문가 정책 권한이 필요하며 원문 인용을 만들어 붙이지 않는다. |
| F-19 | 독립 관계 추가: 한 문서의 기존 주어·목적어, 관계, 근거 또는 판단 이유 | 현재 그래프의 기존 개체 사이에 사람이 관계를 추가한다. 원문 근거와 전문가 판단을 구별하고 별도 주장·이력으로 보관한다. | 앱·HTTP·tenant MCP 제공. 새 개체 생성과 문서 간 관계 생성은 제공하지 않는다. |
| F-20 | 검토·판단·관계 추가의 이력과 되돌림 | 전후 값, 이유, 출처, 행위 주체를 확인하고 해당 변경의 되돌림 이벤트를 남긴다. | 앱 제공. 원장 삭제나 옛 승인 일괄 복원으로 처리하지 않으며 현재 근거를 다시 검사한다. |
| F-21 | Clean Up: 문서, 미리보기 항목, 명시 선택, 이유 | 서버가 제공한 정리 가능 항목을 확인해 현재 목록 표시를 정리한다. 적용 이력·영수증·되돌림을 제공한다. | 앱 제공. 원문·기계 추출·검토 이력을 삭제하지 않는다. 미리보기 항목을 자동 선택하지 않는다. |
| F-34 | 작업 공간 검토함: 미검토·보류·재검토 상태 | 제한된 공간 집계로 주장, 이전 판단과 추출 상태를 모아 기존 상세·재추출 화면에 연결한다. | 앱·HTTP·tenant MCP 제공. 페이지와 실제 누락을 구별하며 조회만으로 승인·분석을 실행하지 않는다. 기존 AI 세션·작업 관리로 이동한다. |

## 9. 공통 완료 기준

사용자에게 보여 주는 완료 상태는 실제 저장 결과에 근거한다. 다음 조건을 모든 관련 기능에 적용한다.

- 원본 보관, 본문 저장, 관계 저장, 검색·대조 완료를 각각 확인한다. 후속 단계가 실패해도 성공한 저장을 반복하지 않는다.
- 본문 저장은 읽은 기준 판본을 검사하고 수정 전 전체 파일을 보존한다. 충돌한 초안을 새 판본 번호만 붙여 다시 제출하지 않는다.
- 질문·검토·추출의 근거에는 대상 문서와 당시 판본을 유지한다. 오래된 그래프와 판단을 최신 사실처럼 표시하지 않는다.
- 서버·사용자·작업 공간·접근 권한이 달라지면 이전 화면과 늦은 응답이 새 범위의 결과로 나타나지 않게 한다.
- 실행 중, 저장 완료, 저장 미확인, 부분 완료, 실패, 중단을 구별한다. 임시 파일 정리 경고는 저장 실패와 구분한다.
- 검색·대조의 결과 없음과 조회 불완전 상태를 구별한다. 원문 근거·AI 해석·전문가 판단의 출처를 보존한다.

## 10. 현재 실행 범위

현재 코드는 macOS·Windows Electron과 로컬 웹 테스트 진입점을 포함한다. 실제 Codex의 등록·추출·같은 세션의 후속 대조 연결 및 macOS 앱 사용을 확인한 기록이 있다. Claude의 실제 성공 실행과 Windows 실기기의 전체 사용 흐름은 검증이 남아 있다. 최신 화면 구획의 소스 구현과 설치 패키지 반영 시점도 별개이다.

범용 산출물 파일 생성·다운로드, 새 개체 수동 생성, 자동 개념 병합, 대응 자동 승인, 문서 변경에 따른 무인 일괄 재추출, 역할별 조회 관점 UI는 현재 제공 기능에 포함하지 않는다.
