# LLM Wiki 사용자 가이드

기준일: 2026-11-07 · 저장소의 데스크톱 앱 기준

LLM Wiki는 자료 원본을 보관하고, 읽고 고칠 수 있는 Wiki 문서를 만들며, 문서에서 추출한 개념과 관계를 AI 질문에 활용하는 지식 공간입니다. 이 가이드는 데스크톱 앱을 처음 연결하는 사람과 자료를 등록·검색·수정하며 업무에 활용하는 사람을 위한 안내입니다. 설치한 앱과 연결한 서버의 버전에 따라 제공되는 메뉴가 다를 수 있습니다.

제품의 목적·동작 원리·추구하는 가치를 먼저 알고 싶다면 [LLM Wiki 이해하기](INTRODUCTION.md)를 읽어 보세요.

화면을 보며 따라 하려면 앱의 **사용자 가이드** 또는 [화면 가이드](guide/index.html)를 먼저 여세요. 실제 앱의 캡처에서 조작 위치를 확인하고, 화면을 확대하거나 12개 장면을 차례로 넘길 수 있습니다. 처음 시작·지식 활용·수정과 관리의 세 과정으로 나눴으며, 이 문서는 세부 조건과 오류 해결을 찾아볼 때 사용합니다. 캡처의 작업 공간명은 **워크스페이스**, 사용자 이름은 **홍길동**으로 통일한 연습용 예시이며, 자료와 AI 응답도 모의 예시입니다.

### 처음 한 번 사용해 보기

1. [시작 설정](#시작-설정하기)에서 서버 계정과 개인 AI를 연결합니다.
2. **문서 → 문서 등록 → 텍스트 붙여넣기**에서 [연습용 텍스트](#텍스트를-붙여넣어-등록하기)를 입력합니다.
3. **등록하고 관계 추출**을 누르고 각 단계의 결과를 확인합니다.
4. **문서 열기**로 입력한 내용이 저장되었는지 확인합니다.
5. **관계 확인**으로 조건과 관계가 원문에 맞게 읽혔는지 확인합니다.
6. **AI 채팅**에서 문서 이름과 질문을 적고 답변의 **근거**를 엽니다.
7. 답변 아래의 **내려받기**로 파일 하나를 저장해 열어 봅니다.

## 기본 개념 이해하기

### 자료가 지식이 되는 과정

자료를 등록하면 원본을 보관하고, 필요하면 문자를 읽어 Markdown 문서로 저장합니다. 개인 AI가 이 문서에서 대상과 관계를 추출합니다. 이후 문서와 관계를 탐색하거나 AI에게 질문할 수 있습니다.

본문을 고치면 기존 관계는 이전 본문을 근거로 한 상태가 됩니다. 새 본문으로 관계를 다시 추출하고 변경 내용을 확인해야 문서와 관계를 함께 최신 상태로 유지할 수 있습니다.

| 용어 | 뜻 | 사용할 때 기억할 점 |
| --- | --- | --- |
| 작업 공간 | 함께 접근할 수 있는 문서와 지식을 모아 놓은 공간 | 같은 서버라도 권한과 작업 공간이 다르면 보이는 자료가 다릅니다. |
| 원본 | 처음 등록한 파일이나 붙여넣은 텍스트 | 이후 Wiki 본문을 수정해도 등록 원본은 바뀌지 않습니다. |
| Wiki 문서 | 앱에서 읽고 편집하는 Markdown 문서 | 문서 저장과 관계 추출은 서로 다른 처리입니다. |
| 판본 | 특정 시점의 원본 또는 문서 내용 | 현재 본문과 관계가 어떤 판본에 근거하는지 확인합니다. |
| 개체 | 문서에 등장하는 장치·조직·개념 등 관계의 대상 | 이름이 같아도 문맥과 근거가 다를 수 있습니다. |
| 관계·주장 | 대상 사이의 의미, 속성, 조건 등을 구조로 나타낸 내용 | AI가 만들었다는 사실만으로 원문에 맞는 해석이 확정되지는 않습니다. |
| 온톨로지 | 개체·관계·속성과 근거를 함께 담은 지식 구조 | 지도와 상세 정보를 통해 원문 근거까지 살펴봅니다. |
| 전문가 판단 | 사람이 업무상 적용할 해석이나 정책을 이유와 함께 기록한 것 | 원문에 적힌 사실과 사람이 정한 적용 판단을 구별합니다. |
| 후보 | 기존 지식과의 관련성 등 추가 확인이 필요한 제안 | 후보가 나왔다고 관계가 확정되거나 원문이 변경되지는 않습니다. |
| 개인 산출물 | AI 답변 등을 바탕으로 만든 개인 초안 | 파일로 내보낼 수 있으며 생성만으로 Wiki 본문에 반영되지 않습니다. |

### 결과의 상태 읽기

화면의 상태는 다음 행동을 판단하는 데 사용합니다.

| 표시되는 상황 | 의미 | 다음 행동 |
| --- | --- | --- |
| 변환 완료 | 파일에서 읽은 내용을 준비했습니다. | 변환 보고의 누락·미독 범위를 확인합니다. |
| 문서 저장 완료 | Wiki 문서를 저장했습니다. | 본문을 열어 제목·내용·표 등이 올바르게 들어왔는지 확인합니다. |
| 관계 추출 완료 | 해당 본문을 기준으로 추출 결과를 저장했습니다. | 관계와 인용을 살펴봅니다. 최초 추출 결과는 사람의 검토 전 상태입니다. |
| 미검토 | 사람이 해석을 확인하지 않은 내용입니다. | 중요한 업무에 사용할 부분의 근거를 확인합니다. |
| 오래됨·재검토 필요 | 본문이나 판단의 기준이 달라졌습니다. | 현재 본문과 비교하고 재추출 또는 재검토합니다. |
| 일부만 처리됨·미독 | 자료의 일부를 읽거나 처리하지 못했습니다. | 누락 범위를 확인하고 원본 대조 또는 다시 변환할 방법을 선택합니다. |
| 후보 | 검색·대조 결과로 제안된 내용입니다. | 근거와 차이를 살펴보고 실제 반영 여부를 판단합니다. |
| 오류·중단 | 해당 처리가 완료되지 않았습니다. | 이미 보관·저장된 단계와 아직 끝나지 않은 단계를 구별해 복구합니다. |

예를 들어 문서가 정상 저장된 뒤 관계 추출이 실패할 수 있습니다. 이때 자료 전체를 다시 등록하기 전에 저장된 문서를 열고 관계 추출만 다시 진행할 수 있는지 확인하세요.

## 시작 설정하기

### 시작 전에 준비할 것

| 준비물 | 필요한 작업 |
| --- | --- |
| 배포받은 LLM Wiki 설치 파일 | 데스크톱 앱 실행 |
| 운영 담당자가 안내한 서버 주소 | 계정 로그인, 문서와 지식 조회·저장 |
| 서버에서 사용하는 계정 이름 | 처음에는 회원가입, 이후 같은 이름으로 로그인 |
| 이 PC에 별도로 내려받아 설치하고 로그인한 Codex CLI 또는 Claude Code CLI | 관계 추출, AI 질문 등 AI 작업 |
| 문서 처리 환경 | PDF·DOCX·XLSX·이미지에서 문자 읽기와 OCR |

앱 계정 로그인과 개인 AI 로그인은 별개입니다. 앱 계정은 서버의 자료에 접근하는 데 사용하고, 개인 AI 계정은 이 PC에서 AI를 실행하는 데 사용합니다.

Windows x64 설치판은 배포받은 EXE를 실행해 설치합니다. 개인 문서 처리에 필요한 Python 환경과 패키지, Tesseract 및 한국어·영어 OCR 데이터가 포함됩니다. Codex와 Claude Code는 별도로 설치하고 로그인해야 합니다. 이전에 별도 프로그램 위치를 저장했다면 포함된 환경으로 자동 교체되지 않습니다.

macOS는 DMG를 열어 LLM Wiki를 응용 프로그램 폴더에 복사합니다. 개인 Python 문서 처리 환경과 OCR 환경은 별도로 준비합니다. 설치 파일의 서명·공증 상태에 따라 macOS에서 실행 허용 안내가 나올 수 있으므로 배포 담당자의 설치 안내를 확인하세요.

일반 사용자는 앱을 사용하기 위해 저장소를 내려받거나 개발용 실행 환경을 준비할 필요가 없습니다. 서버를 새로 준비해야 하는 경우에는 운영 담당자의 설치 안내를 확인합니다.

### 앱 안에서 사용자 가이드 열기

로그인 전에는 로그인 화면의 **사용자 가이드**, 로그인 후에는 사이드바 아래의 **사용자 가이드**를 누릅니다. 앱 안에서 화면 가이드를 읽고 원래 작업 화면으로 돌아갈 수 있습니다. 가이드는 앱에 포함되어 서버에 연결하기 전에도 볼 수 있습니다.

### 서버에 가입하고 로그인하기

1. 앱을 실행합니다.
2. 이 서버를 처음 사용한다면 **회원가입**, 기존 계정이면 **로그인**을 선택합니다.
3. **계정 이름**과 **서버 주소**를 입력합니다.
4. **가입하고 시작** 또는 **로그인**을 누릅니다.
5. 로그인 후 선택된 작업 공간을 확인합니다.

이전에 사용한 이름과 주소가 표시되면 바로 로그인할 수 있습니다. 다른 이름이나 주소를 사용하려면 **변경**을 누릅니다.

일반 로그인 화면에서 인증 토큰을 직접 입력할 필요는 없습니다. 앱이 인증정보를 처리하고 OS의 보호 저장을 사용합니다. 이 PC에서 보호 저장을 사용할 수 없다는 안내가 나오면 다음 실행 때 다시 로그인해야 할 수 있습니다.

서버 주소는 운영 담당자가 제공한 주소를 입력하세요. 원격 접속은 HTTPS 주소를 사용합니다. 같은 PC의 `localhost`, `127.0.0.1`, `[::1]`에 접속할 때만 HTTP를 허용합니다. 주소에 계정·암호·검색 조건을 덧붙이지 않습니다.

접속은 되었지만 작업 공간이 선택되지 않았다면 **설정 → 서버·계정 → 작업 공간**에서 공간을 고르고 **선택 적용**을 누릅니다.

### AI 연결 전에 CLI 설치하기

**AI를 연결하려면 사용할 Codex CLI 또는 Claude Code CLI가 이 PC에 먼저 설치되어 있어야 합니다.** LLM Wiki 설치 파일에는 AI CLI가 포함되지 않습니다. 앱의 **Codex 로그인 / Claude Code 로그인**은 설치된 CLI의 로그인을 돕는 기능입니다.

1. 사용할 AI를 고릅니다.
2. 아래 공식 안내에서 이 PC의 운영체제에 맞는 설치 방법을 선택해 CLI를 내려받고 설치합니다.
3. 설치가 끝나면 새 터미널을 열어 해당 CLI의 버전이 표시되는지 확인합니다.
4. 같은 PC·OS 사용자로 개인 AI 계정에 로그인합니다. 설치를 마친 뒤 앱의 로그인 버튼을 사용해도 됩니다.
5. LLM Wiki의 **설정 → AI 실행**으로 돌아와 연결 상태를 확인합니다.

| 사용할 AI | 공식 설치 안내 | 설치 확인 |
| --- | --- | --- |
| Codex CLI | [OpenAI 공식 Codex CLI 안내](https://learn.chatgpt.com/docs/codex/cli) | `codex --version` |
| Claude Code CLI | [Claude Code 공식 설치 안내](https://code.claude.com/docs/en/setup) | `claude --version` |

설치 후 앱에서 프로그램을 찾지 못하면 **AI 프로그램 자동으로 찾기**를 사용합니다. 계속 찾지 못하면 **프로그램 위치 · 문서 처리 진단**에서 실제 실행 파일을 선택하고 **변경한 위치 저장** 후 앱을 종료·재실행합니다.

### 개인 AI 연결하기

앞 절의 CLI 설치를 마친 뒤 진행합니다.

1. 사이드바 아래의 **설정**을 누르고 **AI 실행** 탭을 엽니다.
2. **Claude Code** 또는 **Codex**를 선택합니다.
3. 이미 이 PC의 같은 OS 사용자로 로그인했다면 앱이 로그인 상태를 확인합니다.
4. 로그인이 필요하면 **Claude Code 로그인** 또는 **Codex 로그인**을 누릅니다.
5. 열린 터미널이나 브라우저에서 로그인을 마칩니다.
6. 앱의 자동 확인을 기다리거나 **로그인 완료 확인**을 누릅니다. 이미 로그인했는데 확인되지 않으면 **이미 로그인했다면 다시 확인**을 사용합니다.
7. 필요하면 **AI 호출 확인**으로 실제 응답까지 시험합니다.

**AI 호출 확인**은 짧은 질문을 실제 AI에 보내는 작업이며 개인 계정의 사용량에 반영될 수 있습니다. 로그인 확인만 끝난 상태에서도 AI 작업을 시작할 수 있으므로 호출 시험을 매번 할 필요는 없습니다.

| AI 상태 | 뜻 | 다음 행동 |
| --- | --- | --- |
| **연결됨** | 실제 AI 응답까지 확인했습니다. | 사용할 작업으로 돌아갑니다. |
| **로그인은 확인됐어요** | 프로그램의 로그인은 확인했으며 실제 응답 시험 전입니다. | 작업을 시작하거나 **AI 호출 확인**을 사용합니다. |
| **연결이 필요해요** | 개인 AI 로그인이 필요합니다. | 선택한 AI의 로그인 버튼을 사용합니다. |
| **로그인을 기다리고 있어요** | 터미널·브라우저에서 로그인 중입니다. | 로그인을 마치고 **로그인 완료 확인**을 누릅니다. 중단하려면 **대기 취소**를 사용합니다. |
| **호출에 실패했어요** | 실제 호출이 실패했습니다. | 오류와 계정 한도를 확인한 뒤 다시 시도합니다. |
| **연결에 문제가 있어요** | 실행 파일이나 로그인 확인에 문제가 있습니다. | **설치 위치 변경** 또는 프로그램 자동 찾기를 사용합니다. |
| **상태 확인 필요** | 사용할 수 있는 확인 기록이 없습니다. | 로그인하거나 기존 로그인을 다시 확인합니다. |

AI 제공자를 바꾸고 해당 AI의 로그인이 확인되면 선택이 자동 저장되어 다음 AI 실행부터 적용됩니다. 이미 진행 중인 작업은 시작 당시 AI를 계속 사용합니다. 프로그램 파일의 위치를 변경했을 때는 별도 저장과 앱 재시작이 필요합니다.

### 프로그램을 찾지 못할 때

1. **설정 → AI 실행**에서 **프로그램 위치 · 문서 처리 진단**을 펼칩니다.
2. **AI 프로그램 자동으로 찾기**를 눌러 설치 위치를 다시 찾습니다.
3. 필요한 경우 **프로그램 위치 변경** 영역에서 해당 항목의 **파일 선택** 또는 **폴더 선택**을 눌러 실제 설치 위치를 고릅니다.
4. **문서 처리 환경 확인**을 누르고 문제가 있는 항목을 확인합니다. 정상 항목은 **확인된 프로그램**에 접혀 있습니다.
5. 위치를 바꿨다면 **변경한 위치 저장**을 누릅니다.
6. 앱을 명시적으로 종료하고 다시 실행합니다. 창을 닫아 숨기기만 해서는 새 위치가 적용되지 않습니다.

설정 가능한 위치는 AI 실행 파일, **문서 처리 프로그램 폴더**, **Python 실행 파일**, **문자 인식 실행 파일 (선택)**, **문자 인식 언어 폴더 (선택)**입니다. 경로를 모르면 운영 담당자에게 진단 결과와 함께 문의하세요.

프로그램 자동 찾기와 문서 처리 진단은 AI 설치나 로그인을 대신하지 않습니다. **문서 처리 환경 확인**은 실제 모델을 호출하지 않습니다.

## 화면 구성과 작업 공간 이해하기

### 주요 메뉴

| 메뉴 | 사용하는 때 |
| --- | --- |
| **문서** | 자료 등록, 이름·내용 검색, 문서 읽기·편집, 원본 확인 |
| **온톨로지** | 개념과 문서를 검색하고 관계·근거·용어 문맥 탐색 |
| **검토함** | 검토 대기·보류·재검토 항목을 확인하고 판단 기록 |
| **AI 채팅** | 지식에 질문, 자료 첨부, 웹 검색, 답변 내보내기 |
| **AI 세션** | 실행 중 작업, 최근 결과, 지난 실행 기록 확인 |
| **설정** | 서버·계정, AI 실행, 화면 테마 설정 |

상단에는 **뒤로가기**, 현재 위치, 화면별 작업 버튼이 표시됩니다. 창이 좁아 버튼이 보이지 않으면 **화면 메뉴**를 확인하세요. 사이드바는 **메뉴 접기 / 메뉴 펼치기**로 조절합니다. 접힌 메뉴에 마우스를 올리거나 키보드 초점을 주면 임시로 펼쳐집니다.

하단 상태바에서 연결, 현재 작업 공간, AI 실행 상태와 한도를 확인할 수 있습니다. 화면을 이동해도 이미 시작한 AI 작업은 계속될 수 있습니다.

### 작업 공간 바꾸기

접근할 수 있는 작업 공간이 여러 개이면 사이드바의 공간 이름에서 전환할 수 있습니다. 하나뿐이면 공간 이름만 표시됩니다. **설정 → 서버·계정**에서도 현재 공간과 연결 상태를 확인할 수 있습니다.

다른 공간으로 옮겨도 작성 중인 초안이 새 공간으로 옮겨지지는 않습니다. 전환 확인창이 나오면 현재 작업을 확인한 뒤 **전환**하거나 **취소**합니다. 전환이 실패하면 기존 공간을 유지합니다.

문서가 보이지 않으면 먼저 현재 서버·계정·작업 공간을 확인하세요. 권한이 없는 자료는 검색이나 화면을 바꾼다고 조회할 수 있는 것이 아닙니다.

## 자료 등록하기

### 파일로 등록하기

1. 사이드바에서 **문서**를 엽니다.
2. **문서 등록**을 누릅니다.
3. **파일 업로드**를 선택하고 **파일 선택**을 누릅니다.
4. 이 컴퓨터에 있는 파일 한 개를 선택합니다. 제목과 저장 이름은 확장자를 뺀 파일명에서 정해집니다.
5. 선택한 파일을 확인하고 **등록하고 관계 추출**을 누릅니다.
6. 원본 보관, 문자 변환, 문서 저장, 관계 추출의 진행 상태를 확인합니다.
7. **문서 열기**로 저장된 본문을 읽고, **관계 확인**으로 추출 결과를 확인합니다.

파일은 선택한 PC에서 읽어 서버에 보관합니다. 서버의 파일 경로를 입력하는 방식이 아닙니다. 현재 선택 창에서는 파일을 한 개씩 등록합니다.

같은 저장 이름의 문서가 있으면 **이름이 겹칩니다** 안내가 나옵니다. **번호를 붙여 등록**을 선택하면 `이름-2`와 같은 새 이름으로 등록합니다. 기존 문서를 갱신하려는 경우에는 취소하고 해당 문서의 본문 편집 또는 관계 재추출을 이용하세요.

문서 쓰기 권한이 없는 경우 버튼은 **원본 보관**으로 표시됩니다. 이 경우 원본 보관까지만 진행하므로 문서 생성·관계 추출까지 완료한 것으로 판단하지 않습니다.

### 텍스트를 붙여넣어 등록하기

1. **문서 → 문서 등록**에서 **텍스트 붙여넣기**를 선택합니다.
2. **문서 제목**에 자료를 구별할 수 있는 이름을 입력합니다. 제목은 최대 200자입니다.
3. **본문**에 텍스트 또는 Markdown을 붙여넣습니다.
4. **등록하고 관계 추출**을 누릅니다.
5. 완료 후 저장된 문서와 관계를 각각 확인합니다.

붙여넣은 최초 텍스트도 원본으로 보관합니다. 나중에 본문을 수정하더라도 최초 입력과 수정 후 문서를 구별할 수 있습니다.

연습용으로는 다음처럼 짧고 관계가 분명한 자료를 사용할 수 있습니다. 아래 내용은 사용 방법을 익히기 위한 가상 예시입니다.

```text
제목: 예시 운영 안내

요청을 접수하면 담당자가 내용을 확인한다.
필수 정보가 없으면 담당자가 보완을 요청한다.
처리가 완료되면 요청자에게 결과를 안내한다.
```

등록 후 “예시 운영 안내에서 보완을 요청하는 조건은 무엇인가?”라고 질문해 보면 본문, 추출한 관계, 답변의 근거를 연결해 확인할 수 있습니다.

### 지원 파일과 크기

| 종류 | 형식 | 확인할 점 |
| --- | --- | --- |
| 일반 텍스트 | MD, TXT | UTF-8 파일을 사용합니다. 등록 시 원문을 그대로 사용합니다. |
| 문서 | PDF, DOCX | 본문·표 등의 변환 결과와 미독 범위를 확인합니다. |
| 스프레드시트 | XLSX | 시트와 셀 위치를 기준으로 읽습니다. 원본의 화면 배치를 그대로 재현하지 않습니다. |
| 이미지 | PNG, JPG, JPEG, GIF, WebP, BMP, TIF, TIFF | OCR 준비 상태와 글자 인식 결과를 확인합니다. |

등록 원본 파일과 붙여넣기 입력의 상한은 20 MiB입니다. 저장하는 Wiki 문서는 UTF-8 기준 1 MiB 이하여야 합니다. 원본 등록이 가능해도 변환한 본문이 저장 제한을 넘을 수 있으므로, 오류 안내가 있으면 자료를 의미 있는 범위로 나누어 준비합니다.

PPTX는 현재 등록 파일 형식에 포함되지 않습니다. PowerPoint 내보내기를 지원하는 것과 PowerPoint 원본을 읽는 것은 별개입니다.

### 변환 결과와 미독 확인하기

등록 진행 화면의 **처리 기록**에서 **최초 Markdown 변환 기록**, **변환한 본문과 미독 구간 확인**을 펼쳐 보세요. 핵심 조건·표·수치가 자료에 들어 있다면 원본과 변환 본문을 대조합니다.

| 자료 | 현재 읽는 방식과 주의할 내용 |
| --- | --- |
| PDF·이미지 | 문자 추출 또는 OCR을 사용합니다. 인식 성공만으로 글자·읽기 순서·표의 의미가 정확하다고 보장되지는 않습니다. |
| DOCX | 문단과 표 셀을 읽습니다. 머리말·꼬리말·각주·미주·주석·변경 추적·텍스트 상자·이미지 내용·표 안의 표 등은 읽지 못한 범위로 알릴 수 있습니다. |
| XLSX | 원본 구조, 시트·셀 위치, 수식과 저장된 계산값을 기록합니다. 수식을 재계산하지 않으며, 계산값이 없으면 미독으로 표시할 수 있습니다. 색이나 조건부 서식의 표시 의미도 직접 확인합니다. |

변환에 필요한 프로그램이 준비되지 않았다면 **설정 → AI 실행 → 프로그램 위치 · 문서 처리 진단 → 문서 처리 환경 확인**에서 상태를 확인합니다. 원본이 보관된 뒤라면 새로 업로드하기 전에 **본문 변환 다시 시도**를 사용할 수 있는지 살펴보세요.

### 등록이 중간에 멈췄을 때

| 안내 또는 상태 | 할 일 |
| --- | --- |
| 파일 선택 실패 | 지원 형식, 파일 크기, 실제 일반 파일인지 확인합니다. MD·TXT는 UTF-8인지 확인합니다. |
| 등록 결과 확인 필요 | **등록 결과 확인**으로 원래 요청의 보관 결과부터 확인합니다. |
| 본문 변환 실패 | **본문 변환 다시 시도**를 누릅니다. 이미 보관한 원본을 다시 올릴 필요는 없습니다. |
| 접수·저장 상태가 불확실함 | **진행·저장 상태 확인**으로 기존 요청부터 확인합니다. |
| 본문만 저장됨 | **문서 열기**로 본문을 보존한 상태를 확인하고, AI 설정과 추출 상태를 확인합니다. |
| AI 연결 실패·사용 한도 | 설정을 보완한 뒤 표시되는 **관계 추출 다시 실행** 또는 문서의 **관계 재추출**을 사용합니다. |
| 서버·계정·작업 공간이 바뀜 | 원래 범위로 돌아와 **원래 작업 범위 재확인**을 사용합니다. |
| 저장 완료와 임시 파일 정리 경고가 함께 표시됨 | 저장된 결과를 확인하고 정리 경고를 별도로 처리합니다. 같은 저장을 반복하지 않습니다. |

처리가 끝나면 **등록 원본 열기**, **분석 작업 상세**, **문서 목록**, **다른 문서 등록**으로 이어갈 수 있습니다. 최초 등록에서 저장한 관계는 검토 전 상태입니다. 중요한 관계는 원문 인용과 함께 확인하세요.

## 문서 찾고 읽기

1. **문서**를 엽니다.
2. **문서 이름이나 내용으로 검색 (Enter)** 입력창에 검색어를 넣고 Enter를 누릅니다.
3. 필요하면 **전체 문서 / 추출 완료 / 재추출 필요 / 미추출**로 범위를 좁힙니다.
4. 문서 행을 선택해 본문을 엽니다.
5. 관계 상태, **문서 정보**, 버전 칩을 확인합니다. 업로드한 파일 자체가 필요하면 **원본 보기**를 누릅니다.

검색 결과가 여러 페이지이면 페이지 버튼으로 이동합니다. 조회 한도나 읽기 실패 안내가 있으면 현재 결과가 전체가 아닐 수 있습니다. 결과가 없을 때는 검색어·필터와 현재 작업 공간을 함께 확인하세요.

문서 본문은 읽고 편집할 수 있는 Markdown입니다. 원본의 페이지·표 모양·글꼴과 같지 않을 수 있습니다. 중요한 원문 형식은 원본 파일을 내려받아 확인합니다.

문서를 바탕으로 질문하려면 **AI 채팅**으로 이동해 문서 이름과 원하는 질문 범위를 구체적으로 적습니다.

## 문서 본문 수정하고 판본 복원하기

### 본문과 문서 정보 수정하기

1. 문서를 열고 **본문 편집**을 누릅니다.
2. Markdown 본문을 수정합니다.
3. 필요하면 접힌 문서 정보를 열어 **제목·태그·설명**을 수정합니다. 일부 과거 문서는 이 정보의 편집을 지원하지 않을 수 있습니다.
4. **변경 내용 확인**으로 저장 전후를 비교합니다.
5. 보완할 부분이 있으면 **계속 편집**, 확정하려면 **저장**을 누릅니다.
6. 읽기 화면에서 수정한 내용과 관계의 현재 상태를 다시 확인합니다.

문서 ID와 원본 연결은 읽기 전용입니다. 본문 편집으로 업로드 원본 파일을 바꾸지는 않습니다.

저장할 때 수정 전 전체 문서를 이력으로 보존합니다. 메타정보를 포함한 저장 문서 전체는 UTF-8 기준 1 MiB 이하여야 합니다. 한도 오류가 나오면 중요한 내용을 임의로 잘라 버리지 말고 문서를 나눌 범위를 검토하세요.

**취소**는 읽기 화면으로 돌아가는 행동입니다. 작성한 초안을 명시적으로 폐기했다는 뜻은 아닙니다. 화면 이동 중에는 초안을 유지하지만 앱을 종료하면 저장하지 않은 초안은 사라집니다. 필요한 변경은 종료 전에 저장하세요.

### 다른 사람이 먼저 수정한 경우

같은 문서를 다른 사용자나 AI가 먼저 수정했다면 충돌이 표시될 수 있습니다.

1. 현재 서버의 최신 본문과 내 수정 내용을 비교합니다.
2. **최신 본문을 기준으로 다시 작성할 내용**에 필요한 변경을 재반영합니다.
3. **검토한 본문으로 비교 계속**을 누릅니다.
4. 변경 내용을 다시 확인한 뒤 저장합니다.

오래된 본문을 다시 보내 최신 변경을 덮어쓰지 마세요. 잠시 저장이 혼잡하다는 안내와 문서 충돌은 다른 상태이므로 화면의 안내에 맞게 처리합니다.

### 이전 판본 비교하고 복원하기

1. 문서의 버전 칩을 눌러 **버전 선택**을 엽니다.
2. 확인할 과거 버전을 선택합니다. 기본적으로 바로 앞 버전과의 차이를 보여 줍니다.
3. 현재 문서와 비교하려면 **현재 본문과 비교**를 선택합니다.
4. 복원할 내용을 확인한 뒤 **이 버전으로 복원**을 누릅니다.
5. 복원 후 본문과 관계의 상태를 확인합니다.

복원은 선택한 과거 내용을 새 판본으로 저장합니다. 복원 직전의 현재 문서도 이력으로 남습니다. 과거 버전을 지우거나 과거 관계의 검토 승인을 되살리는 동작은 아닙니다.

저장하지 않은 초안, 저장 결과가 확인되지 않은 상태, 읽기 전용 권한에서는 복원이 제한됩니다. 먼저 초안과 저장 상태를 정리하세요. 복원한 본문에 맞는 관계가 필요하면 관계 재추출을 진행합니다.

## 등록 원본과 원본 판본 확인하기

문서 목록에서 원본을 선택하거나 문서 상세의 **원본 보기**, 등록 결과의 **등록 원본 열기**를 사용합니다.

1. **버전** 선택 상자에서 확인할 원본 판본을 고릅니다. 등록 시각과 **최신** 표시로 구별합니다.
2. **문서 정보**에서 원본과 판본의 등록 정보를 확인합니다.
3. 텍스트 원본이면 표시된 내용을 읽습니다.
4. 다른 형식에서 **이 형식은 미리보기를 지원하지 않습니다**가 나오면 **내려받기**로 원본 파일을 열어 확인합니다.
5. **생성된 문서**를 누르면 연결된 Wiki 문서로 이동합니다. 연결 문서가 여러 개이고 다음 조회가 가능하면 **다음 문서 범위 확인**을 사용합니다.

원본 상세의 **내려받기**는 선택한 원본 판본 자체를 받습니다. **내보내기**는 연결된 첫 Wiki 문서의 현재 본문을 지원 형식으로 바꿉니다. 원래 표·서식·그림이 필요한 경우에는 원본의 **내려받기**를 선택하세요.

아직 분석하지 않은 원본은 **분석 시작**, 이미 작업이 연결된 원본은 **작업 보기**로 이어집니다. 같은 원본 판본에 기존 작업이 있다면 새 작업을 중복으로 접수하기 전에 그 작업을 확인합니다.

## 관계 재추출과 결과 반영하기

### 최초 추출과 재추출의 차이

최초 등록의 **등록하고 관계 추출**은 문서와 첫 관계의 저장 결과를 확인해 제공합니다. 이후 기존 문서에서 실행하는 **관계 재추출**은 새 후보를 만들고, 이전 결과와 비교한 뒤 명시적으로 반영하는 절차입니다.

본문 저장만으로 관계가 다시 추출되지는 않습니다. 재추출 후보를 만들었다고 기존 관계가 곧바로 바뀌는 것도 아닙니다.

### 저장된 본문으로 새 후보 만들기

1. 문서에서 현재 저장된 본문이 의도한 내용인지 확인합니다. 편집 중이라면 먼저 저장합니다.
2. **관계 재추출**을 누릅니다.
3. **추출 중…** 상태를 확인하고 완료를 기다립니다.
4. **결과 비교·반영**을 엽니다.
5. 이전 관계와 새 후보, 추가되거나 사라진 관계, 원문 인용, 진단 결과를 확인합니다.

### 사라진 관계 판단하기

새 후보에서 빠졌다고 이전 관계가 거짓이거나 삭제되어야 하는 것은 아닙니다. 원문에서 실제로 사라졌는지, 이번 추출에서 누락했는지 살펴보세요.

**이번 비교의 판단**에서 필요한 판단을 선택하고 **미발견 판단 기록**으로 저장합니다.

| 선택 | 의미와 필요한 확인 |
| --- | --- |
| **전체 재추출 요청 기록** | 판단 이유와 현재 원문의 정확한 인용을 남깁니다. 기록만으로 AI가 실행되지는 않습니다. |
| **현재 근거로 복구 초안** | 현재 근거와 복구할 전체 항목을 지정해 초안을 만듭니다. 전체 항목 JSON을 입력하는 고급 절차이며, 반영 후 새 버전에서 검토해야 합니다. |
| **이번 비교에서 제외** | 원문 전체를 확인한 뒤 이번 비교에서 제외합니다. 과거 사실을 삭제하거나 부정한다는 뜻은 아닙니다. |

실제로 AI를 다시 실행하려면 **개인 AI로 새 후보 만들기 → 명시 AI 재추출 실행**을 사용합니다. 판단 기록과 실행 요청을 구별하세요.

### 검사하고 반영하기

1. **검사**를 실행하고 진단을 확인합니다.
2. 추가·사라진 관계와 근거 전체를 실제로 살펴본 뒤 화면의 확인 항목을 선택합니다.
3. **검사 후 반영**을 누릅니다.
4. **관계가 새 버전으로 바뀌었습니다. 추가된 관계를 검토해 주세요.** 안내를 확인합니다.
5. 필요한 경우 **현재 새 관계 검토 읽기**로 현재 관계를 읽고, 실제 검토한 주장만 선택해 **명시 범위 완료 기록**을 남깁니다.

검사 통과는 저장 조건을 확인한 결과입니다. 추출의 의미가 정확하다는 판단이나 문서 전체의 승인을 대신하지 않습니다. 명시 범위 완료 기록도 선택한 범위에만 적용됩니다.

본문·검토·추출 규약이 도중에 달라져 입력 기준이 오래되었다면 최신 본문을 확인한 뒤 **관계 재추출**로 새 후보를 준비합니다. 고급 절차에서는 **전체 원문·이전 추출 준비**로 새 입력 기준을 준비할 수 있습니다. 오래된 초안을 그대로 밀어 넣지 않습니다.

다른 기기 등에서 같은 추출안의 후보·판단 기록만 갱신되었다면 **현재 추출 결과 다시 읽기 → 대조한 서버 후보로 새 편집 시작**으로 서버 기록을 다시 확인할 수 있습니다. 이 동작만으로 오래된 본문·규약 기준이 갱신되지는 않습니다.

응답을 받지 못한 경우에는 **같은 요청 기록 조회**, 실행 접수가 불확실하면 **같은 실행·후보 확인 기록 조회**로 원래 요청부터 확인합니다.

### 기존 지식과의 검색·대조 읽기

분석 작업의 **기존 지식 대조**는 추출 저장 후 다른 지식과의 관련 후보를 찾은 결과입니다. 확정 관계나 자동 병합 결과가 아닙니다.

- **실행 기록**에서 최신 결과와 이전 결과를 확인합니다.
- **최신 자료로 검색·대조 다시 실행**은 검색과 대조를 다시 수행합니다. 이전 결과와 저장된 관계는 보존됩니다.
- 진행 중인 대조는 **이 대조 중단**으로 멈춥니다.
- 조회 누락, 조회 한도, 재확인 필요 안내가 있으면 후보 0개를 “관련 지식이 전혀 없음”으로 해석하지 않습니다.

## 온톨로지에서 개념과 관계 탐색하기

### 개념이나 문서를 시작점으로 찾기

1. 사이드바에서 **온톨로지**를 엽니다.
2. **개념이나 문서 이름 검색**에 검색어를 입력합니다.
3. 필요하면 검색 대상을 **전체 / 개념 / 문서**로 바꾸고 **검색**을 누릅니다.
4. 결과에서 살펴볼 개념을 시작점으로 추가합니다.
5. 같은 지도에서 비교할 개념이 있으면 시작점을 더 추가합니다.

최근 변경 문서에서도 탐색을 시작할 수 있습니다. 같은 이름이 여러 문서에 등장해도 자동으로 하나의 개체로 합쳐지는 것은 아닙니다. 어떤 문서와 문맥에서 나온 개념인지 함께 확인하세요.

### 지도를 넓히고 상세 근거 읽기

- 개념을 선택하면 **개념 정보**를 확인할 수 있습니다.
- **이 개념의 연결 불러오기**, **연결 N개 더 보기**로 연결을 추가합니다.
- 관계를 선택하면 **관계 상세**에서 주체·관계·대상과 조건 등을 읽습니다.
- **근거·검토 이력 보기**로 원문과 사람의 판단을 확인합니다.
- 문서 링크 또는 **문서의 전체 온톨로지 보기**로 해당 자료의 지식 구조를 살펴봅니다.
- 자료가 바뀌었다면 **이 개념의 연결 새로 불러오기** 또는 **다시 불러오기**를 사용합니다.

지도는 필요한 연결을 나누어 불러옵니다. 개념의 연결은 기본 20개씩 조회하므로 처음 보이는 지도가 모든 관계를 포함한다고 생각하지 마세요. 더 보기와 누락 안내를 확인합니다.

### 용어 설명과 문맥 확인하기

개념 상세의 용어 카드에서 **원문에서의 설명**을 읽고 **앞뒤 원문 문맥 보기**를 펼칩니다. 업무 영역, 서술 관점, 식별 범위가 있으면 함께 확인합니다.

이 설명은 현재 원문에 연결된 내용입니다. 같은 단어라도 문서마다 뜻이 다를 수 있으므로 독립된 사전 정의처럼 사용하기 전에 근거 문맥을 살펴보세요.

## 관계 검토하고 전문가 의견 남기기

### 검토함에서 판단하기

1. **검토함**을 엽니다.
2. **전체 / 검토 대기 / 보류 / 다시 검토** 중 필요한 상태를 선택합니다.
3. 문서별로 묶인 항목을 선택합니다.
4. 원문과 판단 영역을 나란히 읽고 관계·속성·조건이 근거와 맞는지 확인합니다.
5. **승인 / 수정 / 보류 / 반려**를 선택합니다.
6. **이유**를 적고 **저장**을 누릅니다.

| 선택 | 사용할 때 |
| --- | --- |
| **승인** | 대상 주장과 그 조건이 원문에 맞는지 확인한 경우 |
| **수정** | 원문에 맞게 관계·속성·조건을 바로잡을 수 있는 경우 |
| **보류** | 정보가 부족하거나 추가 확인이 필요한 경우 |
| **반려** | 현재 추출 내용을 받아들이기 어려운 경우 |

반려는 해당 사실이 논리적으로 거짓이라고 새로 선언하는 동작이 아닙니다. 수정할 때는 원문에 없는 업무 판단을 원문 사실처럼 끼워 넣지 않습니다. 별도의 업무 의견은 전문가 의견으로 기록합니다.

**더 불러오기**가 있으면 아직 확인하지 않은 항목이 남아 있습니다. 조회 누락·한도 안내와도 구별하세요. 빈 목록이 작업 공간 전체에 검토할 내용이 없다는 보장은 아닙니다.

### 지도에서 관계 검토로 이어가기

온톨로지의 **관계 상세**에서도 **검토하기**, **원문 근거 정정**, **근거·검토 이력 보기**로 이어갈 수 있습니다. 실제로 표시되는 행동은 현재 권한과 대상 상태에 따라 달라집니다.

**이전 기준 판단**은 과거 본문이나 추출 결과에 대한 기록입니다. 현재 관계에 자동 적용된 판단으로 보지 않습니다. **추출 기준 변경**, **추출 상태 확인** 안내가 나오면 현재 본문과 추출 상태를 확인하고 필요한 재추출·재검토를 진행합니다.

### 전문가 의견으로 관계 추가하기

1. 온톨로지 지도에서 항목을 선택하고 **관계 추가**를 누릅니다. 문서별 온톨로지에서는 **새 관계**를 누릅니다.
2. 같은 문서에 이미 존재하는 개체를 **주체**와 **대상**으로 선택합니다.
3. **관계**와 **이유**를 입력합니다.
4. 필요하면 **추가 속성 (극성 · 조건 · 적용 범위 · 시점)**을 펼쳐 입력합니다.
5. 내용을 확인하고 저장합니다.

이 경로는 전문가 의견으로 저장하며 원문 인용을 새로 만들어 붙이지 않습니다. 새 개체를 만들거나 서로 다른 문서의 개체를 연결하는 기능은 아닙니다.

### 판단 기록 확인하고 되돌리기

검토 이력에서 변경 전후 값, 작성자, 시각, 이유를 확인합니다. 되돌릴 수 있는 기록이면 **되돌림 이유**를 적고 **선택 판단 되돌림 기록**을 사용합니다.

되돌림은 과거 기록을 삭제하는 방식이 아닙니다. 현재 적용 상태와 기준을 다시 확인한 기록이 남습니다. 본문 또는 추출 결과가 바뀌었다면 이전 승인을 그대로 복원하기보다 현재 근거에서 다시 검토해야 합니다.

## AI 채팅으로 질문하기

### 대화 시작하고 이어가기

1. **AI 채팅**을 엽니다.
2. 기존 대화를 찾으려면 **대화 목록 열기**, 새로 시작하려면 대화 목록의 **새 대화**를 사용합니다.
3. 질문을 입력합니다.
4. Enter 또는 위쪽 화살표의 **질문 보내기**를 누릅니다. 줄바꿈은 Shift+Enter입니다.
5. 답변을 읽고 **근거**를 확인합니다.
6. 같은 주제를 이어서 묻고 싶으면 같은 대화에서 후속 질문을 보냅니다.

질문에는 문서 이름, 알고 싶은 대상, 적용 조건과 원하는 답변 형태를 적으면 좋습니다.

| 목적 | 질문 예시 |
| --- | --- |
| 조건 확인 | “예시 운영 안내에서 보완을 요청하는 조건을 원문 인용과 함께 알려 줘.” |
| 문서 비교 | “문서 A와 문서 B의 점검 조건을 비교하고, 서로 다른 조건은 표로 정리해 줘.” |
| 불확실성 확인 | “이 설명에서 원문으로 확인되는 내용과 추가 확인이 필요한 내용을 나누어 줘.” |
| 수정안 작성 | “이 문단의 조건을 유지하면서 더 명확한 Markdown 수정안을 작성해 줘.” |

후속 질문에는 이전 대화가 문맥으로 사용됩니다. 다만 이전 AI 답변 자체가 새로운 사실의 출처나 사람의 승인으로 바뀌지는 않습니다. 주제가 크게 달라지면 새 대화로 나누는 것이 편리합니다.

응답 생성을 멈추려면 **응답 중단**을 누릅니다. 다른 화면이나 대화로 이동하는 것만으로 실행이 중단되지는 않습니다.

### 답변 양식과 AI 모델 선택하기

입력창의 **＋**를 누르면 **답변 양식**, **자료 붙여넣기**, **파일 첨부**, 제공되는 경우 **모델**을 선택할 수 있습니다.

답변 양식은 다음 중에서 고릅니다.

- **기본 답변**: 일반 질문과 설명
- **비교 분석 보고서**: 차이점·공통점과 비교 근거
- **항목 매핑표**: 항목 사이의 대응을 표로 정리
- **타임라인·프로세스**: 시간 순서나 처리 순서
- **요약 브리핑**: 짧은 핵심 정리

모델 선택지는 현재 AI에서 여러 후보를 제공할 때 표시됩니다. 선택한 모델은 저장되어 다음 AI 실행부터 적용됩니다. 이미 실행 중인 작업의 모델은 바뀌지 않습니다.

### 자료 붙여넣기와 파일 첨부

**＋ → 자료 붙여넣기**로 긴 자료를 추가하거나 **파일 첨부**로 PC의 파일을 선택합니다. 지원 환경에서는 파일을 끌어다 놓을 수도 있습니다. 긴 글을 붙여 넣으면 첨부 칩으로 접히고, 짧은 글은 입력창에 그대로 들어갑니다.

| 항목 | 한도와 처리 |
| --- | --- |
| 파일 형식 | DOCX, XLSX, PDF, MD, TXT, PNG, JPG, JPEG, GIF, BMP, TIF, TIFF, WebP |
| 파일 크기 | 파일당 최대 20 MiB |
| 첨부 개수 | 최대 20개 |
| 첨부 하나에서 읽은 글 | 최대 12,000자 |
| 전체 첨부에서 읽은 글 | 최대 40,000자 |
| 긴 붙여넣기의 칩 전환 | 300자 초과 또는 5줄 초과 |

읽은 글이 한도를 넘으면 앞부분만 포함하고 일부만 담았다는 안내를 표시합니다. 질문의 핵심이 뒷부분에 있으면 해당 범위를 따로 준비하세요. 이미지·스캔 PDF는 OCR이 필요할 수 있으며, XLSX 수식은 새로 계산하지 않습니다. PPTX 첨부는 지원하지 않습니다.

채팅 첨부와 **문서 등록**은 다릅니다. 첨부에서 읽은 텍스트는 질문에 포함되어 AI에 전달되고 대화 기록에도 포함됩니다. 지속적으로 함께 검색할 Wiki 자료로 만들려면 별도로 문서를 등록하세요.

### 공개 웹 자료를 함께 검색하기

1. 입력창의 지구본 **웹 검색**을 누릅니다.
2. **외부 검색어**에 검색에 사용할 공개 검색어를 입력합니다. 최대 200자입니다.
3. **적용**을 누릅니다.
4. 웹 사용 여부와 검색어를 확인하고 질문을 보냅니다.
5. 이후 사용하지 않으려면 같은 설정에서 **사용 안 함**을 선택합니다.

웹 조사에는 별도로 지정한 외부 검색어를 사용합니다. 질문, 첨부, 이전 대화, Wiki 문서 전체를 검색어에 자동으로 합치지 않습니다. 답변을 생성하는 개인 AI에는 질문과 필요한 근거가 전달되므로, 자료의 이용 범위에 맞게 질문과 첨부를 선택합니다.

### 답변의 근거 확인하기

답변의 **근거** 칩을 눌러 어떤 문서와 인용을 사용했는지, 원문의 어느 위치인지 확인합니다. 웹 자료는 출처 제목·링크·확인 시각 등으로 구별합니다.

다음 상황에서는 확인 범위를 넓히거나 질문을 구체화하세요.

- **이 답변에는 저장된 인용이 없어요**가 표시됩니다.
- 검색 결과나 읽은 범위가 일부라는 안내가 있습니다.
- 근거가 이전 본문에 연결되어 있거나 재검토가 필요합니다.
- 첨부 내용이 일부만 포함되었습니다.
- 답변의 조건·수치가 원문과 맞지 않습니다.

질문할 때마다 모든 문서와 전체 이력을 한 번에 보내는 방식은 아닙니다. 현재 답변에서 실제로 읽고 인용한 근거를 기준으로 판단하세요. 인용이 있더라도 그 인용이 답변의 결론을 뒷받침하는지 확인해야 합니다.

## 답변과 개인 초안을 파일로 내보내기

### 답변 바로 내려받기

답변 아래에는 **복사**, **다시 묻기**, **내려받기**가 있습니다. 필요한 답변의 **내려받기**를 눌러 형식과 저장 위치를 선택합니다. 파일로 요청한 답변은 파일 카드의 **내려받기**, **다른 형식으로**를 사용할 수 있습니다.

현재 지원 형식은 다음과 같습니다. 실행 환경에서 제공하는 형식만 선택 목록에 나타납니다.

| 형식 | 용도와 결과 |
| --- | --- |
| Markdown (.md) | 제목·목록·표 등의 Markdown 본문을 보관하고 다시 편집 |
| 텍스트 (.txt) | 글 중심의 단순한 파일 |
| Word (.docx) | 문서 형태로 읽고 편집할 보고서 |
| PDF (.pdf) | 고정된 형태로 읽고 공유할 문서 |
| Excel (.xlsx) | 답변의 Markdown 표 등을 바탕으로 만든 새 스프레드시트 |
| PowerPoint (.pptx) | 답변의 제목과 내용을 바탕으로 만든 새 발표 자료 |

“Word 보고서로 만들어 줘”, “Excel 매핑표로 정리해 줘”, “PowerPoint 브리핑으로 만들어 줘”처럼 결과 형태를 질문에 적을 수 있습니다. 내려받은 파일은 전달 전에 열어 내용과 배치를 확인하세요.

Excel·PowerPoint 내보내기는 답변을 새 파일로 만드는 기능입니다. 첨부한 원본 파일의 서식이나 배치를 그대로 되살리는 기능은 아닙니다. 그림·사진 파일 생성은 제공하지 않습니다.

### 개인 결과물 편집하기

답변을 내려받을 때 결과물 쓰기 권한이 있고 저장에 성공하면 해당 답변을 개인 결과물로 보관합니다. 모든 답변에 별도의 결과물 복사본을 자동으로 만드는 것은 아닙니다. 개인 보관이 실패한 경우에도 파일 내보내기는 가능할 수 있으므로 개인 보관 결과와 파일 저장 결과를 각각 확인하세요.

결과물 화면을 열었다면 **본문 편집**으로 내용을 고치고 **프리뷰 보기**로 확인한 뒤 **개인 초안 저장**을 누릅니다. 파일로 사용할 때는 지원 형식과 **내려받기**를 선택합니다. 미저장 변경, 저장한 개인 초안, 저장된 AI 결과의 상태를 구별해 확인하세요.

화면에 표시되는 **개인 초안 · Wiki에는 반영되지 않음**은 공유 문서와 별도로 관리된다는 뜻입니다. 개인 초안 저장이나 내려받기는 Wiki 본문을 바꾸지 않습니다.

### 검토한 결과를 Wiki에 반영하기

현재 개인 결과물 화면에는 Wiki 직접 반영 버튼이 없습니다. 문서를 수정하려면 다음 순서로 진행합니다.

1. AI 결과에서 반영할 내용과 원문 근거를 검토합니다.
2. 대상 문서를 열고 **본문 편집**을 누릅니다.
3. 검토한 텍스트를 필요한 위치에 옮기고 기존 내용과 맞게 편집합니다.
4. **변경 내용 확인 → 저장**을 진행합니다.
5. 수정한 본문을 다시 읽고 필요한 경우 **관계 재추출**을 진행합니다.

수정안 작성, 개인 초안 저장, 공유 문서 저장, 관계 재추출은 각각 별개의 단계입니다.

## AI 작업과 지난 실행 기록 관리하기

### 실행 중 작업과 최근 결과 확인하기

1. 사이드바 또는 하단 상태바에서 **AI 세션**을 엽니다.
2. **돌고 있는 작업**에서 대상과 현재 상태를 확인합니다.
3. **열기**로 해당 작업이나 대화로 이동합니다. 이 행동으로 AI를 새로 실행하지는 않습니다.
4. 특정 작업을 멈추려면 해당 행의 **중단**을 누릅니다.
5. **최근 끝난 작업**에서 **열기**로 결과를 확인합니다.

최근 결과의 X 버튼인 **확인하고 목록에서 지우기**는 최근 목록의 확인 상태를 정리합니다. 저장된 결과와 실행 원장을 삭제하지 않습니다. 확인 상태는 이 기기의 사용자·작업 공간 단위로 관리되므로 다른 PC의 목록과 다를 수 있습니다.

여러 질문·분석·관련 지식 찾기를 독립적으로 실행할 수 있습니다. 화면을 옮겨도 진행 중인 작업은 유지됩니다. 아직 실행하지 않은 준비 단계 작업은 기본 실행 목록에 표시되지 않을 수 있습니다.

### 지난 기록 찾기

**AI 세션 → 지난 기록**을 열고 **종류 필터**에서 **전체 / 문서 분석 / AI 질문 / 관련 지식 찾기**를 고릅니다. **더 불러오기**가 있으면 추가 기록을 불러옵니다. 목록의 필터와 건수는 불러온 범위이므로 오래된 작업을 찾을 때는 조회 범위를 확인하세요.

### 분석 작업 상세에서 할 수 있는 일

| 행동 | 사용하는 때 |
| --- | --- |
| **새로고침** | 현재 진행 상태와 저장 결과를 다시 확인 |
| **실행 가능 여부 확인** | 시작·재개 조건을 확인 |
| **이 작업 실행 / 이 작업 이어서 실행** | 확인된 실행 방식으로 명시적으로 시작 |
| **이 기기의 실행 중단** | 현재 PC에서 실행 중인 처리를 중단 |
| **작업 취소 검토 → 이 작업 취소** | 분석 작업을 취소. 이미 저장한 문서와 결과는 유지 |
| **분석 당시 원본 버전 열기** | 최신 원본 대신 해당 분석이 실제로 사용한 원본을 확인 |
| **저장 결과** | 저장됨·저장되지 않음·저장 여부 미확인을 구별 |
| **작업 기준과 진행 이력** | 해당 작업의 입력 기준과 진행 기록 확인 |

“실행이 끝났다”와 “결과가 저장되었다”는 다를 수 있습니다. 저장 여부 미확인이라면 먼저 새로고침과 기존 요청 조회로 결과를 확인하세요.

### 창 닫기와 앱 종료

창의 닫기 버튼은 창을 숨깁니다. 연결과 진행 중인 AI 작업은 유지됩니다. macOS에서 앱을 다시 활성화하면 숨겨진 창이 나타납니다.

앱 메뉴에서 명시적으로 종료할 때 진행 중인 작업이 있으면 **진행 중인 AI 작업** 확인창이 표시됩니다.

- **계속 실행**: 앱을 종료하지 않고 작업을 유지합니다.
- **작업을 중단하고 종료**: 실행을 멈추고 앱을 종료합니다.

종료해도 이미 저장된 결과와 복구 기록은 보존합니다. 다시 실행했다고 중단된 AI 처리가 임의의 지점부터 자동으로 이어지는 것은 아닙니다. AI 세션이나 분석 작업 상세에서 상태와 이어서 실행 가능 여부를 확인하세요. 저장하지 않은 문서 편집 초안은 종료 전에 저장해야 합니다.

## 계정과 앱 설정 관리하기

### 서버 연결과 로그아웃

**설정 → 서버·계정**에서 현재 계정 이름, 서버 주소, 작업 공간을 확인합니다. **연결 확인**으로 연결 상태를 확인하고 다른 서버나 계정으로 바꾸려면 **로그아웃**한 뒤 다시 로그인합니다.

로그아웃은 앱의 연결과 자동 복원을 해제합니다. 서버의 원본·문서 삭제나 서버 인증 토큰 회수와는 다릅니다. 서버가 오프라인인 경우에도 현재 앱의 연결 해제를 할 수 있습니다.

### 계정 사용량 확인하기

하단의 AI 상태·한도를 누르거나 **설정 → AI 실행 → 계정 사용량 (참고)**를 열고 **사용량 새로고침**을 누릅니다. 설정에 항목이 보이지 않으면 하단의 AI 상태·한도 링크를 사용하세요.

**AI 계정 사용량**은 여러 세션이 공유하는 개인 계정의 한도입니다. 확인 가능한 경우 잔여·사용 비율, 한도 기간, 초기화 시각, 마지막 확인 시각을 보여 줍니다. 개별 작업의 실행 횟수나 토큰 수와는 다릅니다.

Claude는 현재 계정 한도 수치를 제공하지 않는다고 표시합니다. 미제공, 조회 실패, 이전 조회값은 실제 잔여량 0%와 다릅니다. 최신 확인 시각과 실제 AI 오류를 함께 살펴보세요.

### 화면 테마 바꾸기

**설정 → 화면 → 화면 테마**에서 **라이트 / 다크 / 시스템 설정 따르기**를 선택합니다. 선택은 이 기기에 저장됩니다.

### 업데이트하기

설치 앱에서 **업데이트 준비 완료**가 표시되면 **지금 재시작** 또는 **나중에**를 선택할 수 있습니다. 나중에 선택한 경우 사이드바의 **업데이트** 항목을 사용합니다. 준비된 업데이트는 앱 종료 시 설치할 수 있습니다.

재시작 전에는 편집 중인 내용을 저장하고 진행 중인 AI 작업을 확인하세요. 업데이트 알림과 항목은 배포 채널에 실제 업데이트가 있을 때 나타납니다. 설치 파일을 따로 전달받은 경우에는 배포 담당자의 교체 안내를 따릅니다.

## 자주 겪는 문제 해결하기

| 문제 | 먼저 확인할 것 | 이어서 할 일 |
| --- | --- | --- |
| 로그인되지 않음 | 계정 이름, 서버 주소, 서버 실행 상태 | 이름·주소를 수정하고 다시 로그인합니다. 원격 접속은 HTTPS 주소를 확인합니다. |
| 이전에 보던 문서가 없음 | 서버·계정·작업 공간, 검색어·상태 필터 | 올바른 공간에서 검색 조건을 풀고 다시 조회합니다. |
| 저장·검토 버튼이 없음 | 현재 계정의 쓰기·검토 권한, 대상 상태 | 설정과 안내를 확인하고 필요한 권한은 운영 담당자에게 문의합니다. |
| AI 프로그램을 찾지 못함 | 선택한 AI의 설치 여부와 실행 위치 | **AI 프로그램 자동으로 찾기** 또는 **프로그램 위치 변경**을 사용합니다. |
| 로그인했는데 AI가 실행되지 않음 | 같은 PC·OS 사용자로 로그인했는지, 선택한 AI, 계정 한도 | 로그인 재확인과 오류 안내를 확인합니다. 필요하면 실제 호출 시험을 합니다. |
| 파일은 보관됐지만 문서가 없음 | 문자 변환·문서 저장 단계의 오류 | 등록 결과와 처리 기록을 읽고 **본문 변환 다시 시도** 등 해당 단계만 복구합니다. |
| 문서는 있으나 관계가 없음 | AI 실행 상태, 추출 실패, 문서 상태 | AI 세션과 분석 작업 상세를 확인하고 필요한 관계 추출만 실행합니다. |
| OCR 내용이 이상함 | 원본 화질, OCR 언어, 미독·부분 처리 안내 | 원본과 대조하고 필요한 본문을 정정한 뒤 관계를 재추출합니다. |
| Excel 계산값이 빠짐 | 원본에 저장된 계산값이 있는지 | 사용하던 스프레드시트 프로그램에서 계산·저장한 별도 원본을 준비해 등록 여부를 검토합니다. 기존 원본은 보존됩니다. |
| 본문 수정 후 관계가 오래됨 | 현재 본문과 추출 기준의 차이 | **관계 재추출 → 결과 비교·반영**을 진행합니다. |
| 저장 충돌 | 다른 사용자 또는 AI의 최근 변경 | 최신 본문을 읽고 내 변경을 재반영한 뒤 비교·저장합니다. |
| 저장 결과를 받지 못함 | 서버 연결과 기존 요청 상태 | 새 요청을 반복하기 전에 저장 결과·동일 요청 기록을 조회합니다. |
| 답변이 근거 없이 단정함 | 저장된 인용, 읽은 범위, 첨부 누락 | 근거를 열어 확인하고 원문 범위와 조건을 지정해 다시 질문합니다. |
| 내보내기에 원하는 형식이 없음 | 해당 화면과 실행 환경의 형식 목록 | 제공하는 형식으로 저장하거나 문서 처리 진단을 확인합니다. |
| 실행 기록 일부만 보임 | 현재 공간, 종류 필터, 더 불러오기 | 과거 기록을 추가 조회합니다. |
| 창을 닫았는데 AI가 계속 실행됨 | 창 숨김 상태 | **AI 세션**에서 해당 작업을 중단하거나 앱 메뉴로 명시 종료합니다. |

문의를 보낼 때는 작업한 시각, 화면 이름, 오류 문구, 문서·작업 식별 정보, 어느 단계까지 저장됐는지를 함께 전달하면 원인을 찾기 쉽습니다. 인증 토큰이나 개인 로그인 정보는 보내지 않습니다.

## 업무별로 따라 하기

### 새 자료를 팀 지식으로 활용하기

1. 문서 등록에서 자료를 올립니다.
2. 변환 보고와 저장된 본문을 원본과 대조합니다.
3. 관계를 열어 핵심 조건과 근거를 확인합니다.
4. 필요한 관계만 검토함에서 판단합니다.
5. AI 채팅에서 문서 이름과 질문 범위를 지정합니다.
6. 답변의 근거를 확인하고 필요한 파일 형식으로 내려받습니다.

### 잘못된 내용을 바로잡기

먼저 무엇이 잘못됐는지 구별합니다.

| 잘못된 대상 | 수정할 곳 |
| --- | --- |
| Wiki 본문 자체 | **본문 편집 → 변경 내용 확인 → 저장** |
| 본문은 맞지만 추출한 관계가 잘못됨 | 관계의 **원문 근거 정정** 또는 검토함의 **수정** |
| 원문 밖의 별도 업무 의견이 필요함 | **전문가 의견으로 추가** |
| AI 답변의 해석이나 표현 | 근거를 확인하고 같은 대화에서 정정 질문. 공유 문서 수정이 필요하면 별도로 본문 저장 |

본문을 바꿨다면 관계 재추출을 검토합니다. 중요한 판단은 이유를 남겨 다음 사용자가 원문과 업무 의견을 구별할 수 있도록 합니다.

### 자료를 수정한 뒤 결과를 다시 확인하기

1. 현재 본문과 이력을 비교해 바뀐 내용을 확인합니다.
2. 저장된 본문으로 관계를 재추출합니다.
3. 추가·사라진 관계와 현재 원문 근거를 비교합니다.
4. 검사 후 반영하고 필요한 새 관계를 검토합니다.
5. 이전 기준의 판단과 현재 판단을 구별합니다.
6. 기존 질문을 다시 할 때는 변경된 조건과 현재 근거를 확인하도록 요청합니다.

## 현재 앱의 제공 범위 알아두기

- **문서 간 대응·변경 영향 조회**는 서버 API와 MCP에 있는 기능이며 별도 앱 메뉴로 제공하지 않습니다. 검토함에 관련 건수가 포함되어도 직접 처리할 버튼이 없을 수 있습니다.
- **Clean Up과 문서별 별도 관계 검토 화면**은 현재 일반 메뉴에서 진입하는 기능이 아닙니다. Clean Up은 원문이나 판단 이력 삭제, 미검토 관계 자동 제거, 같은 이름의 개체 자동 병합을 뜻하지 않습니다.
- 개인 결과물의 **Wiki 자동 반영**, 원본 파일 자체의 편집·재작성, PPTX 등록·채팅 첨부, 그림·사진 파일 생성은 현재 안내한 앱 기능에 포함되지 않습니다.
- 목록·지도·근거 조회에서 더 보기, 일부 조회, 미독, 건너뜀 등의 안내가 있으면 결과의 범위를 함께 해석합니다.
