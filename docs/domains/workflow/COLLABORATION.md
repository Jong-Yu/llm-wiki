# 역할별 서브에이전트와 협업

기본은 주 에이전트가 직접 처리합니다. 실제 분리 이득이 있는 전문 작업이나 원문 분리 평가에만 아래 규칙을 적용합니다.


역할 원본은 요청한 `.agent/`에 두며 `.codex/agents`가 이 폴더를 가리킵니다. 기존 `.agents/skills/`는 작업 절차의 위치입니다. 같은 지침을 두 곳에 복사하지 않습니다. 주 에이전트는 현재 단계·파일 담당·최종 통합을 맡고 아래 전문 역할 중 필요한 것만 호출합니다.

| 역할 | 집중 범위 |
| --- | --- |
| [wiki_researcher](../../../.agent/wiki_researcher.toml) | 다양한 분야의 1차 출처 검색·본문 확인·출처가 있는 재서술 |
| [wiki_ontology](../../../.agent/wiki_ontology.toml) | 개체·관계 의미 판단·원문 근거·revision·연결 후보 |
| [wiki_reviewer](../../../.agent/wiki_reviewer.toml) | 독립 의미 평가·누락·잘못된 확정·보존 검증 |
| [wiki_prompt_editor](../../../.agent/wiki_prompt_editor.toml) | 개발 사례의 실제 오류에 따른 추출 지침 개선 |
| [wiki_storage](../../../.agent/wiki_storage.toml) | 파일 저장·전체 버저닝·충돌·실패 시 보존 |
| [wiki_mcp](../../../.agent/wiki_mcp.toml) | MCP 계약·stdio/HTTP·인증·Codex 연결 |

- 에이전트끼리 필요한 질문을 주고받을 수 있습니다. 기존 담당자에는 메시지 도구를, 새 전문 작업에는 하위 에이전트 도구를 사용합니다. 역할 선택이 없는 환경은 해당 TOML의 `developer_instructions`를 읽어 범위와 함께 전달합니다. 일반 채팅 생성·다른 사용자 채팅 메시지 도구로 대체하지 않습니다.
- 위임에는 질문, 입력 문서와 revision, 기대 결과, 편집 가능한 파일, 이미 참여한 역할을 전달합니다. 같은 파일의 편집자는 한 명으로 정하고 읽기 전용 검토는 병행할 수 있습니다. 슬롯이 부족하면 부모에게 배정을 요청합니다. 조상·같은 작업의 재호출, 서로 기다리는 호출 고리, 범위 없는 재위임은 하지 않습니다.
- 모델·실행 권한·MCP 연결은 부모 설정을 따릅니다. 역할 지침은 권한 격리가 아닙니다. 현 프로젝트는 동시에 열린 하위 작업을 최대 3개로 설정하며, 환경에 더 작은 제한이 있으면 그 제한을 따릅니다.
- 의미 검증은 JSON·인용 검사와 구분합니다. 현재 스키마로 표현할 수 있는 분류·과정·조건·부정·가능성은 보존하고, 남은 복합 논리·정량 의미를 다른 관계로 강제 변환하지 않습니다. 생략 사유는 검토 결과에 남기며 MCP 인자에 임의 필드를 추가하지 않습니다.
- 추출 담당에게 평가 정답을 주지 않습니다. 프롬프트 개선에는 개발 사례만 사용하고, 별도 검증 사례는 최종 평가에 남깁니다. 최대 두 번의 개선 뒤에도 해결하지 못한 부분은 보고합니다. 점수를 높이려고 정답을 결과에 맞추거나 모든 관계를 생략하지 않습니다. 실행 방법은 [README](../../../README.md#역할별-에이전트와-의미-검증), 실제 결과는 [PLAN](../../PLAN.md)에 기록합니다.
