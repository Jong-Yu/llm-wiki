문제 없이 검증된 단계는 재확인 없이 이어가라는 사용자 요청에 따라 진단 검토 연결, 기존 업무 MCP13개, 작업 공간 검토함·기존 작업 관리 연결, 스킬 분리·추가를 완료했습니다. 검증은 진단 Electron12묶음, MCP79개, 검토함 Electron6묶음·격리HTTP1묶음·전체 제품 빌드, 스킬6개 형식/링크 및 독립 가상요청9건입니다. 실제 근거·수정한 오류·미실행은 [HISTORY](HISTORY.md)와 각 도메인 기록을 따릅니다.

### 2026-10-29 — 정의 종료 후 구현·검증

사용자가 정리한 순서의 구현·검증과 파일 충돌 없는 병렬 진행을 승인했습니다. 반환 수·정렬 등 개발 기본값을 별도 정책 질문으로 다시 나누지 않습니다.

- 기존 `MCP 추출 프롬프트 개선 방향 찾기` 채팅이 공통 MUST·허용 이력 생략과 실제 미독 구별·통합 검증을 담당했고 완료했습니다. 해당 평가를 중복 실행하지 않았습니다.
- 현재 구현 채팅은 같은 AI 세션의 저장 후 검색·대조, 후보/제외/이전 실행 보관·검토 화면, 다중 실행·창 숨김/명시 종료·대화 문맥·실제 계정 사용량을 담당합니다. 기존 완료된 관계 편집·IA·변환기 구현을 다시 만들지 않습니다.
- 파일 담당은 Python 비교 저장/조회·클라이언트, 앱 실행 서비스/공통 연결, renderer 및 신규 비교 앱 서비스로 나눴습니다. 주 에이전트는 CLI의 명시 세션 재개·추출 후 비교 연결과 질문의 고정 대화 문맥, 최종 통합 검증을 맡습니다. 공통 프롬프트/초안 검사 규칙은 기존 후속 작업의 담당을 유지합니다.
- 운영 규약 발행·기본 정책 전환·서버 배포는 위 후속 운영 범위에서 완료했습니다. 기존 자료 일괄 재분석은 수행하지 않았습니다. 실제 검증과 남은 항목은 각 도메인 HISTORY에 기록합니다.
- 이번 담당 구현·검증 완료: 저장 후 동일 세션 대조와 보호된 수동 재대조·결과 화면, 다중 실행/개별 중단/창 수명, 고정 대화 문맥과 실제 Codex 계정 한도를 연결했습니다. 전체 제품 빌드, 격리 저장/API/프로세스/Electron 검증과 실제 Codex 추출→대조를 통과했습니다. [통합 기록](HISTORY.md#2026-10-29--정의-종료-후-병렬-구현과-통합-검증)을 따릅니다. 공통 MUST·미독 구별의 기존 담당 결과를 운영에 반영했고 Claude의 실제 성공 검증은 사용 한도 해제 뒤에 남습니다.

### 2026-10-29 — 역할별 조회 관점을 PoC에서 제외

- **인증**: D-071의 경로와 flat data 응답을 사용합니다. access-context의 새 display_name/default_tenant/access_revision은 기존 클라이언트·정책 호환을 고려합니다. 공통 Access DTO의 access_revision 추가는 MCP 담당, 이를 생성하는 AccessScope/정책은 인증 담당, 각 업무의 현재성 비교·actor 호환은 해당 업무 담당입니다. 과거 불변 actor에 새 필드를 억지로 주입하지 않습니다.
- **공통 경로**: 저장 담당은 `core/common/storage_layout.py`에서 `personal_root(root, user_id)`, `source_root(root, source_id)`, `source_version_root(root, source_id, version_id)`, `analysis_job_root(root, user_id, job_id)`, `analysis_request_root(root, user_id)`, `knowledge_root(root, kind)`를 제공합니다. 반환은 Path이며 경로 계산만으로 폴더를 생성하지 않습니다. user/source/job ID와 kind를 검증합니다. knowledge kind는 graphs/reviews/correspondences입니다. analysis_request_root는 `_personal/<userId>/_requests/analysis`이며 source/job 공통 요청 충돌 검사는 같은 계약을 사용합니다. 과거 경로 읽기·충돌 처리는 각 저장 모듈 소유자가 맡습니다.
- **문서 파서**: 저장 담당이 `core/modules/documents/metadata.py`의 `parse_document(content)`를 제공하며 결과는 metadata, body, body_start_line, body_revision, document_id를 읽을 수 있게 합니다. content/revision은 전체 파일 그대로 유지합니다. HTTP 문서 읽기에는 별도 필드로 추가하고 기존 필드 의미를 바꾸지 않습니다. 목록은 지식 catalogue와 문서 API가 동일 metadata/작성 정보 구조를 사용합니다.
- **작성 기록**: `WikiStore.save`는 기존 호출을 유지하며 actor/origin/reason을 선택 인자로 받는 확장 지점을 저장 담당이 제공합니다. actor는 서버가 검증한 실제 사용자, origin은 human/ai를 구별하는 생성 경로 정보입니다. 기존 출처 미기록은 unknown으로 보존하며 신규 UI·MCP·분석 경로가 적절한 값을 전달합니다. 임의 클라이언트 사용자 ID를 신뢰하지 않습니다.
- **기본 등록**: 분석 담당이 신규 흐름의 요청·응답을 자신의 PLAN에 먼저 공개하고 UI/MCP가 이를 소비합니다. 기본 경로는 원본을 재등록하지 않고 하나의 현재 MD와 정확한 분석 판본을 연결합니다. 기존 고급 계획을 지우는 방식으로 구현하지 않습니다.
- **의존성**: 암호화·YAML 파싱 등 필요한 라이브러리는 검증된 것을 재사용합니다. requirements/lock 편집은 MCP 담당만 하며 다른 담당은 자신의 PLAN에 필요한 패키지/호환 조건을 적습니다. 인증 담당은 필요한 암호화 키 설정·초기화 함수도 먼저 공개하여 MCP 담당의 서버 조립과 연결합니다.

### 실행 순서와 완료 판정

6개 세션이 병렬로 조사·구현·담당 검증을 진행합니다. 저장/인증 담당은 공통 함수·DTO를 먼저 공개하고, 나머지는 소유 파일 안에서 독립 부분을 진행합니다. 타 세션 파일을 대신 수정하거나 서로의 완료를 기다리며 순환 대기하지 않습니다. 연결 구현은 실제 계약과 맞춘 뒤 완료로 판정합니다.

격리 데이터에서 가입→동일 토큰 재로그인→API/MCP 동일 사용자·권한→원본 등록→MD/Front Matter→본문 판본 기반 추출→수정 이력·stale→로그아웃·앱 재시작을 검증합니다. 다른 사용자 가입 후 기존 사용자 유지, 실제 권한 회수, 동시/부분 실패, 기존 원본·전체 히스토리·검토 원장 보존을 포함합니다. 실제 data/.local이나 사용자 CLI 설정을 시험용으로 변경하지 않습니다. 현재 로컬 MCP의 자료 루트 불일치 등 기존 운영 문제를 인증 우회나 빈 자료 자동 생성으로 숨기지 않습니다. 전체 구현 완료는 각 담당 결과와 통합 검증 뒤에 판단합니다.

2026-10-28 실행 파일 정리를 완료했습니다. 과거 시험·평가·설계 산출물과 비서비스 백업·기록은 삭제하고 현재 데이터·인증·실행 환경·연결된 AI 규칙은 유지합니다. 검증 범위는 [이번 정리 기록](HISTORY.md)을 따릅니다.

현재 목표는 **LLM Wiki의 다섯 큰 기능을 연결한 최소 PoC**입니다. 2026-10-26 사용자의 기능 재정의와 후속 선택에 따라 **원본 보관 + Markdown 편집**을 기준으로 삼습니다. [D-066](DECISIONS.md#d-066--다섯-기능-중심의-poc와-원본-보관markdown-편집-2026-10-26)에 범위와 이유를 기록합니다.

이번 작업은 기능 범위와 우선순위의 재정의입니다. 기존 등록·분석·그래프·검토·질문·결과 초안·설정 구현을 재사용하되, 새 PoC의 완료 여부는 아래 사용자 흐름으로 확인합니다. 다섯 큰 기능을 먼저 연결하고 세부 기능과 고도화는 그 이후에 진행합니다.

기존 macOS·Windows 앱과 Windows/WSL2 서버의 지원 방향은 유지합니다. 설치·배포 확대보다 이번 PoC의 기능 연결을 우선하며, 이전 출시 목표와 미완료 검증은 배포 계획 기록 (정리로 삭제된 참고 자료)에 남깁니다.

## 실행 경계

- **AI 실행은 모두 개인 CLI**가 맡습니다. Codex 또는 Claude Code를 선택해 본문 준비·관계 추출/재추출·대화·산출물 생성·본문 수정안을 실행합니다.
- **MCP는 AI 작업의 규칙과 데이터 통로**입니다. CLI가 MCP 서버의 온톨로지 추출 Rule과 해당 작업의 입력을 받아 처리하고 기존 검증·저장 계약으로 결과를 제출합니다.
- **Electron의 데이터 조회·변경은 FastAPI**를 사용합니다. 목록·본문·그래프·전문가 수정·결과 조회는 기존 업무 API에 연결합니다. AI 실행과 서버 저장의 완료 상태를 구분합니다.
- MCP 토큰은 기존 OS 보호 저장을 사용합니다. Wiki 서버 연결 토큰과 각 AI CLI의 로그인은 별도로 관리합니다. 기존 권한·버전 충돌·전체 이력 보존 계약을 유지합니다.

## 문서 편집 기준

사용자가 선택한 흐름은 **업로드 원본 보관 → 편집 가능한 Markdown 본문 → 해당 본문을 근거로 관계 추출**입니다.

- PDF·DOCX 등 업로드 원본과 원본에서 읽어 낸 변환 보고는 보존합니다. 앱과 AI가 편집하는 대상은 Wiki Markdown 본문입니다. Markdown 수정이 업로드 원본까지 수정한 것으로 표시되지 않아야 합니다.
- 직접 붙여넣은 텍스트도 최초 입력과 이후 편집 본문을 구분합니다. AI 수정안은 CLI와 MCP로 만들며, 직접 편집과 AI 수정안의 앱 반영은 기존 FastAPI 저장 경로를 사용합니다.
- 본문 저장은 수정 전 전체 파일과 기준 버전 검사를 유지합니다. 본문이 바뀌면 기존 관계가 이전 본문에 근거한다는 상태를 표시하고 현재 본문으로 재추출할 수 있게 합니다. 과거 전문가 판단은 보존하며 새 추출에 자동으로 승계하지 않습니다.
- 원본 파일 자체를 앱에서 편집하거나 AI로 다시 작성하는 기능은 이번 PoC 범위에서 제외합니다. 원본 교체의 기존 판본 보관 기능은 유지합니다.

상세 저장·계보 계약은 [documents 결정](../documents/DECISIONS.md), [sources 결정](../sources/DECISIONS.md), [검토 규칙](../reviews/RULES.md)을 따릅니다.

## 다음 범위와 미결정 사항

기존 화면 재구성에서 사용하던 API/MCP를 재사용하면서, 이번에 승인된 D-071~D-074의 가입·로그인·저장·기본 분석 계약을 위 6개 세션에서 병렬 구현합니다. 온톨로지 그래프의 기존 의미와 사용자 검토 계약은 유지합니다. 새 기능과 기존 자료 호환을 연결한 뒤 완료 조건을 확인하며, 관련 없는 고급 편집·배포 확대를 선행 단계로 늘리지 않습니다.

- **재사용 기반**: 제목 지정 등록, 불변 원본, Markdown 저장, MCP 규약 기반 분석·재추출, 그래프/전문가 검토, 근거 기반 질문·결과 초안, Codex/Claude 선택과 보호 연결 저장이 있습니다. 구현과 검증의 정확한 범위는 각 담당 PLAN을 따릅니다.
- **명확한 후속 범위**: 채팅에서 생성하는 산출물의 프리뷰·다운로드를 한 흐름으로 연결해야 합니다. 기존 텍스트 답변·초안 및 원본/변환 첨부 다운로드만으로 이 기능이 완료됐다고 판단하지 않습니다.
- **아직 정하지 않은 사항**: PoC 산출물의 파일 형식, 첫 시연에서 검증할 입력 형식·문서 집합과 실행 환경입니다. 모든 파일 형식의 생성·편집을 약속하지 않으며 큰 기능을 구체화할 때 필요한 최소 범위를 정합니다.
