# 제품·작업 절차 계획

## 현재 상태

제품은 **문서 등록·추출 / 관계 그래프·전문가 수정 / 문서 목록·관계·편집 / AI 채팅·산출물 / 연결 설정**의 다섯 기능을 중심으로 개발합니다. 원본을 보관하고 Markdown 본문을 편집하며, 해당 본문에 근거한 관계와 사람의 판단을 구분합니다. 범위 결정은 [D-066](DECISIONS.md#d-066--다섯-기능-중심의-poc와-원본-보관markdown-편집-2026-10-26)을 따릅니다.

- 기능별 구현·배포·미검증 상태는 [담당 도메인 PLAN](../../PLAN.md#도메인별-시작점)에서 관리합니다. 과거 세션의 담당표·실행 순서는 현재 작업 지시로 사용하지 않습니다.
- [제품 소개](../../INTRODUCTION.md)·[사용자 가이드](../../USER_GUIDE.md)·[화면 가이드](../../guide/index.html)의 설명 기준은 2026-11-23, 기존 화면 캡처 기준은 11-07입니다. 현재 화면 재촬영과 설치판 안내 확인은 남아 있습니다.
- [제품·개발 명세](../../reference/README.md)는 기준일의 구조와 기능을 설명합니다. 현행 동작은 담당 PLAN/RULES, 결정 이유는 DECISIONS, 실제 검증은 HISTORY를 확인합니다.
- 작업 도구는 조회 `wiki-query`, 편집 `wiki-edit`, 판단·관계 검토 `wiki-review`, 분석 운영 `wiki-analyze`, 진단 `wiki-diagnose`로 나뉩니다. 복합 요청은 `wiki-route`, 기존 복합 편집 호출은 `wiki-maintain`을 사용합니다.

## 실행 경계

- AI 실행은 개인 Codex 또는 Claude CLI가 맡습니다. MCP는 규칙·데이터·작업 제출 통로이고 Electron의 업무 조회·변경은 FastAPI를 사용합니다. AI 실행 완료와 서버 저장 완료를 구분합니다.
- 서버 토큰은 OS 보호 저장을 사용하며 AI CLI 로그인과 별도로 관리합니다. 권한·판본 충돌·전체 이력 보존은 [AGENTS](../../../AGENTS.md#공통-데이터-보존)와 담당 도메인 계약을 따릅니다.
- 원본 파일과 변환 보고는 보존하고 앱/AI의 편집 대상은 Markdown 본문입니다. 본문 변경 시 기존 관계의 오래됨을 표시하며 이전 전문가 판단을 새 추출에 자동 승계하지 않습니다. 원본 자체의 편집·AI 재작성은 PoC 범위에서 제외하고 기존 원본 교체의 판본 보관은 유지합니다.
- macOS·Windows 앱과 Windows/WSL2 서버의 지원 방향은 유지합니다. 빌드 성공, 실제 기기 동작, 운영 배포, 모델 의미 평가의 완료를 각각 판정합니다.

## 다음 범위와 미결정 사항

- 문서 등록의 확정 목표와 현재 시안/제품 차이는 [UI PLAN](../ui/PLAN.md), 변환·보정의 미완료 기능과 실자료 검증은 [sources PLAN](../sources/PLAN.md)을 따릅니다.
- 배포본·개발본 차이, Windows 실기기·두 PC 연결, 제공자별 실제 검증은 [platform PLAN](../platform/PLAN.md)과 [analysis PLAN](../analysis/PLAN.md)을 따릅니다.
- 관리자 기능·공간 배정의 구현 범위는 [access PLAN](../access/PLAN.md)을 따릅니다. 역할별 조회 관점은 PoC에서 제외한 상태이며 재도입 일정은 정하지 않았습니다([D-083](../access/DECISIONS.md#d-083--poc에서-역할별-조회-관점-제외-2026-10-29)).
- 현재 화면 캡처를 갱신하고 안내 문서의 설치판 반영을 확인해야 합니다. 새 입력 형식이나 배포 환경을 추가할 때는 해당 범위의 완료 조건을 정합니다.

## PoC 완료 조건

- 실제 앱에서 연결 설정 → 등록·본문/관계 저장 → 그래프·전문가 수정 → 문서/관계 조회 → 본문 수정·재추출 → 근거 기반 채팅·산출물 프리뷰/다운로드를 확인합니다.
- 직접 편집과 AI 수정 후 원본·이전 본문·판단 이력을 보존합니다. 오래된 관계·미완료 추출을 최신 완료 결과로 표시하지 않습니다.
- 선택한 실제 CLI와 대상 기기에서 확인한 범위를 기록합니다. 합성 실행기 시험을 실제 모델·기기 검증으로 대신하지 않습니다.
- 저장 실패·충돌·연결 실패·응답 유실에도 자료를 보존하고 저장 완료와 재시도할 작업을 구분합니다. 실제 검증과 남은 한계는 담당 HISTORY에 기록합니다.
