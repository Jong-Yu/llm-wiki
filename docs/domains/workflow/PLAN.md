# 제품·작업 절차 계획

## 현재 상태

도메인별 문서 분리·작업 규모별 절차 간소화와 보존/구조 검증 완료. 제품은 자료 축적 → 질문/결과물 활용 → 사람의 수정 재사용을 지향합니다.

제품의 다음 완료 목표는 **설치 후 계속 사용하는 내부 배포판 v0.1.0**입니다. 사용자가 지원 범위를 **macOS·Windows 앱 + Windows/WSL2 서버**로 확정했습니다. 현재는 macOS 로컬 통합과 미서명 패키지 검증을 마쳤으며, 아래 출시 완료 조건은 미충족입니다. 버전 문자열이나 합성 모델 시험 통과를 배포 완료로 취급하지 않습니다. 범위와 이유는 [D-063](DECISIONS.md#d-063--반복-사용하는-v010-내부-배포판의-지원-범위-2026-10-26)을 따릅니다.

사용자는 Windows/WSL2 환경을 설치 중이며, **백업·복원은 이번 v0.1.0 범위에서 제외**했습니다. 서버 설치를 기다리는 동안 Windows 실행 경계·설치 패키지·실제 AI 검증을 병행합니다. 사용자가 준비된 최초3회와 후속 판정1회 모델 전송을 명시 승인했으며, 기존 ChatGPT 로그인만 사용하고 API 키 전환·추가 크레딧 구매는 하지 않습니다.

Wiki MCP 사용 스킬 `wiki-query`·`wiki-analyze`·`wiki-maintain`을 프로젝트에 추가했습니다. 기존 `poc-step`은 개발 절차를 유지합니다. 스킬 메타데이터·링크/도구명 검사, 독립 모의 판단 8건과 실제 읽기 MCP 5호출을 확인했습니다. 현재 읽기 전용 권한에서 분석/수정의 실제 저장은 미실행이며 [검증과 한계](HISTORY.md#wiki-mcp-사용-스킬-추가-2026-10-25)를 따릅니다.

[내부 팀 공유용 아키텍처 PPTX](../../../output/presentations/Wiki_with_AI_Architecture.pptx)와 [변환 PDF](../../../output/pdf/Wiki_with_AI_Architecture.pdf)는 16:9 13장입니다. Wiki 작성·관계 추출의 실제 기준과 수정·사용 방법을 중심으로 구성했습니다. 공통 규약의 원문 의미·조건·예외·출처 보존, 관계의 방향·부정·계획·동일성 판단을 가상 원문과 결과 예로 설명합니다. 본문 수정·원문 근거 정정·전문가 업무 판단·전체 재추출을 구분하고, 실제 앱의 분석 계획·지식 탐색·검토함·대화 기록 캡처를 필요한 부분만 확대해 사용합니다. 질문 실행부터 답변 편집·Wiki 반영, 개인 CLI 준비와 보관 구조까지 담았습니다. 화면은 격리 시험 데이터이며 예시는 실제 모델 출력과 구분합니다. [현재 산출물 검증](HISTORY.md#2026-10-26--wiki-추출-기준과-ui-사용-가이드로-재구성)을 따르며 이전 제품 소개 PDF와 제작 이력은 보존합니다.

파일 정리와 첫 커밋 준비 요청에 따라 Python 캐시를 정리하고, 앱 배포 산출물·개인 MCP 설정·환경변수·키·개발 캐시의 Git 제외 규칙을 보완했습니다. 운영 자료·기존 기록·문서가 참조하는 검증 산출물은 로컬에 보존하며 소스·평가·최종 문서·lockfile은 커밋 대상에 유지합니다. 제외/포함 규칙과 격리 스테이징·자료 보존 검증을 완료했으며 실제 커밋·푸시는 실행하지 않았습니다. [현재 정리·Git 준비 검증](HISTORY.md#2026-10-26--파일-정리와-첫-커밋푸시-준비)을 따릅니다.

## v0.1.0의 남은 범위

격리 시연에서 발견한 변환 첫 클릭·질문 인용/heartbeat·의미 보고·규범 보존·OCR 결함은 보완했고, Python 전체999검사와 Electron 전체27검사가 통과했습니다. 기존 실제 모델 실패는 [고정 보고서](../../../evals/rfc9111_stale_20261026/REPORT.md)에 보존합니다. 실제 질문 결과의 저장·초안·Wiki 반영·재시작 재조회도 추가 검증했습니다. 다음 표는 현재 남은 범위입니다.

| 담당 | 남은 작업 | 현재 근거와 미완료 사항 |
| --- | --- | --- |
| Python/API | WSL2 서버 설치 후 HTTPS·자동 시작, 재부팅·업데이트 시 데이터 보존 검증 | [platform 계획](../platform/PLAN.md)의 배포 도구는 구현됨. 사용자가 환경 설치 중이며 실제 연결 검증은 설치 후 진행 |
| Python 실행기 + UI | Windows 개인 실행기·보호 저장·프로세스 취소를 앱에서 끝까지 검증하고 필요한 결함 수정 | 현재 PC의 실제 보호 기능 probe로 고정 차단을 보완하고 좁은 회귀 검증 완료. Windows 설치 후 실기기 확인이 남음 |
| MCP·의미 평가 | 수정 후 실제 AI 질문 제출/인용·추출·별도 의미 검사 재검증, 실패 시 원인 수정 | 실제4회 평가와 질문 후속 통합 완료. 추출 의미/검사 위치 오류를 보완했고 새 원문 최종 평가 준비 중. [ontology 계획](../ontology/PLAN.md)과 평가 규칙 적용 |
| UI | macOS 신규 PC 설치와 Windows 설치 패키지, 최초 연결·진단·반복 사용·종료/재시작·수동 업데이트 검증 | [UI 계획](../ui/PLAN.md)의 Mac arm64/Windows x64 설치 파일·Python 실행기 후보2 준비. Mac 앱 교체/설정 보존과 격리 실행기 ZIP 검증 완료. Windows 실기기와 신규 PC 설치는 남음 |
| 공통 통합 | Mac·Windows 두 PC가 WSL2 서버에 연결하여 실제 AI 결과를 저장·편집·재사용하고 충돌·권한·연결 실패 처리 확인 | 실제 질문 결과의 macOS 후속 통합 완료. 배포 환경의 두 PC 사용자 동선은 서버/Windows 설치 후 확인 |

착수 전 필요한 환경 정보는 실제 Windows/WSL2 서버·클라이언트, 접속 주소/TLS·운영 계정과 지원할 OS/CPU 조합입니다. 현재 macOS arm64 패키지 근거만으로 다른 아키텍처의 지원을 선언하지 않습니다. 앱 서명·공증 여부와 내부 설치 시 신뢰 확인 절차도 배포 방식에 맞춰 정해야 합니다.

## v0.1.0 출시 완료 조건

- 지원 OS/CPU 조합과 필요한 Python·개인 AI CLI·OCR 설치 조건을 명시하고, 각 대상의 배포 파일로 신규 설치·최초 연결·실제 진단을 통과합니다.
- Windows/WSL2 서버에서 HTTPS·인증/권한·자동 시작을 확인하고, 서버와 두 클라이언트를 재시작한 뒤 같은 자료·이력·허용 범위로 다시 연결합니다. 서버가 개인 AI/변환을 대신 실행하지 않는 기존 경계를 유지합니다.
- 실제 AI로 원본 등록/변환 → Wiki·그래프 → 질문/근거 → 저장 답변 → 편집 초안 → 명시 Wiki 반영 → 종료/재시작 후 재조회·후속 질문을 반복합니다. 저장 영수증과 인용을 확인하고, 별도 의미 평가의 오류·미실행을 성공으로 취급하지 않습니다.
- 격리 배포 데이터에서 두 PC의 같은 문서 수정 충돌, 권한 회수, 연결 단절·응답 유실·취소·부분 완료를 확인하여 원문/전체 이력과 확인된 결과를 보존합니다. 복구 시 자동 AI 재실행·중복 저장이 없어야 합니다.
- 앱·Python 실행기·서버의 수동 업데이트를 검증하고 호환 버전을 기록합니다. 교체 과정에서 원본·위키 전체 이력·업무 기록·설정을 보존하고, PC에 묶인 보호 자격증명은 재연결 절차를 확인합니다. 사용자 요청에 따라 백업 생성·백업 복원·그 백업에 의존하는 되돌림 시험은 이번 출시 조건에서 제외합니다.
- 배포 파일·버전·지문, 설치/업데이트/복구 안내, 실제 검증 결과와 알려진 제약을 남깁니다. 서명·공증 상태와 설치 절차를 사실대로 안내합니다. OCR 오인식·복잡한 배치 및 스키마의 표현 한계는 원문 확인·검토 흐름과 함께 공개하며, 핵심 흐름 실패·데이터 손실·권한 오류는 알려진 제약만으로 출시 완료 처리하지 않습니다.

새 실제 모델 전송의 기존 자동 승인 검토 거부는 준비된6개 파일/해시·수신자·최초3회 범위를 사용자에게 제시하고 명시 승인을 받은 뒤 해소했습니다. 후속 판정은 실제 산출물을 고정한 전송 목록에 따라 별도 확인하며 기존 실패를 삭제하거나 성공으로 바꾸지 않습니다.
