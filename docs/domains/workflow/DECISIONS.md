- 이유: 각 단계의 완료 조건과 검증 결과를 확인한 뒤 다음 기능을 추가하기 위해서입니다. 진행 상태는 [PLAN.md](../../PLAN.md)에서 관리합니다.

### D-004 — 문서 책임 분리와 최소 구성

- 이유: 중복된 설명이 서로 어긋나는 것을 줄이고 다음 작업자가 필요한 정보를 찾기 쉽게 합니다. 파일별 역할은 [AGENTS.md](../../../AGENTS.md)에 정의합니다.

### D-034 — 지식을 축적·활용·갱신하는 제품 목적 (2026-10-23)

상태: 사용자가 합의한 제품 목적입니다. 자료 축적 → 업무 질문·결과물 활용 → 지식 갱신의 방향이며, 아래 미결정 사용자 흐름이나 새 API의 구현 완료를 뜻하지 않습니다.

- 목적: 사람과 AI가 문서와 업무 판단을 함께 축적·활용·갱신하는 공동 지식 공간입니다. 대화나 AI 세션이 바뀌어도 허용된 자료와 적용 가능한 현재 판단을 찾아 다시 사용할 수 있어야 합니다. 미검토·오래됨·불확실함도 함께 드러내며 항상 완전하거나 정확한 지식을 보장한다고 표현하지 않습니다.
- 제품의 중심: 사용자는 **“LLM Wiki에 AI 온톨로지 도입”**을 화면 설계에서도 유지해야 한다고 명시했습니다. 원문에서 발견한 개체·개념·조건·관계·속성과 그 근거를 질문·탐색·수정·재사용에 연결하는 것을 기준으로 삼습니다. 화면 구성 제안은 D-039에서 관리합니다.
- 검토 기준: 자료 도입 → AI 정리·연결 → 사람 검토 → 질문·결과물 활용 → 결과의 위키 반영 → 변경 재검토의 연결을 기준으로 정책과 화면을 조사합니다. 사용자가 작업의 대상·현재 상태·다음 행동·완료 결과를 확인할 수 있는지, 다음 작업에서 그 결과를 다시 찾을 수 있는지가 중요합니다. 모든 자료와 답변에 새 사전 승인 단계를 추가한다는 뜻은 아닙니다.
- 지식과 판단: 원문·AI 해석·전문가 판단은 D-025·D-028·D-031의 출처와 상태를 유지합니다. 원문 정정, 근거에 따른 해석 정정, 전문가의 업무 정책 변경은 서로 다른 작업입니다. 사람의 판단을 현재 범위에 적용하는 것과 원문을 덮어쓰는 것을 구분합니다. AI 결과를 저장할 때의 출처 보존·재사용 계약은 아래 미결정 범위에 남깁니다.
- 화면과 연결 수단: D-033의 AI 대화 중심 및 필요할 때 여는 문서 뷰어 선택은 유지합니다. 문서 뷰어·그래프·검토함은 이 순환에서 맡는 업무로 평가하고, MCP·CLI·Electron은 지식에 접근하고 작업을 실행하는 수단으로 봅니다. 35개 화면의 존재만으로 순환 전체가 정의되거나 사용성이 검증됐다고 판단하지 않습니다.
- 후속 구체화와 남은 범위: 전문가 판단에 새로 등장한 용어의 서버 발견 경로는 [D-040], 첫 실자료의 선택·등록·부분 추출은 [D-042]에서 구체화했습니다. 일반 자료의 원격 등록·개인 CLI 요청·단계별 저장/화면 결과 계약은 [D-043]에서 설계했으며 제품 연결은 미구현입니다. 미검토·재검토 상태를 답변에 드러내는 기본 행동, AI 결과 문서의 원출처·버전·판단 이력 보존, 바뀌거나 사라진 옛 판단 및 영향 권고의 재검토 종료 조건은 남아 있습니다. 조사 결과와 우선순위 제안은 [PLAN](../../PLAN.md)에 기록하며 기존 API가 이 기능을 모두 제공한다고 표시하지 않습니다.

## D-049 — 도메인별 문서와 작업 규모별 절차 (2026-10-25)

상태: 사용자가 요청한 문서 체계 정리입니다. 제품 계약·데이터·권한·다음 구현 단계를 변경하지 않습니다.

- 결정: 루트 PLAN/DECISIONS는 색인, 도메인 PLAN은 현재 상태/완료 조건, 도메인 DECISIONS는 해당 계약/이유, 도메인 HISTORY는 이후 실행 이력으로 나눕니다. 이관 전 원본 4개는 동결 보관하고 SHA-256을 기록합니다. D-042의 대상별 운영 정정 이력은 보관본으로 연결합니다.
- 읽기: AGENTS의 경로 표에서 주 도메인을 정한 뒤 그 PLAN/DECISIONS의 관련 절과 필요한 RULES만 확인합니다. 공통 UI 수정에 ontology/evaluation·운영 이력을 읽지 않습니다. 실제 계약을 건드릴 때만 관련 도메인을 추가하며 원문 분리 평가의 입력 제한은 우선합니다.
- 규모: 문구/스타일·작은 수정은 직접 처리하고 관련 확인만 실행합니다. 일반 기능은 해당 완료 조건과 영향 경로를 확인합니다. 저장·권한·공유 계약 변경은 격리 데이터의 실패/충돌/호환 검증까지 넓힙니다. 전체 검증은 공통 영향·통합 이정표·원인 미확인 회귀 때 실행합니다.
- 기록: 현재 상태를 교체하고 실제 검증은 해당 도메인 HISTORY에 짧게 남깁니다. 중요한 선택만 D 번호를 추가하며 실행법이 바뀔 때만 README를 수정합니다. 과거 기록은 수정하지 않고 후속 이력으로 정정합니다.
- 이유: 같은 시작 문서·무관한 계약·과거 작업을 반복해서 읽는 비용을 줄이면서 저장 보존·권한·검토·평가 계약은 그대로 적용하기 위해서입니다. 읽기 범위 지침이며 파일 접근 권한 격리를 제공하지 않습니다.

## D-063 — 반복 사용하는 v0.1.0 내부 배포판의 지원 범위 (2026-10-26)

상태: 사용자가 일회성 PoC를 넘어 v0.1.0 배포 수준을 요청하고, 지원 환경을 macOS·Windows 앱 + Windows/WSL2 서버로 선택했습니다. 출시 완료를 선언하는 결정은 아닙니다.

- 결정: 설치 후 자료와 작업을 보존하며 반복 사용하는 내부 배포판을 목표로 합니다. 클라이언트는 macOS·Windows Electron 앱, 중앙 서버는 Windows 호스트의 WSL2 구성을 지원 범위로 삼습니다. 개인 AI와 변환은 각 PC에서 실행하는 기존 경계를 유지합니다.
- 완료 기준: 대상 환경의 실제 설치·연결·AI 활용·재시작·두 PC 사용과 데이터 보존, 수동 업데이트를 배포 파일로 검증합니다. 같은 날 사용자가 백업·복원을 하지 않겠다고 명시해 백업 생성/복원과 이에 의존하는 되돌림 시험을 이번 v0.1.0 조건에서 제외했습니다. 기존 자료·전체 이력 보존 규칙은 유지합니다. 세부 완료 조건과 담당별 남은 상태는 [workflow PLAN](PLAN.md#v010-출시-완료-조건)에 둡니다. 기존 단계5/6의 시험과 버전 문자열만으로 이 기준을 충족했다고 표시하지 않습니다.
- 작업 기준: 먼저 안내에 따른 수동 업데이트 경로를 검증합니다. 자동 업데이트·새 호스팅 서비스 도입은 이 결정의 필수 구현 범위에 넣지 않습니다. 지원할 OS 버전/CPU, 실제 서버 접속/TLS·운영 계정, 서명·공증 및 내부 설치 신뢰 확인 방식은 배포 전 확정할 항목입니다.
- 품질 경계: 실제 모델의 인용·저장·후속 활용과 의미 평가를 합성 모델의 계약 시험과 구분합니다. 알려진 OCR·표현 한계는 원문 확인·검토 방법과 함께 기록할 수 있지만 핵심 흐름 실패·데이터 손실·권한 오류는 출시 차단 사항입니다. 실제 모델 전송 승인·운영 권한 부여·자료 이전은 이 지원 범위 선택으로 승인됐다고 간주하지 않습니다.
- 이유: 사용자가 원하는 결과는 다음 실행과 다음 버전에서도 자료와 작업을 이어가는 제품이므로, 개발 PC의 한 번 성공한 시연 외에 설치·운영·복구 근거가 필요합니다.
