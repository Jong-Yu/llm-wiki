# 분석 작업·추출 규약 계획

## 현재 상태

실행 제공자를 Codex 또는 Claude Code로 선택할 수 있습니다. 서버 실행 이력과 별도 검사 보고에 실제 제공자를 보존하고, 기존 고정 진단 규약은 정확히 알려진 스키마의 제공자 메타데이터만 확장한 검증 사본으로 처리합니다. 기존 발행 바이트/hash·정책·입력 기준은 유지하며 새 발행에는 두 제공자를 명시합니다. 관련 서버·CLI 계약 검증을 완료했으며 실제 모델 의미 정확도와 구분합니다. [D-065](DECISIONS.md#d-065--codexclaude-실행-기록과-고정-규약-호환-2026-10-26)와 [HISTORY](HISTORY.md)를 따릅니다.

RFC9110 §9.2.1의 실제 별도 판정은 상태/verdict 계약을 지켰으나, 평가 하네스가 포함한 원본 전체 줄 번호와 발췌문 줄 번호가 혼동되어 인용 위치 검증에 실패했습니다. 검사 지침에 입력 source의 첫 줄을1로 세는 기준과 D-024의 viewpoints 정규화 분류를 명확히 했습니다. 기존 공개 진단 스키마·서버 검증은 유지하고 관련24검사를 통과했습니다. [개발 평가](../../../evals/rfc9110_safe_20261026/REPORT.md)를 보존하며 수정 후 새 원문 평가와 구분합니다.

공통 규약·작업 접수·단계별 고정 입력·위키/그래프 결과 영수증, 개인 Codex 실행·별도 의미 검사, 분석 계획·추출안 수동 비교/명시 적용, 질문 실행·결과 초안/Wiki 반영과 기존 작업 재개가 구현되어 있습니다. 원본13형식 및 변환 보고, 앱 연결/패키징의 기존 완료 범위를 이전 후속 문구로 다시 미구현 처리하지 않습니다. API·앱 통합의 최신 근거는 [platform HISTORY](../platform/HISTORY.md)·[ui HISTORY](../ui/HISTORY.md)를 따릅니다.

D-056의 규칙별 다섯 상태·진단 v2·별도 의미 검사 위에 관리자용 불변 발행·허용/기본 규약 전환·전체 정책 보존/CAS·명시 되돌림을 완료했습니다. 실제 격리 HTTP/MCP 서버에서 발행→허용→새 초기화→입력→진단 저장/조회→구 v1 유지·명시 rebase→되돌림을 검증했습니다. 기존 작업은 고정 규약을 계속 사용하며 기본값 변경이 작업을 자동 전환하지 않습니다. [D-058](DECISIONS.md#d-058--규약-허용-정책의-명시-전환전체-보존되돌림-2026-10-25), [실행 절차](RULESET_ROLLOUT.md), [이번 검증](HISTORY.md#2026-10-25--규약-발행허용전환되돌림)을 따릅니다.

별도 의미 검사의 상태·판정 계약과 부분 보고 보존을 보완했습니다. 모델 출력에서 규칙별 상태와 findings를 묶어 `not_run`/`schema_limit` 충돌을 구조적으로 거부하고, 원문 인용·대상 또는 상태 연결이 잘못된 규칙은 `error`로 남기면서 다른 유효한 규칙과 근거를 보존합니다. 기존 진단 v1/v2 발행 바이트·다섯 상태·저장 결과 참조는 유지합니다. [D-061](DECISIONS.md#d-061--별도-의미-검사-상태-계약과-부분-보고-보존-2026-10-26), [개발 회귀·CLI 검증](HISTORY.md#2026-10-26--별도-의미-검사-상태-충돌과-부분-보고-보존)을 따르며 실제 모델의 개선 효과는 새 원문 평가가 필요합니다.

운영 전환은 **미적용**입니다. 현재 확인된 개인 MCP의 사용자 `jong-yu`/tenant `personal`은 `read` 권한이며, 운영 규약 대상 경로와 관리 권한이 확인되지 않았습니다. 검증된 격리 발행 산출물·정책 변경안·되돌림 절차를 준비했고 운영 권한·설정·위키는 변경하지 않았습니다. 합성 모델 보고를 사용하는 계약 시험은 실제 모델 의미 정확도 평가와 구분합니다.

추출안 재추출 실행·실제 OCR·Windows/운영 배포·앱 복구 및 통합은 각 담당의 이번 병렬 검증 근거를 반영하는 중입니다. 공통 결과 저장 경계에 추출안 작업의 `save=false` 강제를 연결했으며 실제 후보/진단 연결·개인 실행기의 최종 결과는 해당 담당 인계로 확정합니다. 이미 완료한 일반 분석 실행기를 재구현하지 않습니다.

## 남은 적용·검증

- 확인된 운영 관리 호스트·권한·기존 규약 root/policy·tenant·새 버전·기본값 전환 여부·서버 업데이트 방법을 받아 발행 산출물 호환을 다시 확인하고, 명시 정책 전환과 실제 접속을 수행합니다. 현재 대상 미확정 때문에 운영 완료로 표시하지 않습니다.
- 이번 실행기·OCR·앱 통합의 최종 근거를 각 소유 도메인 기록과 대조합니다. Windows 실기기·두 PC·HTTPS/자동시작·서명 자격이 필요한 부분은 실제 확인된 범위만 완료로 기록합니다.
- 실제 원문/모델 의미 정확도 평가는 ontology의 원문 분리 평가로 따로 수행·기록합니다. 구조·인용·전송·저장 통과로 의미 정확도나 사람 승인을 대체하지 않습니다.

## 완료 조건

고정 원문·규약·선택 맥락·각 버전과 단계별 저장 영수증을 연결하고 변경/충돌/실패를 검증합니다. 스키마·의미 변경 시에만 ontology의 해당 평가 절차를 추가합니다.

현재 접수 묶음의 완료 조건은 원본 기준/작업 소유권·현재 권한·request/job/lease 분리·멱등/취소·원본 보존과 실제 CLI API/MCP 접수·hash 확인 수신입니다. 후속 규약/AI 저장의 완료 조건을 통과한 것으로 확대하지 않습니다.
