# 분석 작업·추출 규약 계획

## 현재 상태

### 등록·추출·재개

- 개발본은 큰 보존 등록의 전체 본문을32MiB 고정 참조 묶음으로 읽고 작은 참조 요청으로 Wiki에 저장한다. 요청/모델 입력8MiB와 기존 저장·이력 계약은 유지한다. 구간 누적 추출·전체 재검토·중단 재개는 구현했지만 **자동 분할 분석은 비활성 상태**다. 새 원문에서 구간 경계에 걸린 문장의 미해결 의견 때문에 재검토가 중단되어 전체 완료 조건을 충족하지 못했다. 작은 문서의 기존 분석 경로는 유지한다. [D-164](DECISIONS.md#d-164--큰-등록-본문의-고정-참조와-구간별-누적-분석-2026-11-25) · [보존 검증](HISTORY.md#2026-11-25--큰-등록-본문-참조와-누적-구간-분석의-보존-검증).

- **AI 해석 후보 쪽 그림(Windows 포터블 0.6.4 반영):** 등록 문서의 그래프 추출 호출에 변환이 도식 연결을 정리하지 못한 쪽의 원본 화면 그림을 함께 넘깁니다(최대 40장, 실패하거나 CLI가 그림을 받지 않으면 글만). 격리 서버의 실제 Claude 추출에서 8쪽 정답 연결 62개 중 글만 5개, 그림 포함 29개가 들어갔습니다. Codex 실제 첨부·Windows 실행·LibreOffice 글꼴은 미확인입니다. [D-169](DECISIONS.md#d-169--ai-해석-후보-쪽의-원본-화면을-그래프-추출-호출에-함께-넘기기-2026-11-26) · [검증](HISTORY.md#2026-11-26--ai-해석-후보-쪽-그림을-그래프-추출-호출에-붙이기d-169) · [0.6.4 릴리즈](https://github.com/Jong-Yu/llm-wiki-releases/releases/tag/app-0.6.4-portable).
- 기본 흐름은 불변 원본 → 읽힌 문자를 보존하는 Markdown 한 개 → 그 본문 판본의 온톨로지 추출입니다. 보존형 본문 준비는 모델을 호출하지 않으며 요약·재작성은 명시적 고급 계획으로 분리합니다. 별도 plan이나 파생 TXT 원본을 만들지 않습니다. [D-074](DECISIONS.md#d-074--기본-등록의-단일-markdown과-최소-분석-기록-2026-10-28).
- 기기의 taskId·접수 전 requestId와 서버 job을 연결했습니다. 응답 유실에는 기존 요청을 조회하고, 본문 저장 뒤 추출 실패에도 성공 영수증을 보존해 본문을 재저장하지 않습니다. [복원 계약](../platform/DECISIONS.md#d-151--기기별-문서-처리-식별과-보호된-복원-기록-2026-11-23).
- 서버 공유 승인·기기 실행권과 기존 등록/claim/lease/재개를 연결해 **운영 서버·0.5.0 Windows 포터블에 반영**했습니다. 승인 대상은 현재 승인·고정 근거·실행권 없이는 등록/실행하지 않습니다. `execution_claim_id`는 한 번만 소비하고 실패·만료 뒤에는 영수증 확인과 명시 인계가 필요합니다. 일반 부분 보존·기존 작업은 호환하고 앱에도 CLI와 같은 원본 4MiB 보존 등록 예외를 적용했습니다. [D-154](../platform/DECISIONS.md#d-154--서버-알림-이력과-공유-문자-사용-승인-2026-11-24) · [배포 기록](../platform/HISTORY.md#2026-11-24--알림승인-050-포터블-공개와-서버-반영).
- **승인한 수정 문자 고정은 개발 코드에 반영했고 미배포입니다.** 서버가 보정 참조를 최초 registration 사건에 고정하고 최초 Wiki 저장·입력 복원에서 같은 문자를 조립합니다. 외부 접수의 보정 참조 주입을 막고 원래 경고·미독·기존 요청 지문을 보존합니다. [D-156](../sources/DECISIONS.md#d-156--보류-쪽의-재인식과-불변-문자-보정-2026-11-24) · [검증 기록](HISTORY.md#2026-11-24--승인한-쪽-보정의-분석-입력-고정).
- **D-158 입력 확장(개발·미배포):** 누락 위치의 직접 입력·명시 빈 페이지·일반 단위·전체 문서 선택을 최초 registration에 고정합니다. 원래 `complete/unread_ranges/units`를 유지하며 유효 입력 위치와 사용자 보완 근거를 별도 제공합니다. 실제 AI 입력 한도/미포함 진단 차단은 유지합니다. [검증](HISTORY.md#2026-11-25--직접-입력의-고정-등록과-변환-진단-분리).

### 규약·입력과 저장 후 대조

- 기본 `rules_view`와 `input_view`는 **full**입니다. 명시 `stage-v1`·`current-review-v1`, 문서별 작업 묶음과 설정 지문 기반 재사용을 지원합니다. 전체 원문·발행 규약·현재 판단·저장 스키마는 유지하며, 선택 보기에서 제외한 과거 이력은 감사/경고로 표시합니다. 실제 필수 미독은 `unread_ranges`로 보존하고 저장을 차단합니다. [D-076](DECISIONS.md#d-076--명시-입력-보기와-검증된-재개로-분석-전송량-제한-2026-10-29) · [D-133](DECISIONS.md#d-133--공통단계별-모델-지침과-출력-스키마-중복-분리-2026-11-18).
- `stage-v1` 추출 비교는 품질·반복 일관성 조건을 충족하지 못해 기본 적용하지 않았습니다. 규약 우선 배치와 `json-values-v1`도 철회했습니다. 원시 평가·실패는 보존하고 현재 기본값과 구분합니다. [지침 비교](HISTORY.md#2026-11-18--승인-후-추출-반복-비교와-기본값-유지) · [배치 철회](DECISIONS.md#d-136--추출-입력의-규약-우선-배치-2026-11-19).
- 인용 anchor의 CR/LF 좌표와 진단/Front Matter의 `splitlines()` 좌표를 구분해 안내하며 준비·AI·교정·검증·저장·의미검사·대조 시간을 관측합니다. 실제 Codex 및 Mac 설치 앱 등록을 확인했지만 개발 표본의 시간 개선을 모든 문서의 속도·품질 보장으로 확대하지 않습니다. [구현 기록](HISTORY.md#2026-11-21--인용-좌표-안내와-단계별-시간-관측) · [앱 실측](HISTORY.md#2026-11-22--설치-앱-등록부터-후속-대조완료-화면까지-실측).
- 저장 없는 초안 검사에서 수정 가능한 실패만 최대 2회 전체 재추출합니다. 원시 출력·전체 입력·최종 hash를 보존하며 미독·취소·adapter 오류·저장 응답 유실을 교정 호출로 재시도하지 않습니다. 형식 통과는 의미 승인과 구분합니다. [D-081](../ontology/DECISIONS.md#d-081--저장-없는-초안-검사와-제한된-끝점-역할-규칙-2026-10-29).
- 추출 저장 영수증 뒤 같은 AI 세션으로 기존 지식을 검색·대조하고, 독립 의미 검사는 별도 세션에서 수행합니다. 실제 Codex 전체 흐름은 확인했습니다. 대조나 로컬 요약 기록 실패 때문에 저장된 추출을 재실행하지 않습니다. 대조의 의미·조회 계약은 [knowledge 계획](../knowledge/PLAN.md)을 따릅니다.

## 현재 공개 계약

- 변환 저장·부분 확정·계획 생성은 HTTP 경계에서 변환한 업무 TypedDict를 받습니다. 입력 복사·profile 제외·기본값·저장 지문은 기존과 같습니다. [검증](HISTORY.md#2026-11-25--분석-계획의-업무-입력-계약-분리).
- 기본 접수는 `POST /api/v1/tenants/{tenant}/analysis-jobs/registrations`와 MCP `analysis_registration_create`입니다. `request_id`, `source_ref`의 원본 ID/판본/hash/등록 판본, `document`, `title`, 선택 `conversion_ref`를 사용합니다. 원본을 먼저 등록하고 바이너리는 불변 변환 보고를 참조하며 MD/TXT에는 변환 참조가 필요 없습니다.
- 응답은 기존 `CreatedJob` 봉투와 job 조회/claim/input/result/cancel 경로를 사용합니다. `Job.registration`은 보존 모드·제목·변환 참조 또는 과거 작업의 null입니다. `Job.conversion`은 방식·위치·complete/unread_ranges/warnings·AI 출처·실제 actor와 `first_markdown`의 document/revision/body_revision/document_id를 연결하고 저장 전 값은 null입니다.
- 신규 작업은 `_personal/<userId>/analysis/<jobId>/`에 기록합니다. 구 `_jobs`·actor·bundle은 원래 위치/바이트로 호환하며 중복 위치는 오류입니다. 자동 이관·삭제나 과거 actor 필드 주입은 하지 않습니다.
- 고정 입력은 불변 원본·변환 참조 또는 정확한 Markdown 판본으로 복원합니다. 누락 판본·hash 불일치에서는 중단하고 source_revision은 전체 파일 SHA, 인용·anchor는 전체 파일 1-based 줄 좌표를 유지합니다. 공통 `parse_document`와 `WikiStore.save()`를 사용합니다.
- 재사용은 현재 원문·규약·권한·맥락·검토와 실행 설정 지문을 대조합니다. 최종 저장 증거와 job 연결이 확인된 경우에만 영수증 유실을 완료로 복원하고 불명확한 중간 증거는 `pending_reconcile`로 남깁니다.
- 통합 이력은 작업 이벤트만 조회하고 상세 결과·입력·실행 준비 검증은 기존 상세 API가 수행합니다. 목록 증분 관측·입력 재사용에도 소유·현재 lease·정책·판본 검사를 유지합니다. [D-102](DECISIONS.md#d-102--통합-이력의-작업-이벤트-조회와-상세-결과-검증-분리-2026-11-06).

## 남은 작업과 검증

- 0.6.4의 AI 해석 후보 쪽 그림 전달에서 Codex 실제 첨부·Windows 실행·LibreOffice 글꼴 확인. 릴리즈 전 렌더·취소·인코딩 회귀는 [검증 기록](HISTORY.md#2026-11-26--릴리즈-전-쪽-그림-렌더의-실행권취소-보완)을 따른다.
- 큰 문서의 구간 경계를 넘는 근거 확인과 최종 전체 재검토 완료. 현재 후보를 기본 활성화하거나 일반 문서 정확성이 확인된 것으로 간주하지 않는다. 개발 자료를 이용한 프롬프트 수정은 두 번에 도달했으며 최종 평가의 미완료와 실패 산출물을 보존한다.

- 호환 서버·0.6.4 포터블에 포함한 문자 보정의 실제 개인 PC 등록→Wiki 저장→추출 입력 복원 확인.
- Windows 전체 분석과 실제 두 PC의 승인·이어가기·동시 실행 차단·실행 인계 확인. 0.5.0 배포/격리 검증과 구분합니다.
- Claude의 추출·동일 세션 재개·자동/수동 대조 전체 성공. 최초 실제 추출은 제공자 사용 한도로 거절됐으며 이후 일반 질문 성공과 별개입니다. [제한 기록](HISTORY.md#2026-10-30--claude-실제-검증의-제공자-사용량-제한).
- 선택 입력·교정의 다양한 실문서 정확도와 독립 반복 일관성, 남은 저장 후 대조 지연 검토. 새 규약 승인 뒤 자동 재추출·미확인 저장 자동 복구·기존 작업 자동 정리·고정 보관기간은 추가하지 않습니다.

## 완료 조건과 근거

원본 중복 없이 단일 Markdown·Front Matter·실제 actor/AI 출처와 그래프 기준 판본을 연결해야 합니다. 원문·변환 경고/위치·과거 작업 바이트를 보존하고 CAS·멱등·동시 접수·부분 성공·응답 유실·재개·취소·소유권을 확인합니다. 형식/저장 검사, 실제 모델 의미 평가, 앱·운영·Windows 확인은 각각 수행한 범위만 완료로 기록합니다.
