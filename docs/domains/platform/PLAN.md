# API·MCP·실행 환경 계획

## 현재 배포 — PPTX 그림 문자 복구 0.6.5 (2026-11-26)

[0.6.5 Windows 포터블](https://github.com/Jong-Yu/llm-wiki-releases/releases/tag/app-0.6.5-portable)과 운영 서버에 PPT 검토 대상 복원·개인 AI 그림 문자 복구를 반영했습니다. 소스는 `39ac710`/`v0.6.5`입니다. 기존 주소·터널을 유지했고1,840개 자료/정책 파일은 동일합니다. 알림 DB 한 곳은 의도한5슬라이드 검토 대상 복원과 이력만 변경됐음을 별도로 검증했습니다. 공개 ZIP/SHA 전체 다운로드·기존8릴리스/16자산·latest 보존을 확인했습니다. 실제6그림의 Claude 판독과 격리 등록을 검증했으며 Windows 실기·두PC·Codex 실제 그림 판독은 남습니다. [배포 기록](HISTORY.md#2026-11-26--ppt-그림-문자-복구-065-배포).

## 현재 상태

- 새 VOC의 PPT 검토 대상 복원과 개인 AI 그림 문자 복구는0.6.5에 반영됐습니다. 서버가 미판단 `whole_document/pending`만 고정 보고의 단위로 복원하고, 앱은 명시 실행의 복구 후보를 보호 초안에 받습니다. [대상 복원](HISTORY.md#2026-11-26--ppt-미판단-검토-대상-복원) · [개인 실행 경계](HISTORY.md#2026-11-26--개인-ai-그림-문자-복구의-ipc실행-경계).

- 운영 서버에 로그인 사용자의 텍스트 오류 보고 접수와 `data/voc` 개별 파일 보관을 추가했습니다. 목록·조회·피드백 기능 없이 앱에서 전송만 합니다. [D-168](DECISIONS.md#d-168--텍스트-오류-보고의-서버-전용-보관-2026-11-26) · [검증 기록](HISTORY.md#2026-11-26--텍스트-오류-보고-api와-서버-보관). 운영 서버와 Windows 포터블0.6.3에 반영했습니다.

- 개발본에서 PPT/PPTX 등록 뒤 문서 목록의 응답 형식 검증이500으로 실패하던 누락을 수정했습니다. 개인 알림 목록 삭제는 원천 이력을 보존하는 별도 상태로 연결했습니다([D-166](DECISIONS.md#d-166--개인-알림-목록에서-삭제와-원천-이력-보존-2026-11-26)). 운영 서버와 공개 Windows 포터블0.6.1에 반영했으며 Mac 설치는 정상 종료 대기입니다. [진단·검증 기록](HISTORY.md#2026-11-26--문서-목록500-진단과-개인-알림-삭제).

- 개발본의 알림 본문 조회를 분리하고 연결·알림·초안 IPC의 공통 검사와 채널 타입 연결을 정리했습니다. 분석·업무 API 서비스의 연결 의존성도 필요한 메서드로 한정했습니다. [품질 개선 검증](HISTORY.md#2026-11-25--조회-책임과-ipc-계약-정리).

- 개발본에 Office·이미지 원본의 개인 PC 미리보기와 별도 IPC/보호 임시 폴더를 연결했다. Office는 기존 LibreOffice를 사용하며 구형 PPT의 격리 지원 여부를 확인한다. Windows 포터블0.6.4에 포함했으며 Windows 실기는 별도다. [D-165](DECISIONS.md#d-165--office이미지-원본의-기기-내-미리보기-2026-11-25) · [검증](HISTORY.md#2026-11-25--원본-미리보기의-로컬-실행-경계).

### 배포와 개발본

- 공개 Windows 포터블·호환 서버는 **0.6.5**(`39ac710`/`v0.6.5`)이며 현재 범위는 위 절을 따릅니다. 과거0.5.0의 서버 알림·판단·승인·기기별 이어가기는 [0.5.0 기록](HISTORY.md#2026-11-24--알림승인-050-포터블-공개와-서버-반영), 설치형0.1.2는 [과거 배포 기록](HISTORY.md#2026-11-23--012-정식-배포와-공개-다운로드-검증)을 따릅니다.
- 0.5.0 이후 **보류 쪽의 문자 보정 API·앱 IPC·개인 재인식**을 개발 코드에 연결했습니다. 보정을 표시하지 못하는 구0.5.0 클라이언트는 해당 쪽 확인·승인을 할 수 없습니다. 호환 서버와 Windows 포터블0.6.4에 포함했으며 Windows 실기 확인은 남아 있습니다. [D-156](../sources/DECISIONS.md#d-156--보류-쪽의-재인식과-불변-문자-보정-2026-11-24) · [검증 기록](HISTORY.md#2026-11-24--보류-해결의-보정-api와-개인-재인식-연결).
- PDF/PPT 문자·도식 변환의 후속 개발·AI 시험은 [sources 계획](../sources/PLAN.md)을 따릅니다. 등록을 Wiki 저장·온톨로지 구성까지 한 작업으로 잇는 새 제품 목표는 [UI 계획](../ui/PLAN.md)이며, 현재 배포된 승인 흐름과 구분합니다.

### 연결과 개인 실행

- 단일 ASGI 앱에서 인증된 `/api/v1`과 `/mcp`를 제공하고 기존 업무 저장소를 재사용합니다. 공개 가입·로그인, tenant/profile·행동 권한과 저장 직전 재인가를 유지합니다. [D-046](DECISIONS.md#d-046--업무별-백엔드-모듈과-fastapimcp-분리-및-스펙-주도-개발-2026-10-25).
- Codex·Claude 개인 CLI가 분석·질문·변환·별도 의미 검사를 실행합니다. 서버는 AI나 변환기를 실행하지 않습니다. Windows 번들은 Python·개인 실행기·OCR을 포함하고 AI CLI는 별도 설치합니다. 현재 PC의 보호 파일·프로세스 트리 진단 실패 시 실행을 거부합니다. [D-055](DECISIONS.md#d-055--개인-실행-환경과-읽기-전용-진단안전한-재개-2026-10-25) · [D-064](DECISIONS.md#d-064--windows-실행-전-실제-보호-기능-진단-2026-10-26) · [D-069](DECISIONS.md#d-069--windows-설치-파일에-개인-실행기와-ocr-포함-2026-10-27).
- MCP는 `all` 기본과 `ask`·`write`·`extract`·`review` 묶음, 선택 업무 안내·표준 프롬프트를 제공합니다. `ask`에는 읽기 전용 검토함과 본문 보기가 포함됩니다. `--guidance-mode` 기본은 `full`이며 평가용 축약 전송·스킬 안내 제외를 기본 적용하지 않았습니다. [D-134](DECISIONS.md#d-134--기능별-mcp-안내와-사용자-선택-프롬프트-2026-11-18) · [D-135](DECISIONS.md#d-135--역할별-mcp-도구-묶음과-읽기-본문-보기-2026-11-19).
- Mac 런처는 기존 프로젝트 서버·Quick Tunnel의 시작/재시작과 주소 기록을 관리합니다. 설정한 비공개 주소 메모 연동도 지원합니다. 기존 정책·토큰 오류를 초기화나 재발급으로 우회하지 않습니다. 실행법은 [README](../../../README.md#현재-mac의-apimcp-서버), 구조는 [core 길잡이](../../../core/README.md)를 따릅니다.

### 채팅·템플릿·복원

- 일반 v5/v6 질문은 공개 작업 설명과 답변 조각을 전달하며 최종 근거·스키마·저장 검증을 유지합니다. 등록 템플릿·실험용 초안은 완료 후 표시합니다. 추가 질문은 실행·lease를 끝내고 사용자 응답에서 원래 요청·고정 근거·템플릿을 이어받습니다. Codex·Claude의 실제 합성 호출과 앱 연결을 검증했고 0.1.3-rc.2 이후 포터블·서버에 반영했습니다. [스트리밍](HISTORY.md#2026-11-23--일반-질문-답변의-실시간-전송) · [추가 질문](HISTORY.md#2026-11-23--추가-질문-저장과-사용자-응답-이어가기).
- 템플릿은 불변 파일·지침 판본을 저장하고 DOCX/PPTX/XLSX·UTF-8 양식을 렌더링합니다. 구조·필드·무결성 검사 후 실제 파일을 반환합니다. Pandoc은 사용하지 않습니다. [D-129](DECISIONS.md#d-129--등록-템플릿의-불변-판본과-채팅-산출물-생성-2026-11-15) · [실제 DOCX 저장 검증](HISTORY.md#2026-11-16--템플릿-생성-cli-실패-진단과-실제-docx-저장).
- 문서 처리 taskId와 원본 판본·변환 시도·분석 request/job은 보호 기록으로 복원합니다. 성공한 AI 호출 확인도 같은 제공자·모델·경로와 현재 로그인에서만 복원하며 자동 호출하지 않습니다. [D-151](DECISIONS.md#d-151--기기별-문서-처리-식별과-보호된-복원-기록-2026-11-23) · [호출 확인 기록](HISTORY.md#2026-11-23--재시작-뒤-ai-호출-확인-기록-복원).
- 등록 입력·빈 구간 선택·고정 제출 요청은 별도 보호 초안으로 복원합니다. 원래 기준과 불변 참조를 유지하고, 완료/폐기 CAS가 늦은 저장을 차단합니다. 분할 저장·12 MiB 초과 복원·재인증 후 최초 요청 재개를 격리 검증했습니다. [초안 복원](HISTORY.md#2026-11-25--등록-입력과-고정-제출의-보호된-초안-복원).

## 현재 계약

- 알림의 원천 사건·읽음·페이지 확인·승인·공유 요청·실행 주체를 분리해 tenant별로 보관합니다. 원본/보고를 참조하며 현재 권한·고정 판본·CAS·안정 요청 ID를 검사합니다. 원천 저장 성공과 알림 실패를 구분하고 전달 대기·영수증으로 복구합니다. [D-154](DECISIONS.md#d-154--서버-알림-이력과-공유-문자-사용-승인-2026-11-24).
- 승인과 실행 PC를 구분하고 기기 실행권을 확보한 뒤 기존 claim/lease/결과 경로를 사용합니다. 저장 미확인은 원래 승인/접수 조회로 확인하고, 중단·만료는 영수증 확인 뒤 명시적으로 인계합니다. 앱의 보존 등록에도 CLI와 같은 원본 4MiB 예외를 적용했습니다. [분석 계약](../analysis/PLAN.md).
- OS 알림은 보조 전달이며 클릭은 해당 화면만 엽니다. 종료 중 서버 사건은 다음 실행에서 가져오고, 미전송 로컬 사건은 PC 재접속 때 전달합니다. 종료된 PC로 즉시 푸시하는 상주 서비스는 없습니다. 자동 이력 삭제·고정 보관기간은 적용하지 않습니다.
- HTTP/MCP는 전체 파일·본문 판본과 실제 actor를 전달하고 `WikiStore.save()` 등 기존 저장 모듈의 전체 이력·CAS·영수증을 사용합니다. 간결 응답·초안 검사·Clean Up도 저장/권한 경계를 유지합니다. `ontology_validate_draft`는 저장 없는 형식 검사이며 의미 승인과 구분합니다.
- 신규 서버 초기화는 새 절대 경로에서만 수행합니다. 기존 토큰 시작 호환은 보존하되 키 손실·암호문·알 수 없는 항목을 자동 복구하지 않습니다. 자료·정책·설정 이관과 권한 부여는 별도 명시 작업입니다.

## 남은 작업과 검증

- 실제 Windows의 문서 전체 처리·OCR·LibreOffice·AI 호출·보호 기능·설치/업데이트 확인.
- 0.5.0의 Windows OS 알림 허용/거부/클릭과 앱 숨김/종료, 실제 두 PC의 읽음·판단·승인·실행 인계. 격리 부하·회귀 검증을 실기기 성공으로 확대하지 않습니다.
- Claude의 **추출 후 같은 세션 대조** 전체 성공은 미확인입니다. 이후 질문/추가 질문 실제 호출 성공과 구분합니다. [기존 제한 기록](../analysis/HISTORY.md#2026-10-30--claude-실제-검증의-제공자-사용량-제한).
- Windows/WSL2 서버의 실제 설치·외부 HTTPS·재부팅 자동 시작·다른 PC 연결, 배포 서명·공증과 Mac 첫 실행 환경 확인. 생성된 배포 도구와 격리 시험만으로 완료 판정하지 않습니다.
- 로컬 stdio MCP의 거절된 보호 토큰은 정상 인증으로 재연결해야 합니다. 11월 21일 확인한 로컬·공개 HTTP의 정상 로그인 성공과 별개입니다. [연결 확인 기록](HISTORY.md#2026-11-21--정상-로그인으로-로컬공개-mcp-조회-확인).
