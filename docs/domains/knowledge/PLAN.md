# 개념 조회·연결·영향 계획

## 현재 상태

### 질문 근거 조회

- `knowledge_lookup(question)`은 후보 탐색과 근거 준비를 묶고, 선택 문서의 질문 관련 단락·주장·현재 판단을 반환합니다. 현재 응답은 `passages-first-v2`이며 전체 원문이 필요하면 `wiki_read`의 줄 범위 보기로 이어 읽습니다. 선택 문서마다 추출 상태·재검토/재추출 필요·원시/현재 보류 건수와 상세 조회 경로를 제공합니다. [D-137~D-140](DECISIONS.md#d-140--질문-조회-결과를-더-줄이고-줄-범위-읽기를-더하기-2026-11-20).
- 질문 후보는 그래프 순위와 본문 BM25 순위를 번갈아 섞어 그래프 없는 문서도 찾습니다. 문서당 색인 단어 상한은 60,000입니다. [D-142](DECISIONS.md#d-142--온톨로지가-없는-문서도-본문으로-질문-후보-순위에-넣기-2026-11-20).
- 앱 채팅은 허용 공간의 관련 Wiki·판단을 고정하고 첫 답변 전에 초기 근거를 제공합니다. 추가 조회 한도·현재 권한·인용 검증을 유지하며, 질문 접수의 기본 줄 읽기는 `whole-window-v1`입니다. 사용자 발언과 최신 변경 조건을 우선하는 대화 문맥을 사용하되 이전 답변을 새 사실의 근거나 사람 승인으로 쓰지 않습니다. [D-124](DECISIONS.md#d-124--기존-관계판단-색인과-첫-답변-전-고정-근거-제공-2026-11-08) · [D-138](DECISIONS.md#d-138--질문-근거-read의-요청-줄-범위-한-번에-주기-2026-11-19) · [D-120](DECISIONS.md#d-120--사용자-원문을-우선하는-질문-문맥과-조건-변경-유지-2026-11-08).
- 같은 원문의 줄 나누기·단락 점수 계산을 재사용하는 조회 개선을 서버에 반영했습니다. 응답 동등성 확인과 실제 Claude 전후 측정의 범위는 [검증 기록](HISTORY.md#2026-11-22--질문-조회-속도-개선결과-동일)과 [플랫폼 기록](../platform/HISTORY.md)을 따릅니다.

### 개념·연결·변경 영향

- 개념·주장·근거·검토함·통합 이력을 조회하고, 명시 문서 연결과 이름/유형이 같은 개념 후보를 구분합니다. 선택 용어 카드는 기존 원문·개체·판단을 읽으며 개체 설명 자동 생성은 도입하지 않습니다.
- 변경 영향은 이전 조회의 기준 판본과 현재 자료를 대조합니다. 현재 연결·과거 근거·재검토 권고와 복원 불가를 구분하고 자동 재추출·정책 승계를 하지 않습니다. 세부 조회 경계는 [RULES](RULES.md), 저장·접근 계약은 아래 절을 따릅니다.
- SQLite 질문 색인과 변경 관측, 같은 잠금 안의 검증 결과 재사용을 사용합니다. 원문/원장의 권위, 현재 권한, 손상·충돌·불완전 표시를 유지합니다. 성능 검증과 운영 반영은 [HISTORY](HISTORY.md)에 기록합니다.

### 저장 후 대조와 산출물

- 저장 후 대조는 실제 추출의 같은 제공자·세션을 재개해 검색·근거 읽기·재검색을 수행합니다. 실행별 5회 조회와 최대 20개 후보의 범위를 `coverage`로 알리고 후보·제외 이유·실패를 개인 실행 이력에 보존합니다. 수동 재대조는 보호된 로컬 세션 기록과 서버·사용자·공간·관점·문서·작업이 일치해야 하며, 현재 대상을 다시 전달합니다. stale 또는 기준 변경은 거부합니다. [대조 계약·검증](HISTORY.md#2026-10-29--저장-후-기존-지식-대조-계약).
- 웹 근거는 사용자가 선택한 질문에만 고정하고 원출처·보관 문자·인용을 보존합니다. 같은 대화는 웹 선택을 유지하고 새 대화는 해제합니다. [D-099](DECISIONS.md#d-099--질문별-외부-웹-근거-선택과-출처-보존-2026-11-05) · [D-125](DECISIONS.md#d-125--현재-질문을-사용하는-웹-검색-토글-2026-11-10).
- 등록 템플릿의 전체 원문 선조회·묶음 작성·단일 산출물 저장을 구현했습니다. 기존 자료를 재사용한 실제 채팅/DOCX 저장·다운로드는 확인했으나 내용 일부 누락, 인용 정의·링크, 페이지 배치 한계가 남습니다. [D-130·D-131](DECISIONS.md#d-131--큰-등록-템플릿의-묶음-작성과-단일-산출물-저장-2026-11-16) · [검증 기록](HISTORY.md#2026-11-16--기존-데이터의-템플릿-생성저장과-원본-비교).

### 미적용·보류

- 2026-11-23~24 일상어 검색 개선 실험은 사용자 결정으로 제품에 넣지 않고 종료했습니다. 실제 사용자 질문에서 실패가 반복될 때 새 질문으로 재검토하며, 골드셋 구축·그래프 탐색 확장은 보류합니다. [D-152](DECISIONS.md#d-152--일상어-질문-검색-개선-실험을-앱에-넣지-않고-마치기-2026-11-24) · [실험 기록](HISTORY.md#2026-11-24--일상어-질문-검색-개선-실험-종료미적용).
- 판본 표식(D-127), 초기 인용문 참조화(D-128), 검색 페이지 후보(D-123), 스킬 안내 제외와 등록 지침 보강은 기본 도입을 보류합니다. 실제 비용·품질 기준을 충족하지 못한 실험을 완료 기능으로 표시하지 않습니다. [결정](DECISIONS.md) · [실행 기록](HISTORY.md).

## 공개 구현 계약

- 문서 목록은 `documents.changes.document_fields()`의 metadata/document_id/body_revision/authorship를 사용합니다. `source_status`는 metadata.source로 판단하고 제목으로 계보를 추정하지 않습니다. actor와 AI origin을 구분합니다.
- HTTP 문서 목록·검색의 `group_sources=true`는 현재 원본 판본과 실제 `metadata.source.id/version`이 일치한 Wiki를 원본 행의 `documents`에 보존합니다. 목록은 묶은 뒤 페이지화하며 이전 판본 결과·미등록 계보는 독립 문서로 남깁니다. 기본 조회와 MCP는 기존 행 구성을 유지합니다. [검증](HISTORY.md#2026-11-25--문서-목록검색의-선택적-원본-계보-묶기).
- content/revision은 전체 파일, body/body_start_line/body_revision은 별도 필드입니다. 본문 검색·링크는 Front Matter를 제외하되 인용 줄은 전체 파일 기준입니다.
- 새 `_knowledge`와 기존 `_reviews`를 함께 발견하고 충돌·skipped·truncated를 알립니다. 원문 없는 원장의 이력은 보존하되 현재 지식으로 적용하지 않습니다. 과거 prefix·body 인용의 영향 복원도 같은 기준을 사용합니다.
- 개념 snapshot과 검토함/이력 cursor는 access_revision을 우선하고 과거 actor는 policy_revision으로 호환합니다. 감사용 policy_revision과 과거 actor를 재작성하지 않습니다.
- tenant 이력의 개인 분석 작업은 `JobStore.list_history_ids()`와 `JobStore.history()`로 발견·조회하며 소유 경계와 전체 events를 유지합니다. 상세 결과 검증은 [D-102](../analysis/DECISIONS.md#d-102--통합-이력의-작업-이벤트-조회와-상세-결과-검증-분리-2026-11-06)로 구분합니다.

## 남은 검증

- 검토 판단이 쌓인 실제 위키의 질문 품질과 여러 문서·긴 대화의 근거 발견을 확인해야 합니다. 처음 선택한 8개 문서 밖의 정답을 놓치는 비율과 실자료 전체 회수율은 미측정입니다.
- 큰 도구 결과의 Codex 보고 토큰은 모델이 받은 전체 양을 반영하지 않을 수 있습니다. 표본의 토큰·시간 개선을 일반 비용 절감이나 완전 정확성으로 확대하지 않습니다.
- 템플릿 산출물의 내용·인용·페이지 배치, 다른 실행 환경과 설치 GUI의 등록→분석→조회 전체 흐름, 자료 확대에 따른 집계·검토 조립 비용은 추가 확인 범위입니다. 개별 기능의 운영·설치 반영은 [플랫폼 계획](../platform/PLAN.md)을 따릅니다.

## 완료 조건과 근거

변경한 조회에서 원문·판단·출처와 현재 권한을 보존하고 current/stale/pending 및 complete/truncated/skipped를 정확히 표시합니다. 기계층과 전문가 정책, 실제 모델 평가와 합성 계약 검증을 구분합니다. 성능 변경은 같은 응답·근거를 대조하고 의미 변경은 별도 원문 평가로 확인합니다.
