[검증 기록](HISTORY.md#2026-11-06--통합-이력과-변경-영향의-반복-검증-감축)과 [운영/실측](../platform/HISTORY.md#2026-11-06--통합-이력과-변경-영향의-반복-검증-감축)을 따릅니다.

### 2026-11-05 — 선택 웹 근거와 질문별 출처

[D-099](DECISIONS.md#d-099--질문별-외부-웹-근거-선택과-출처-보존-2026-11-05)의 선택 웹 결과를 질문별 고정 근거와 v4 인용 계약에 연결했습니다. 웹 없는 v3 호환, 실제 보관 문자 인용, 소유권·충돌·동일 요청·실패 보존과 웹 해제/자료 변경 시 세션 분리를 확인했습니다. 검증 범위와 실행 한계는 [HISTORY](HISTORY.md#2026-11-05--선택-웹-근거와-인용-보존-d-099)를 따릅니다. 운영 서버 갱신은 이번 범위에 포함하지 않았습니다.

### 2026-10-29 — 이어지는 질문의 대화 문맥

새 질문 작업은 선택 질문보다 앞선 사용자·AI 턴을 대화 판본과 함께 `personal-question-v3` 고정 입력에 보관합니다. 대화의 지시 대상·후속 질문을 해석하는 문맥으로 사용하고 현재 사실과 인용은 이번 질문의 고정 근거로 확인합니다. 옛 답변을 새 근거나 사람 승인으로 전환하지 않습니다. 이후 대화 추가는 진행 중 입력을 바꾸지 않으며 구 v2 작업의 입력/지문은 유지합니다. 판본 충돌·다른 소유자·입력 변조·호환 검사 3개를 통과했습니다. ### 2026-10-29 — 저장 후 기존 지식 대조

개인 CLI의 `run_comparison`과 인증 HTTP의 `knowledge-comparisons` 경로를 연결했습니다. 저장된 대상 그래프의 표현을 묶어 첫 검색을 수행하고, 같은 AI 대화의 후속 요청에 따라 선택 주장·근거 읽기, 문서 전체 읽기, 재검색을 이어갑니다. 첫 검색·추가 읽기를 포함한 실행별 5회 한도와 동일 제공자/세션의 동시 실행 거부는 서버에서 검사합니다. 새 세션을 대신 만드는 기능은 없습니다.

- 기존 `ConceptStore` 검색·조회, `PersonalStore`의 사용자 소유·CAS·요청 영수증·추가 이력을 재사용합니다. 같은 항목/판본의 중복만 묶고 일치한 표현을 함께 표시하며 미검토·전문가 정책 상태를 보존합니다. 최대 20개 후보와 바이트 한도 때문에 빠진 항목은 `coverage`에 남깁니다.
- 후보·제외 이유·근거 참조·미확인점·미판정 항목·실패를 개인 실행별로 보관하고 목록은 최신순입니다. 원문/판단이 바뀌면 재확인 필요를 표시하며 과거 결과를 갱신하거나 자동 재대조하지 않습니다. 수동 재실행은 새 실행과 새 5회를 사용합니다.
- 문서 전체 읽기는 정확한 원문 판본을 응답에 복원하고 원장에는 그 참조를 보존합니다. 수동 재대조의 `refresh_target=True`는 현재 대상 원문·주장·전문가 판단을 첫 턴에 전달해 이전 세션 기억을 교체합니다. stale 그래프 또는 실행 중 대상 기준 변경은 거부합니다.
- 수동 재대조는 실제 추출에서 확인해 보호한 로컬 세션 기록의 제공자·세션 ID와 서버·사용자·tenant·관점·문서·작업이 일치할 때만 재개합니다. Claude의 원래 작업 폴더도 이 로컬 기록으로 복원합니다. 두 CLI는 `--session-registry`를 공유하고 기본 경로는 `work-dir/ai-session-refs`입니다. 로컬 기록이 없거나 다르면 모델 호출 전에 거부하며, 기록 저장 실패가 이미 저장한 추출을 실패로 바꾸지는 않습니다.
- 서버는 실제 조회 참조만 결과에 사용하도록 검사하며 관련성·동일성의 의미 정확성이나 전문가 승인을 선언하지 않습니다. 이전 자동화의 공통 추출 규약/미독 진단 수정은 이 범위에서 중복하지 않았습니다.

격리 저장·실제 ASGI HTTP와 합성 대화 callback의 16개 검사 및 지식 전체 85개 검사가 통과했습니다. 실제 Codex 기본 모델로 새 합성 원본 등록→추출 저장→동일 세션의 검색·근거 읽기·전체 문서 읽기·재검색→후보 3개/제외 6개 보관을 확인했습니다(조회 4/5회, 추출 포함 모델 5호출). 이는 기술 연결 검증이며 의미 품질·토큰 절감의 입증이 아닙니다. 수동 CLI의 현재 기준 재대조·동일 요청 확인과 [앱 결과/이력·중단·복구](../ui/PLAN.md)의 최종 통합도 격리 자료로 검증했습니다. 운영 자료/규약 발행은 변경하지 않았습니다. [검증 기록](HISTORY.md#2026-10-29--저장-후-기존-지식-대조-계약)

2026-10-28 새 지식 경로·Front Matter·access_revision 계약을 개념/연결/영향·목록·집계에 연결했습니다. 공통 격리 계약 검사 26개가 통과했으며 실제 모델/운영 전체 통합은 실행하지 않았습니다.

## 공개 구현 계약

- catalogue는 저장 담당 `documents.changes.document_fields(store, document, snapshot)`를 사용해 문서 목록과 동일 metadata/document_id/body_revision/authorship 구조를 반환합니다. source_status는 실제 metadata.source 존재 여부로 linked/unlinked이며 제목으로 계보를 추정하지 않습니다. actor와 AI origin을 별도로 표시합니다.
- context/개념 source의 content/revision은 전체파일이고 body/body_start_line/body_revision은 별도 필드입니다. 본문 링크·본문 검색은 Front Matter를 제외하며 인용 줄은 전체파일 기준입니다.
- 검토/대응 발견은 새 _knowledge와 기존 _reviews를 읽고 충돌·skipped·truncated를 유지합니다. 원문 없는 원장의 과거 판단도 발견하지만 현재 유효 지식으로 적용하지 않습니다. 신규 원장의 document_id를 포함한 과거 prefix·body 인용의 영향 복원도 검증합니다.
- 개념 snapshot과 검토함/이력 cursor는 선택 access_revision을 우선하고 과거 actor는 policy_revision으로 호환합니다. 감사용 policy_revision·과거 actor는 유지합니다.
- tenant 이력의 개인 분석 작업은 `JobStore.list_history_ids(tenant,user_id,scope_key,limit,cursor)`로 발견하고 `JobStore.history()`로 전체 이벤트를 읽습니다. 새/옛 개인 저장 경로와 소유 경계를 분석 모듈에서 소비하며 상세 결과의 검증 범위는 D-102로 구분합니다.

## 남은 검증

신규 개인 작업은 실제 생성·입력 준비·Wiki 저장을 수행한 격리 자료와 HTTP/MCP 이력 조회에서 통합 검증했습니다. 운영에서는 기존 계정의 읽기 조회와 서버 반영만 수행했으며 새 분석 쓰기나 설치 앱 교체는 하지 않았습니다. 다른 환경과 설치 GUI의 전체 등록→분석→조회 검증, 자료 확대에 따른 집계·검토 조립 비용은 남아 있습니다.
