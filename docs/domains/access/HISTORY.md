# 인증·워크스페이스 실행 기록

## 2026-11-19 — 요청한 신규 계정의 SDV 플랫폼 배정

- 명시 요청으로 미배정 계정 하나에 `sdv-platform`의 중립 `default`와 `read`를 부여한 뒤, 후속 요청으로 지원 업무 권한 9종까지 확대했다. 관리자·다른 공간 권한은 추가하지 않았다.
- 인증 잠금·정책 revision·원자 게시·재읽기로 대상 소속/기본 공간 외 정책과 인증 필드 보존을 확인했다. 토큰 재발급·서버 재시작·자료 변경은 없었으며 실제 사용자 앱의 배정 재확인은 미실행이었다.

## 2026-11-16~18 — 관리자 콘솔 설계

- 독립 관리자 인증, 사용자/공간 검색·개별 배정·대상 내부 이력·원래 검색/페이지 복귀를 [관리 설계](WORKSPACE_ADMIN_DESIGN.md)로 통합했다. 다중 배정은 사용자별 최신 기준·CAS·영수증을 사용하도록 보완했다.
- 설계 검토에서 일반 이름 로그인 토큰의 관리자 승격, 폴더 소유 증명, 미완료 작업의 중복 재시도·복구 주체 문제를 다뤘다. JSON·링크와 공개 키/가상 자료의 [시안](../../../app/tests/workspace-admin-proposal/DESIGN.md)을 검증했으며 실제 관리자 API·키 발급·저장/동시성 구현 및 운영 배포는 확인하지 않았다.

## 2026-11-17 — 신규 가입의 SDV 자동 소속과 전체 권한 제거

- [D-132](DECISIONS.md#d-132--신규-가입과-관리자-워크스페이스-배정-분리-2026-11-17)를 구현했다. 신규 가입은 무소속이며 계정·보호 토큰과 기존 소속을 유지한다. 과거 `new_tenant: true` 미완료 가입의 확정 전후 복구도 검사했다.
- 인증 30개와 관련 HTTP/분석/지식/MCP를 합쳐 223개 통과. 신규 가입을 실행하지 않아도 재현되는 OpenAPI의 `UnboundLocalError: status_code` 1건은 별도 문제로 분리했다. 당시 관리자 기능·설치/배포는 미실행이었다.

## 2026-11-06 — 서버 내부 색인 계산의 현재 read 범위

내부 색인도 계산 직전 현재 소속·행동·관점을 재검사하도록 기존 인가 로직을 공유했다. 권한 회수403·정책 유실·범위 분리·토큰 비보관을 격리 검증했으며 [색인 기록](../knowledge/HISTORY.md#2026-11-06--python의-기동-전저장-후-온톨로지-색인-준비)을 따른다.

## 2026-10-29 — PoC 앱의 기본 중립 조회 고정

- D-083에 따라 로그인·선택·보호 연결 복원·조회에서 허용된 기본 중립 프로필만 사용하게 했다. 기존 보호 파일은 자동 교체하지 않으며 이전 역할 설정 사용자는 재로그인/재선택이 필요하다.
- 격리 웹 9묶음으로 기본값 변경·권한 거부·비기본 연결 거부·보호 파일 바이트 보존을 확인했다. OS 암호화 자체를 재검증한 결과는 아니다.

## 2026-10-29 — 기존 개인 토큰 서버의 시작 호환

- 요청받은 `data/personal`을 0700으로 만든 뒤, 기존 일반 `.token`만 있고 암호화 키가 없을 때 시작이 거부되는 오류를 재현·수정했다. 링크·특수 파일·암호문·알 수 없는 항목·미완료 가입은 계속 차단하며 토큰 자동 이관/재발급은 추가하지 않았다.
- 인증 28개와 legacy MCP 1개 통과. 실제 Mac에서 새 키0600, 재시작 시 같은 키, 미인증401·기존 토큰 API200·MCP 초기화와 기존 정책/토큰 바이트 보존을 확인했다. 이름 로그인 이관·문서 저장은 미실행이며 외부 전송 한계는 [platform 기록](../platform/HISTORY.md)에 남겼다.

## 2026-10-28 — D-071 이름 가입·로그인과 암호화 영구 토큰

- 이름 가입·로그인, 자료 루트 밖의 토큰 해시/암호문, 잠금·미완료 가입 복구와 `access_revision`을 구현했다.
- 격리 인증 27개로 동시 가입·인원 제한·동일 토큰 재시작·응답 유실·저장 실패·암호문 변조/교환·키 손실·권한 회수·공개 HTTP 경계를 확인했다. 기존 사용자/자료와 Bearer 인증을 보존했다.
- 운영 이관·실제 두 PC·Windows/WSL은 확인하지 않았다. 관리자 변경은 서버 중지 또는 같은 인증 잠금 사용을 전제하며 비협조적인 외부 파일 교체까지 보호하지 않는다.
