## 2026-10-29 — 기존 개인 토큰 서버의 시작 호환

- 사용자가 누락된 `personal` 자료 폴더 생성을 요청해 `data/personal`을 0700으로 만들었고 기존 정책 검사가 통과했습니다. 이어서 기존 일반 `.token` 파일만 있고 암호화 키가 없는 경우 `any(credentials.iterdir())` 조건이 서버 시작을 거부하는 알려진 오류를 실제로 재현했습니다.
- `auth.py`는 키가 없을 때 일반 `.token` 파일만 예외로 허용합니다. lstat으로 링크·FIFO·디렉터리를 거부하고 `.enc`·알 수 없는 파일·미완료 가입 기록과 깨진 pending 링크는 키 생성 전에 거부합니다. 기존 키의 복호화·변조·교체 검사, 잠금과 키 공개 방식은 유지합니다. 기존 토큰 읽기/자동 이관/재발급·정책 변경은 추가하지 않았습니다.
- `poc_access` 28개와 기존 legacy MCP 통합 1개, **총 29개 통과**. 새 검사는 8가지 키 미생성 실패 경계를 확인하고 기존 통합은 정책·토큰 보존, 최초 키 0600, 재시작 시 같은 키와 Bearer 인증을 확인합니다. 독립 읽기 전용 보안 검토에서 추가 문제는 발견되지 않았습니다.
- 실제 런처가 최초 `credential.key`를 0600으로 준비했고 Mac loopback의 무인증 401·기존 토큰 API 200·MCP initialize 성공을 확인했습니다. 기존 정책·토큰 파일의 전후 SHA-256을 내부 비교해 바이트 보존을 확인했으며 새 키도 두 번째 실행에서 유지됐습니다. 비밀 값은 출력하지 않았습니다. 서버·터널은 확인 뒤 종료했으며 외부 주소 DNS 실패/자동 승인 제한 등 전송 검증 한계는 platform HISTORY에 기록했습니다. 기존 사용자의 이름 로그인 이관·실제 문서 저장은 수행하지 않았습니다.
