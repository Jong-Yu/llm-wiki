## 2026-11-24 — 휴지통·복원 0.4.0 통합 반영

## 2026-11-20~22 — 문서당 크기 한도 제거

## 2026-11-06 — 문서·이력 조회 인덱스와 증분 관측

- D-100/101의 파생 SQLite와 변경 원장을 연결했다. 원문·전체 이력·CAS·손상 오류를 유지하고 명시 추적에서도 최초/최대30초 전체 대조를 남겼다. 새 판본·작성 원장 변경·cursor·공간 격리·캐시 실패 복귀 및 HTTP/MCP 쓰기 후 목록 반영·권한 회수를 검증했다.
- 문서500개의 warm 중앙값은11.241→9.633ms였지만 이력59개의 증분 관측은4.820→4.906ms로 시간 이득이 없었다. 이력 fixture는약203KiB이며 초기192KiB 표기를 정정한다. 원장 chain loss·동시 정리 실패의 탐색 차이를 보완했고 [운영 반영](../platform/HISTORY.md#2026-11-06--변경-기록계측과-현재-서버-반영)과 구분한다.

## 2026-11-06 — 이력 목록의 반복 원장 읽기 개선

- 같은 저장 잠금의 작성 원장을 목록 항목에서 재사용했다. 복합 손상 시 오류 순서 회귀를 발견해 첫 이력 읽기 뒤 지연 로드로 고쳤다. 격리168검사와 독립 재현에서 기존 `DocumentMetadataError` 우선·전체 파일 보존을 확인했다.
- 검토 중복 검사 수정까지 합친 실자료 ASGI 측정은 공간 전체 이력11.410→4.278초였다. 단독 효과나 운영 반영 결과가 아니며 [전체 API 점검](../platform/HISTORY.md#2026-11-06--전체-http-api-경계와-조회-성능-점검)을 따른다.
