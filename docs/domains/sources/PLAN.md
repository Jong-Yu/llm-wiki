# 원본 등록·보관 계획

## 현재 상태

원본 보관 API는 UTF-8 MD/TXT·직접 입력과 PDF·XLSX·DOCX·PNG·JPEG(`jpg/jpeg`)·GIF·WebP·BMP·일반 TIFF(`tif/tiff`)를 지원합니다. 바이너리는 multipart 파일로만 받으며 실제 바이트/hash·불변 판본·현재 권한·CAS·영수증을 유지합니다. DOCX는 제한된 OOXML 식별 표식, 이미지는 파일 서명을 확인하고 원본을 변환하거나 재인코딩하지 않습니다. 한도는 원본20MiB·요청24MiB이며 서버 OCR/전체 이미지 디코딩·변환 정확도 검증은 수행하지 않습니다.

개인 PC가 보고한 변환 본문과 미독 구간은 원본 판본에 별도 연결합니다. DOCX의 `docx_text`와 문단/본문 블록/표·행·열 위치, 이미지의 `ocr`와 프레임/페이지 위치를 기존 변환 보고 모델에 추가했습니다. 보고된 위치·문자의 원본 전체 포함 여부와 의미 정확도는 미검증 상태로 유지합니다. 실제 검증과 공통 목록/분석 연결 상태는 [작업 기록](HISTORY.md#2026-10-25--docx이미지-원본-보관-확장)에 둡니다.

로컬 OCR은 EXIF/PDF 회전 처리 이력, 제한된 방향·문장 분할 후보 비교와 신뢰도 경고를 보존합니다. PDF는 기존 픽셀 상한 안에서 300 dpi를 목표로 읽으며 낮은 신뢰도 텍스트도 미독 범위와 함께 보존합니다. 회전·한글 생성 표본은 개선됐지만 공개 문서의 일부 구간 악화·목차/2단 읽기 순서·한국어/영문 오인식이 남았습니다. 정확도나 원본 전체 포함으로 승격하지 않으며 [비교 보고](../../../evals/ocr_rotation_korean_20261026/REPORT.md)와 [실행 기록](HISTORY.md#2026-10-26--ocr-회전한국어-품질-보완)을 따릅니다.

Electron에서 실제 원본 등록 POST·본인 영수증 GET·완료 뒤 목록/미리보기까지 연결했습니다. 서버 저장/권한/불변 판본 계약은 변경하지 않고 현재 source_write·전송/응답 hash·완료/조정 대기/응답 유실을 확인합니다. 이번 실제 HTTP 쓰기 통합 검증은 [ui HISTORY](../ui/HISTORY.md)의 원본 등록 항목이 관리합니다.

R1 원본 등록·새 불변 판본·원본/통합 목록·다운로드·본인 요청 확인이 구현됐습니다. 최초 UTF-8 md/txt 파일·직접 입력 범위에서 원본 API15검사가 통과했고 이후 바이너리 확장은 위 기록을 따릅니다. 상세/파일 GET은 허용 profile query를 지원합니다. 이전 전체 검증 기록은 아래 근거에 보존하며 화면 미리보기의 현재 범위/검증은 [ui PLAN](../ui/PLAN.md)이 관리합니다.
