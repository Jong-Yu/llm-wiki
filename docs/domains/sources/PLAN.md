# 원본 등록·보관 계획

## 현재 상태

### 원본 보관과 배포 범위

- 개발본의 내용 확인 화면은 이미지와 DOCX/XLSX/PPTX를 편집 내용 옆에 로컬 렌더한다. Office는 기존 LibreOffice가 필요하며 구형 PPT는 격리 지원 여부에 따라 원본 열기를 제공한다. 문자 변환 결과와 화면용 사본을 구별한다. [렌더 검증](HISTORY.md#2026-11-25--보호된-원본-사본의-office이미지-렌더).

- 원본 등록·불변 판본·목록·다운로드·요청 영수증과 개별 휴지통/복원을 제공합니다. UTF-8 MD/TXT·직접 입력, PDF·XLSX·DOCX·PPTX·PPT·PNG·JPEG·GIF·WebP·BMP·일반 TIFF를 지원합니다. 바이너리는 multipart로 받고 원본 20MiB·요청 24MiB 한도, 실제 바이트/hash·현재 권한·CAS를 검사합니다. 서버에서 OCR·변환 정확도 검증은 하지 않습니다.
- PPT 등록·개인 변환, 전체 30분/무진행 120초 감독과 원본 휴지통은 0.4.0에, Windows checkpoint 읽기 재시도는 0.4.1에 반영했습니다. [D-148](DECISIONS.md#d-148--pptxppt-원본-보관과-개인-변환-2026-11-23) · [변환 감독 기록](HISTORY.md#2026-11-23--ppt-등록과-변환-감독-보완) · [Windows 수정 기록](HISTORY.md#2026-11-24--windows-checkpoint-읽기의-errno-재시도-누락-수정).
- 고정 원본 판본·hash·권한을 확인한 PDF 페이지 PNG와 서버 공유 승인 흐름은 **0.5.0**에 반영했습니다. PDFium은 별도 프로세스로 렌더링하며 원본·보고를 수정하거나 OCR하지 않습니다. 첫 승인 대상은 PDF `page` 경고이고 이미지 `frame` 경고는 기존 부분 복구를 유지합니다. [페이지 미리보기 기록](HISTORY.md#2026-11-24--고정-원본의-pdf-페이지-미리보기) · [배포 상태](../platform/PLAN.md).

### 문자·도식 변환

**VOC 수정은 운영 서버와 Windows 포터블0.6.5에 반영했습니다.** 슬라이드 경고를 전체 입력으로 연결하던 등록 경로를 고치고, 개인 AI로 저신뢰 그림만 복구하는 명시 실행을 연결했습니다. 실제121·122·124·128·136쪽의6그림을 제품 경로로 전사해 원본과 대조했고 내용 오인식·누락은 발견되지 않았습니다. 정상그림14구간·나머지165단위와 원본·보고를 보존한 격리 등록→Wiki→온톨로지 입력도 확인했습니다. 표/목차 형식 차이와 Windows 실기·실제 사용자 전체 등록 확인은 남습니다. [D-170·실원본 검증](HISTORY.md#2026-11-26--저신뢰-pptx-그림-문자-복구와-실제-voc-검증d-170) · [배포 검증](../platform/HISTORY.md#2026-11-26--ppt-그림-문자-복구-065-배포).

이번 PPT 레이아웃·도식·OCR 보완과 AI 해석 후보 쪽 그림 전달은 [Windows 포터블 0.6.4](https://github.com/Jong-Yu/llm-wiki-releases/releases/tag/app-0.6.4-portable)에 반영했습니다. Windows 실제 변환·LibreOffice 글꼴과 Codex 실제 그림 첨부 확인은 남아 있습니다.

- **VOC 원본 재현·수정:** 보관된 동일 PPTX 170장을 배포 코드와 개발 코드로 다시 변환했습니다. 기존 D-167 보완에 더해 49쪽의 숫자 직선 사용자 정의 경로 7개를 보존하고, 그림 OCR의 세로 조각 판독과 정렬 공백 때문에 재인식이 빠지던 경로를 수정했습니다. 구조 미변환 오류는 없으며 OCR 저신뢰5쪽은 그대로 검토 대상으로 남습니다. [실원본·회귀 검증](HISTORY.md#2026-11-26--voc-원본의-변환-오류-재현과-직선-도형ocr-수정).

- **파일 교체·부분 저장 재개:** 파일 문제는 같은 원본의 새 불변 판본을 CAS로 등록하고 이전 파일·Wiki·보고를 보존합니다. 큰 변환은 전체20MiB·10,000단위 안에서 기존 크기의 부분 보고와 최종 manifest로 전송합니다. 중간 저장이 멈추면 같은 요청의 보관 보고로 남은 저장만 재개하며 다시 OCR하지 않습니다. AI8MiB 입력을 넘는 의미 분할·온톨로지 합성은 별도 미구현입니다. [D-163](DECISIONS.md#d-163--변환-보고의-불변-부분-전송과-같은-요청의-저장-재개-2026-11-25) · [격리 검증](HISTORY.md#2026-11-25--파일-교체와-큰-변환-보고의-보존저장-재개).

- **보류 쪽 보정:** 선택 PDF 쪽만 개인 PC에서 다시 OCR하거나 직접 수정한 문자를 별도 불변 보정으로 저장합니다. 원본·원보고·최신 보고 포인터·미독/경고를 유지하고 선택 쪽 후보를 새 전체 보고로 제출하지 않습니다. 승인한 보정은 분석 최초 입력에 고정합니다. [D-156](DECISIONS.md#d-156--보류-쪽의-재인식과-불변-문자-보정-2026-11-24) · [검증](HISTORY.md#2026-11-24--보류-쪽-재인식과-문자-보정-연결).
- **D-158 내용 선택 확장(0.6.4 코드 포함·Windows 실기 미검증):** 명시 누락 페이지 입력·실제 빈 페이지 확인·정상 페이지/비PDF 단위 수정·전체 문서 입력을 원보고와 분리 보관합니다. 고정 선택 참조와 별도 해소 근거를 등록에 반영하며 파일/실행 오류는 재시도·교체를 기본 복구로 유지하되, 확인된 원본과 실패 보고에 사용자가 전체 내용을 명시 대체할 수 있습니다. 단순 사용 확인·일부 페이지 입력으로 오류를 해소하거나 저장 미확정·접근 거부·원본 변경을 우회하지 않습니다. 큰 응답은 요약과 판본 고정 문자 조각으로 읽습니다. [검증](HISTORY.md#2026-11-25--문서-등록의-직접-입력과-불변-내용-선택).
- **문자 보존:** PDF 정상 내장 문자는 유지하고 그림 영역만 OCR해 위치·출처와 함께 덧붙입니다. 비었거나 깨진 내장 문자와 위치 판독 실패는 전체 쪽 OCR로 처리합니다. PPT 그림도 별도로 읽고 미지원·실패·낮은 신뢰도를 숨기지 않습니다. 한국어가 영문 조각으로 읽힌 일부 단어는 같은 위치를 한국어 모델로 다시 읽습니다. [D-159](DECISIONS.md#d-159--그림-영역만-ocr해-내장-문자-뒤에-덧붙이기-2026-11-24) · [D-161](DECISIONS.md#d-161--영문-조각으로-읽힌-한국어-단어만-다시-읽기-2026-11-24).
- **도식 관계:** PPT의 연결 참조와 PDF의 선·상자 위치를 이용해 연결/포함 문장을 덧붙이고 명시 구조와 위치 추정을 구분합니다. 기준을 넘는 미확정 끝점·이름 없는 상자는 AI 해석 후보 경고로 남깁니다. PPT 도형·그룹·SmartArt의 명시 문자·구조도 보존합니다. [D-155](DECISIONS.md#d-155--ppt-도식의-명시-구조와-smartart-문자-보존-2026-11-24) · [D-160](DECISIONS.md#d-160--도식-관계를-a--b-문장으로-덧붙이기-2026-11-24).

## 현재 저장·변환 계약

- 최초 변환 전송·저장 재개·부분 분할은 같은 클라이언트 예산 판단을 사용하며 기존 보고와 서버 검증을 유지합니다. [검증](HISTORY.md#2026-11-25--변환-전송-정책-공통화).
- 원본과 개인 자료는 [D-073](DECISIONS.md#d-073--원본-판본-보관과-관련-저장-폴더-통합-2026-10-28)의 새 경로와 구형 경로를 호환합니다. 조회만으로 이관하지 않고 중복 위치·손상·경쟁에서는 중단해 기존 자료를 보존합니다. 직접 경로 대신 `SourceStore._version_path()`·`_catalog_path()`·`_request_path()`와 공통 `storage_layout`을 사용합니다.
- 같은 사용자의 원본/분석 request ID 충돌, tenant 요청 수와 미완료 카탈로그를 포함한 판본 수 한도, 실제 actor·접근 기준·원본 판본/hash·영수증을 유지합니다. 상세·파일 GET의 profile은 저장소 접근 전에 검사합니다.
- 변환은 개인 PC에서 수행하고 본문·위치·미독·경고를 원본 판본에 별도 연결합니다. 읽힌 문자 보존과 정확도/전체 포함 검증을 구분합니다. 원본 바이트를 재인코딩하거나 경고를 지워 완료로 만들지 않습니다.
- Pandoc은 사용하지 않습니다. DOCX는 `python-docx`로 문단·표 셀을 읽고, XLSX는 원본 구조와 `openpyxl`의 값·수식·캐시·좌표를 보존합니다. 각주·주석·머리말·변경 추적·중첩 표 등 미지원 범위와 병합 셀 한계를 표시합니다. 과거 Pandoc 보고는 그대로 읽으며 수식 재계산·Office 화면 재현은 하지 않습니다. [D-095](../platform/DECISIONS.md#d-095--pandoc-사용-중단과-문서-변환의-대체-2026-11-03).

## 남은 작업

- 0.6.4에 반영한 AI 해석 후보 쪽 그림 전달(D-169)의 Codex 실제 그림 첨부, Windows 실행·LibreOffice 글꼴 확인이 남았습니다. LibreOffice가 없는 PC에서는 PPT 후보에 그림이 붙지 않습니다.
- 정답 초안의 사용자 확인, 실제 스캔 문서·Windows 확인이 필요합니다.
- 한 단 읽기(psm 4)는 두 단 순서 혼합 위험 때문에 채택하지 않았습니다. 슬라이드 스캔에 제한해 적용할지는 미결정입니다.
- 보정 API와 개인 변환기·앱 코드는 호환 서버·0.6.4 포터블에 포함했으며 실제 개인 PC의 전체 처리 확인이 남습니다. 등록의 새 제품 흐름·화면 통합은 [UI 계획](../ui/PLAN.md), 승인 입력·추출은 [analysis 계획](../analysis/PLAN.md)을 따릅니다.

## 완료 조건과 근거

불변 원본·판본·영수증·권한·용량·동시성·실패 보존을 유지하고, 문자 정확성과 도식 관계를 별도로 확인합니다. 오류·응답 유실·취소에도 기존 원본/보고와 확인된 변환 단위를 보존해야 합니다. 격리·합성·재작성 PPTX·실제 원본·Windows 검증을 구분하며 새 규칙의 개발 완료를 배포 완료로 표시하지 않습니다.
