# 온톨로지·의미 평가 계획

## 현재 상태

원문/revision에 근거한 온톨로지 생성·조회·갱신, v2/v3 기본 및 명시적 v4 앵커·v5 관계/대응·v6 출처 보완 구현/검증 기록이 있습니다. RFC9111의 규범 관계 손실과 새 RFC9110 §9.2.1의 원인/조건·지시 범위 오류를 개발 근거로 공통 추출 지침을 총2회 수정·고정했습니다. 규범 문장은 기존 텍스트 속성으로 보존하고, 원인 사건과 발생 조건의 행위자·좁은 예시와 넓은 범주를 구분합니다. 제출 스키마·어휘·검증 지문과 운영 허용/기본 규약은 변경하지 않았습니다.

명시 승인 후 새 공개 원문으로 실제 모델4회를 실행했습니다. 생성 개체29·관계18·속성10의 구조/인용은 통과했고, 원시 의미 판정은4개 규칙 pass·6개 fail입니다. 인용 위치가 발췌문 내부 줄 대신 원본 전체 줄을 사용해 보고 검증은 실패했습니다. R-S06의 태그 문자열 원문 출현 요구는 D-024의 정규화 분류 계약과 불일치하며 원시 점수는 고치지 않았습니다. [개발 평가 보고](../../../evals/rfc9110_safe_20261026/REPORT.md)에 원시 입력·출력·한계를 보존했습니다. 이번2회째 지침 교정의 최종 정확도는 새 원문 평가 전까지 미검증입니다.

## 다음 요청에서 확인할 범위

검사·질문 인용 계약 보완과 공통 Python 회귀는 각 소유자 인계에 따라 진행합니다. 새 독립 평가는 고정 프롬프트·변경 없는 중립 스키마로 새 원문·새 세션에서 수행하며, 승인 대기와 실제 실행 여부를 구분해 기록합니다. 실제 사람 검토와 UI 전체 동선은 이번 의미 평가의 완료 범위에 포함하지 않습니다. 옛 고정 fixture·반복 일치·형식 통과를 독립 정확성 증거로 확대하지 않습니다. 운영 규약 발행·허용·기본값 전환은 별도 절차입니다.

## 완료 조건

변경한 스키마의 호환·재추출·원문/인용·한정어·후보·CAS를 확인하고, 의미 평가는 구조 검증과 분리합니다. 원문 분리 평가는 EVALUATION의 입력 제한을 따릅니다.
