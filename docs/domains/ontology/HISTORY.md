# 온톨로지·의미 평가 이력

## 2026-10-26 — 실제 RFC 원문·로그인 Codex 분리 평가

- [평가 보고와 고정 산출물](../../../evals/rfc9111_stale_20261026/REPORT.md): RFC 9111 4.2.4의 연속 원문 836바이트, 새 격리 tenant/규약, 실제 HTTP/MCP 등록·추출·별도 검사·질문을 실행했다. 합성 모델을 사용하지 않았고 운영 위키·히스토리는 변경하지 않았다.
- `fork_turns=none`에도 AGENTS가 자동 주입된 두 하위 세션을 제외하고, 프로젝트 문서·도구·메모리를 차단한 새 ephemeral CLI에서 선행 검증 기준·생성·판정을 분리했다. 성공 모델 응답 6회이며 실제 모델 ID·토큰 수는 CLI 기록에 없어 미확인이다.
- 실제 API가 진단 union 스키마를 거부한 첫 실패와 재현을 보존했다. 평가 전용 CLI 스키마 사본의 중복 타입 제거로 추출을 진행했고 `fastapi_8`이 공통 제품에 수정했다. 수정된 제품의 투영이 필수 키 배열 순서 외에는 실제 실행 스키마와 같은 계약임을 대조한 뒤 임시 평가 우회를 제거했다. 수정 후 모델 재호출·의미 프롬프트나 원시 출력 수정은 하지 않았다.
- 제품 구조·인용·CAS·전체 이력 등 10개 검증 통과. 검증 스크립트가 이력 디렉터리를 파일로 세었던 초기 실패는 필터 수정 후 통과했다. 독립 의미 판정은 개체 4개/속성 1개 지지, 관계 4개 중 지지 2·조건/규범 의미 손실 2다. 인용 문자열 보존을 완전한 구조화로 계산하지 않았다.
- 별도 검사 모델 응답은 완료됐으나 `not_run`과 `schema_limit`의 계약 위반으로 10규칙 모두 error 보고가 저장됐다. 질문의 핵심 판단 11개는 지지됐으나 원본 식별자 인용 3개를 발명해 서버가 저장을 거부했다. 실패·미저장 초안·모델 간 이견을 보존하고 각 소유자에게 인계했다.
- 미실행/한계: AI 위키 재작성, OCR, 실제 사람 승인, Electron 전체 동선, 운영 배포, 전체 RFC·다분야 일반화. 입력 분리는 OS 격리가 아니며 모델 상관 오류가 남는다. 후속 UI 통합은 `ui_11`, 프롬프트 개선 뒤 독립 최종 검증에는 새 원문이 필요하다.

## 2026-10-26 — 조건·규범 의미 보존 지침 보완 (mcp_5)

- RFC9111 4.2.4의 공개 REPORT·고정 원문·원시 제출을 개발 자료로 사용했다. 두 `MUST NOT` 관계가 `negative/asserted participates_in`으로 저장 가능한 점을 현행 `_graph`로 재현했다. 구조 검증 통과가 금지 규범과 실제 비참여를 구분한다는 뜻은 아니며, 이전 원시 제출·판정·발행 규약을 수정하지 않았다.
- `.agent/ontology_semantics.md`를 한 번 수정해 의무·금지·권고·허용과 발생 사실을 구분하고, 완전한 규범 문장을 기존 텍스트 속성에 보존하도록 했다. 조건 분기의 if/only if/unless·AND/OR, 공동 적용과 개별 예외, 원문 주장 주체를 유지한다. `content.py`의 v3 합성 예시는 실제 사용 관계와 별도 금지 문장을 함께 보존한다. 관계를 전부 없애거나 근거 없는 다른 술어로 치환하는 방식은 사용하지 않는다.
- `.venv/bin/python -B -m unittest core.tests.modules.test_extraction_rules -v`: 최종 10개 통과. v3–v6의 규범 텍스트·조건·출처 왕복, 독립 if/unless/OR 분기, 기존 사실 관계 유지, 지원하지 않는 양태·위조 인용·속성명·조건·500자 초과 거부, 발행 불변성과 이전 기본 정책 보존을 확인했다. 신규 시험의 첫 실행은 격리 tenant 폴더 준비 누락으로 실패했으며 fixture 수정 후 통과했다.
- 프롬프트 SHA256 `54468c58ba889e0f6d7763b3ecd8cfbaecdfb67bd8c5610cbe2fc3bc38180bd8`, 중립 제출 스키마 SHA256 `4464d7be9653d640f1c96bc5581f650801734ed2d300bb411890c7140f0fed24`를 고정해 `mcp_6`에 인계했다. 제출 스키마·definitions·검증 지문은 변경 전과 동일하며 이전 RFC의 불변 규약을 read-only로 읽는 호환 검사도 통과했다. 운영 규약·권한·위키·히스토리는 변경하지 않았다.
- 한계/미실행: 텍스트 보존은 의무·금지 전용 양태나 실행 가능한 논리 결합·예외 우선순위의 완전한 구조화가 아니다. value 500자/evidence 1000자 한도를 유지하며 부족한 표현은 진단으로 남긴다. 이 세션의 실제 모델 호출은 0회이고, `mcp_6`는 비공개 제품 지침·스키마·파생 자료의 외부 전송 승인 대기로 실제 의미 평가를 `not_run`으로 보고했다. 이를 대신 실행하거나 실제 의미 개선·사람 승인·운영/다른 OS 검증으로 확대하지 않았다. 공통 Python 회귀는 `fastapi_9`, UI 통합은 기존 `ui_11` 소유다.

## 2026-10-26 — 실제 RFC9110 평가와 원인·조건 지침 교정

- 사용자가 명시 승인한 기존 ChatGPT 로그인 CLI로 원문 우선 감사·생성·질문·최종 판정4회를 수행했습니다. 자동 재시도·API 키 전환·구매 없이 원시 입력/출력/hash를 보존했습니다. 개체29·관계18·속성10의 구조/인용은 통과했으나 원시 판정은4pass/6fail이며, 발췌문48줄에 원본 전체의3800번대 줄을 사용해 보고 검증이 실패했습니다. [개발 보고서](../../../evals/rfc9110_safe_20261026/REPORT.md)를 따릅니다.
- 관계17의 불이행→부작용 원인을 조건절 자동 과정으로 바꾸고 좁은 과정과 넓은 범주를 합친 오류를 원문과 대조했습니다. 원인/결과/발생 조건 분리와 ID 재사용 전 범위 확인을 역할 프롬프트에 최소 추가했습니다. 이번은 교정2/2회이며 지문은 `885a04149a9a443c3f4762bdf6d5db022e3340e676091c532d2ef68ce0e82737`입니다. content.py는 파일을 직접 읽어 별도 본문 동기화가 필요 없었습니다.
- R-S06의 태그 문자열 원문 출현 요구는 D-024의 정규화 분류 계약과 불일치합니다. 원시 fail을 pass로 고치지 않고 기준 이견으로 보존했습니다. 해당 개발 원문과 새 원문 최종 평가를 구분합니다.
- 역할 TOML2개 파싱·필수 필드, 원시 생성/판정 hash 보존, 기존 extraction_rules10검사(1.470초) 통과. 이 지침 수정 뒤 실제 의미 정확도는 새 원문 평가 전까지 미검증이며 운영 발행/기본 규약·자료·권한은 변경하지 않았습니다.
