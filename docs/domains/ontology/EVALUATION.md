# 원문 분리 평가

아래 입력 제한은 일반적인 시작 문서 읽기와 협업보다 우선합니다. 주 에이전트만 이 문서를 확인하고 두 분리 세션에는 필요한 규칙과 허용 입력만 전달합니다.


- 원문 분리 평가(blind source audit)는 수집·관계 생성 세션과 원본을 보유한 검증 세션을 각각 `fork_turns=none`인 새 세션으로 시작합니다. 주 에이전트는 필요한 작업 규칙, 허용 입력·출력 경로와 담당만 전달합니다. 두 세션은 일반 시작 절차의 `AGENTS.md`·계획·결정 기록·스킬·기존 `evals/`·다른 역할 파일 읽기를 건너뛰고 허용 입력만 읽습니다. 이전 대화가 들어오거나 금지 자료를 읽었다면 노출을 보고하고 새 세션으로 다시 시작합니다.
- 검증자는 생성 결과를 보기 전에 실제 원문의 연속 구절, 출처, 선택 범위와 SHA-256을 확보합니다. 중요 사실·조건·누락 확인 질문을 별도 비공개 검증 파일에 먼저 고정합니다. 재서술·합성 문장을 실제 원문으로 대신하지 않습니다. 여기서 비공개는 생성자에게 경로·내용을 전달하지 않는다는 뜻입니다.
- 수집·추출 세션에는 고정한 원문, 추출 스키마와 프롬프트만 작업 입력으로 줍니다. 검증 노트·기대 정답·옛 점수·이전 대화는 전달하지 않습니다. 원문에 없는 사실을 보충하지 않고 결과 파일과 사용 프롬프트의 SHA-256을 각각 고정한 뒤 제출합니다.
- 검증자는 고정된 원문·제출 그래프·중립 스키마만 평가 입력으로 받아 앞서 고정한 질문과 대조합니다. 추출 프롬프트·기대 정답·이전 점수·생성자의 해설은 보지 않습니다. 프롬프트 hash와 실행 기록은 주 에이전트가 별도로 보존합니다.
- 검증용 그래프는 원시 제출의 문서·원문 hash·`entities`·`relations` 값을 그대로 유지하고 `omissions`와 생성자 해설만 제외합니다. 원시 제출과 검증용 그래프의 SHA-256을 각각 기록하며, 제외한 설명은 판정 확정 뒤 결과 기록에 함께 보존합니다.
- v2 후보도 검증자에게 별도로 전달하되 주장·인용·한정어를 그대로 유지하고 `reason/question`은 가립니다. 검증자는 후보의 근거·불확실성 분류를 관계 의미·핵심 내용 보존과 따로 판단합니다. 후보를 낸 것만으로 미표현 사실을 정답 처리하지 않습니다. 원래 이유·질문은 판정 확정 뒤 함께 보존합니다.
- v3의 검증용 그래프는 `context/identifiers/provenance/attributes`와 그 인용·한정어도 원시 제출 그대로 유지합니다. 속성 주장 판정과 관계 판정, 후보 검토와 핵심 질문의 보존을 별도로 집계합니다.
- 판정은 원문 근거에 따라 지지됨·모순·근거 없음·조건 손실·모호함과 중요한 누락을 구분합니다. 현재 스키마로 표현할 수 없는 의미는 한계로 남기고 다른 관계로 강제 변환하지 않습니다. 구조·인용 검사는 의미 판정과 별도로 보고합니다.
- 생성 결과와 검증 결과가 모두 확정되기 전에는 두 세션 사이의 중간 질문, 답 맞추기, 프롬프트 편집 담당과의 협업을 하지 않습니다. 입력 누락이나 실행 문제는 부모에게만 알립니다. 확정 뒤 일반 협업을 재개하며 주 에이전트는 이견·불확실성을 임의 정답으로 조정하지 않고 그대로 보고합니다.
- 공유 파일 환경의 입력·전달 제한이며 운영체제 권한 격리는 아닙니다. 같은 모델을 쓰는 두 세션에는 상관된 오류가 남을 수 있으므로 독립적인 외부 심사로 과장하지 않습니다.
- 평가 발견을 프롬프트 개선에 사용하면 해당 문서는 개발 자료로 전환합니다. 최종 평가는 새 원문과 새 세션으로 수행합니다. 기존 18개 재서술·합성 자료는 고정 fixture 회귀이며 독립적인 실문서 정확성의 증거로 사용하지 않습니다.

## 추출 변경의 검증

- 온톨로지·추출 프롬프트를 변경하면 구조·인용 검증과 의미 검증을 분리합니다. 기존 재서술·합성 자료 (정리로 삭제된 참고 자료)는 고정 사례 회귀이며 실제 원문 이해의 독립 검증을 대신하지 않습니다. 개발 사례로 프롬프트를 개선할 때는 최대 두 번으로 제한하고 남은 문제를 보고합니다.
- v2 변경은 v1 읽기 호환·재추출 표시, 한정어 보존·범위 검사, 검토 후보 분리·위조 승인 거부, 원문 변경 후 관계와 후보의 stale 처리, 기존 버저닝·CAS·실패 보존을 확인합니다. 모델이 채운 모호한 후보와 가상 답은 실제 사용자 승인으로 기록하지 않습니다. 후보의 검토 적절성과 근거 관계의 의미 보존도 따로 평가합니다. v1의 정답표로 v2 의미를 채점하지 않습니다.
