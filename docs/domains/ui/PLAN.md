## 문서 등록 목표와 개발 반영

개발본은 VOC의 PPT 변환 진단을 원인별 한국어 안내로 표시합니다. 그림·도식의 내용 누락만 있는 부분 변환은 `변환 내용 확인 필요`와 기존 내용 확인 경로를 우선하며, 실제 실행 오류·원인 미확인·저장 미확정은 구별합니다. 운영 앱 반영과 Windows 실기는 남아 있습니다. [검증 기록](HISTORY.md#2026-11-26--voc의-ppt-변환-진단과-내용-확인-안내).

0.6.1은 업로드 후 작업 ID가 확인되면 해당 문서의 진행 상태 화면으로 바로 이동합니다. 파일 업로드의 제목·저장 이름은 선택한 파일명에서 자동 결정하며, 제목 입력은 텍스트 붙여넣기에만 제공합니다. [진입 수정 기록](HISTORY.md#2026-11-26--업로드-후-진행-상태로-직접-이동).

**D-158의 문서 목록·진행 상세와 직접 입력·수정·빈 페이지 확인·파일 교체·보호 초안 복원을 개발 코드에 연결했습니다. 0.6.0 앱·서버에 반영했으며 실제 개인 AI/두 PC 검증은 남아 있습니다.** 문서 올리기 → 문자 변환 → Wiki 저장 → 온톨로지 구성까지 한 작업으로 완료합니다. 원본 업로드나 Wiki 저장만을 등록 완료로 표시하지 않습니다. 내부 권한·보존 계약을 임의 변경하지 않습니다.

- 문자가 필요한데 변환문을 얻지 못하면 직접 입력하고, 낮은 신뢰도는 현재 내용을 확인·수정해 진행합니다. 파일 문제·환경 문제·중단·처리 한도·저장 미확인은 각각 해결 행동을 제시하며 완료한 단계를 반복하지 않습니다. 실제 빈 페이지와 정보가 있는 그림·도표를 구별합니다.
- 같은 문서 화면에서 미완료 단계부터 이어갑니다. 별도 승인·PC 선택·알림 경유를 요구하지 않고 주요 상태·문자·입력·행동을 접기/펼치기에 숨기지 않습니다.
- 실제 서비스의 AppShell·브랜드·토큰·공통 컨트롤을 재사용합니다. 원본과 `등록할 내용`을 넓게 대조하며 PDF 위치는 ‘페이지’로 표시합니다. 좁은 화면도 상하 대조를 유지하고 한쪽을 탭 뒤로 숨기지 않습니다.
- 주 행동은 수정 전후 모두 `이 내용으로 등록 계속`이며 모든 페이지의 현재 내용과 수정 사항을 반영함을 가까이 표시합니다. 등록 작업면에는 온톨로지 결과·그래프·결과 탭을 복제하지 않습니다. 문자 변환·Wiki 생성·온톨로지의 **진행 상태는 각각 표시**하며 완료된 단계와 미완료·중단 단계를 구별합니다.
- 이미지·DOCX/XLSX/PPTX도 원본과 입력을 동시에 대조합니다. 위치 변경과 오류에서 영역 크기를 유지하고 이전 이미지를 즉시 숨깁니다. [원본 대조 검증](HISTORY.md#2026-11-25--이미지office-원본과-등록-내용의-동시-대조).
- 대량 목록·필터·번호 이동은 한곳의 페이지 탐색에 모읍니다. 사용자 검토 화면은1280×900 데스크톱 기준으로 제시하며 반응형 검증과 구별합니다.

확정된 UI 목표는 **등록용 작업 화면을 문서에 통합**하는 것입니다. 문서 행은 문서명·현재 상태 하나·행동의3열로 표시합니다. 상태를 누르면 별도의 진행 상세 페이지로 이동해 문자 변환·Wiki 생성·온톨로지의 상태를 각각 확인합니다. 목록을 줄이거나 위에 겹쳐 가리는 패널은 사용하지 않습니다. 조회는 실행하지 않으며 목록 복귀 시 검색·필터·스크롤과 시작 버튼 초점을 복원합니다. 파일 교체·중단 재개는 행이나 선택한 상세에서 처리하고, 내용 확인·입력이 필요할 때 넓은 대조 작업면을 엽니다. 재개할 단계를 행동명에 표시합니다. 진행 상세는 세 단계와 현재 작업을 구분하며, 총량을 아는 문자 변환에만 처리 수·비율·막대를 표시합니다. Wiki·온톨로지는 실행 상태와 저장 확인으로 표현하며 단계 수를 전체 완료율로 환산하지 않습니다. 등록 목록의 별도 로그인 UI는 제거하며 AI 연결 관리는 기존 설정을 사용합니다. 안전하게 나눌 수 있는 큰 문서 처리와 저장 결과 조회는 자동으로 진행합니다. 저장된 본문은 사용자가 선택해 읽으며 빈 문제 화면을 채우려고 강제로 펼치지 않습니다. 페이지 선택 창은 번호·범위만 제공하고 버튼 목록을 두지 않습니다. 작업 메뉴에 함께 묶인 AI 질문·관련 지식 찾기·관계 재추출의 실행 기록과 재개, 기존 딥링크는 보존하며 AI 채팅/관련 문서에서의 접근을 연결하는 안입니다. 문서 목록·독립 진행 상세·내용 확인·기존 실행 기록 연결은 개발 코드에 반영했습니다. 파일 교체·누락 내용 입력·번호/범위 탐색·종료 후 초안 복원을 연결했습니다. 큰 변환 결과의 보관·전송 분할과 AI 의미 분석 분할은 구별합니다.

최신 시안 소스는 `.local/diagnostics/2026-11-24-registration-redesign/content-focused/`, 최신 진행 표시 시안과 검증은 그 아래 `progress-visual-20261125/`에 있습니다. 전체 흐름과 이전 단계 표시 검증은 `complete-journey-20261125/`·`stage-visibility-20261125/`에 보존했습니다. 실제 `DocumentLibrary`의 표·행 SCSS와 원본/편집 대조를 유지하며 등록 시작부터 정상·내용 보완·실패 복구·완료 읽기, 알림·실행 기록·재열기를 연결했습니다. 합성 자료에서 여러 등록과 초안을 각각 유지하며 저장된 본문은 관계 구성 중에도 읽을 수 있습니다. 최신 검토에는 변경된 데스크톱 화면만 제시하며 앞선 전체20장과 검증은 보존했습니다. **사용자가 최신 진행 시안을 승인한 뒤 실제 목록·검색 계보 묶음, 단계/수량 표시, 기존 보호 복원·재개 및 실행 기록 연결을 개발 코드에 반영했습니다.** 시안은 합성 자료의 설계 근거로 보존하며 실제 구현 검증과 구별합니다. 종료 후 편집 초안 복원과 전체 누락 내용 입력은 개발본에서 검증했습니다. 실제 다중 등록 스케줄링은 남아 있으며, 큰 입력의 구간 분석 상태는 [analysis PLAN](../analysis/PLAN.md)을 따릅니다.

## 현재 구현과 배포

Windows 포터블0.6.3에 사이드바 하단의 `/report` 오류 보고 화면을 추가했습니다. 오류 내용 입력 하나와 보고 버튼을 제공하고, 저장 확인 시 완료를 알리며 실패 시 입력을 보존합니다. 목록·피드백 화면은 없습니다. [검증 기록](HISTORY.md#2026-11-26--텍스트만-전송하는-오류-보고-화면). Windows 포터블0.6.3에 반영했습니다.

개발본에서 휴지통은 사이드바 하단에서 `/documents/trash` 독립 화면으로 열며 삭제 성공 문구와 내용 확인 상세의 중복 복귀 링크를 제거했습니다. 알림은 개인 목록 삭제·분리된 건수 필터·읽음과 내용 검토의 의미 안내를 제공합니다([D-166](../platform/DECISIONS.md#d-166--개인-알림-목록에서-삭제와-원천-이력-보존-2026-11-26)). Windows 포터블0.6.2와 호환 서버는 반영했고 Mac 설치본 교체는 남아 있습니다. [작업 기록](HISTORY.md#2026-11-26--휴지통-독립-화면과-알림-정리).

등록 편집·보호 초안·고정 제출의 상태 전이는 workflow hook이 소유하고 UI는 폼·탐색을 맡습니다. [품질 개선 검증](HISTORY.md#2026-11-25--등록-상태-소유권-정리).

### 공유 기록과 실행 보호 경계

서버 계약의 보존·경쟁 보호를 유지합니다. 개발본의 단일 내용 제출이 내부 순서를 조정하며 별도 사용자 승인·PC 선택 화면을 요구하지 않습니다. 서버 계약은 [D-154](../platform/DECISIONS.md#d-154--서버-알림-이력과-공유-문자-사용-승인-2026-11-24), 보정 확장과 초안 복원은 [D-162](../sources/DECISIONS.md#d-162--원보고와-분리한-사용자-입력과-등록-내용-확정-2026-11-25), 기존 보정 계약은 [D-156](../sources/DECISIONS.md#d-156--보류-쪽의-재인식과-불변-문자-보정-2026-11-24)을 따릅니다.

- `/notifications`는 문서명·사건/대상 수·상태·시각·검토 행동을 기본64px 두 줄 행으로 표시합니다. 전체/읽지 않음/내용 확인 필요를 구별하고 읽음·삭제·닫기·열람을 등록 내용 확정으로 취급하지 않습니다.
- 서버의 안정된 workflow/보고 참조로 기기 간 기록을 읽습니다. 알림 이력·읽음·페이지 확인/보류·승인은 서버가, 미전송 사건·로컬 실행은 해당 PC가 보존합니다. OS 알림은 보조 전달이며 클릭은 정확한 작업 열기만 수행합니다.
- 단일 내용 제출은 변경분 저장 확인 → 현재 페이지 내용 선택 → 고정 입력 확정 → 실행으로 진행합니다. 미저장·충돌·판본 불일치는 후속 실행을 막고 원래 요청을 조회합니다. 다른 기기의 lease/영수증과 기존 실행 claim을 내부에서 확인하며 새 보고에 옛 선택을 적용하지 않습니다.
- D-153의 저신뢰 자동 진행은 D-154의 승인 대기로 대체됐습니다. D-156의 저장 성공도 승인이나 분석 완료를 뜻하지 않습니다. 서버 사건·원문 보고·수정 이력은 보존합니다.

## 남은 작업과 보류

1. **등록 재설계 후속:** PDF·이미지·DOCX/XLSX/PPTX 원본 대조, 위치/번호 탐색, 직접 입력·수정·빈 확인·파일 교체·보호 초안 복원을 개발본에 연결했습니다. Office는 기존 LibreOffice가 필요하고 구형 PPT는 격리 지원 여부에 따라 원본 열기를 제공합니다. 큰 원문의 고정 참조·AI 구간 분석과 기본 활성화 상태는 [analysis PLAN](../analysis/PLAN.md)을 따릅니다. 기존 그래프/진단 한도와 실제 개인 CLI·두 PC 재개·새 앱/서버 배포 검증은 남아 있습니다.
2. **관리자 콘솔:** [v6 시안](../../../app/tests/workspace-admin-proposal/DESIGN.md)의 별도 관리자 인증·가입 배정·공간/사용자·이력·종료 복귀를 실제 API/제품에 연결해야 합니다. 일반 계정·소속과 관리 인증을 분리합니다. [access 설계](../access/WORKSPACE_ADMIN_DESIGN.md)가 계약을 소유합니다.
3. **환경 검증:** Windows 실기기의 설치·보호 저장·개인 CLI·OCR·트레이·알림 허용/거부/클릭·종료/복원, 실제 두 PC 승인/이어가기는 미완료입니다. 현행 승인 검증과 새 D-158 흐름 검증을 구별합니다. Mac 서명·공증도 별도입니다.
4. **사용성·접근성:** 전체 화면 레퍼런스 반영을 완료로 선언하지 않습니다. 대표 자료의 세부 배치 대조, VoiceOver/NVDA 실제 음성·보조기술 전체 흐름·실기기 터치 검증은 남아 있습니다. 기존 페이지 확대 검사와 글자 전용 확대를 구별합니다.
5. **보류 범위:** 문서 대응 메뉴·역할별 관점 선택·원본 형식 내보내기는 숨김을 유지합니다. 관계 재추출 지난 기록·개념 색 범례·동일명 문서의 새 판본 등록은 별도 선택 전까지 진행하지 않습니다. 개인 결과물200개 문제는 답변 자동 복사 중단(D-094)으로 해소된 과거 항목입니다.

## 완료 조건과 근거

- 등록은 정상·직접 입력·내용 수정·파일/환경 문제·중단·한도·저장 미확인에서 적절한 행동을 제공하고, 성공한 단계를 반복하지 않은 채 Wiki/온톨로지 완료를 확인합니다. 원본/내용 동시 표시·대량 페이지 탐색·주요 행동 직접 노출을 검증합니다.
- 문서/초안/판본·권한·부분 결과를 보존하고, 화면 이동·재시작·계정/공간 전환·늦은 응답·충돌·응답 유실에서 다른 대상 표시나 중복 쓰기가 없어야 합니다. 실제 서버 영수증과 AI 출력/합성 결과를 구별합니다.
- 화면별 정상/실패·좁은 폭/확대·테마·키보드·focus 검증은 [RULES 완료 판정](RULES.md#완료-판정)을 따릅니다. 시안·개발본·설치본·실기기 검증 범위를 구별합니다.
- 실제 수행·실패·미실행은 [HISTORY](HISTORY.md)에 기록합니다. 이번 문서 정리의 검증은 [정리 기록](HISTORY.md#2026-11-25--ui-현재-계획과-개발-규칙-정리)을 따릅니다.
