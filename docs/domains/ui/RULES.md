# UI 설계·검수 규칙

2026-10-31 규칙 정의 완료. [D-087](DECISIONS.md#d-087--전체-ui의-설계-규칙과-완료-기준-확정-2026-10-31)에 따른 **제품 구현·검수의 기준**이다. 2026-10-31 제품 반영 범위와 실제 검증·미실행 항목은 [적용 기록](HISTORY.md#2026-10-31--확정-ui-규칙의-제품-반영)을 따른다. 색상은 사용자가 선택한 [D-086](DECISIONS.md#d-086--연속된-작업-면을-기준으로-색상-구성-선택-2026-10-31)의 연속된 작업 면을 따른다.

## 1. 적용 범위와 문서의 책임

- 로그인·연결 화면, 공통 앱 프레임, 현재 활성 업무 경로와 `/guide` 안내 화면, 각 화면의 읽기·편집·비교·검토·진행·복구 상태에 적용한다. 경로별 적용 범위는 12절에서 관리한다.
- 이 문서는 정보 위계·표현·조작·검수의 단일 기준이다. [IA](INFORMATION_ARCHITECTURE.md)는 실제 주소·대상·복귀 계약, [컴포넌트 설계](../../../app/docs/component-architecture.md)는 코드 책임·의존 방향, [토큰 가이드](../../../app/docs/design-tokens.md)는 토큰 사용·생성 방법을 맡는다. 과거 시안·감사의 제안과 충돌하는 시각 규칙은 이 문서를 따른다.
- 현재 제품에 들어간 수치의 원본은 [tokens.json](../../../app/design/tokens.json)이다. 아래 목표 수치를 문서 확정만으로 적용된 값이라고 표시하지 않는다. 구현 시 원본을 갱신하고 생성물을 만든다. 화면별 CSS에 같은 값을 따로 복사하지 않는다.
- 기존 API·권한·저장·판본·원문·판단 의미는 각 업무 도메인의 규칙을 유지한다. 시각적 통일을 위해 상태나 입력 항목을 없애지 않는다. 미지원 기능을 닮은 외형도 만들지 않는다.
- 예외는 해당 화면, 필요한 이유, 대체 규칙과 검증 범위를 기록한다. 긴 제목·확대에 따른 높이 증가와 그래프의 의미별 선 표현은 정상적인 변형이다. 화면마다 임의 padding·색·버튼 높이를 갖는 것은 예외로 인정하지 않는다.

## 2. 정보 우선순위와 노출

첫 화면에서 **어떤 대상인지, 무엇을 읽거나 판단하는지, 다음에 할 수 있는 행동이 무엇인지** 알 수 있어야 한다. 화면명·선택 대상명·설명을 같은 의미로 반복하지 않는다.

| 우선순위 | 기본 노출 | 적용 예 |
| --- | --- | --- |
| 주내용 | 항상 표시, 가장 큰 공간 배정 | 문서 본문, 검토할 주장과 근거, 대화, 변경 비교 |
| 판단에 필요한 정보 | 주내용·행동 가까이에 표시 | 현재 판본, 원문/전문가 근거 구별, 미저장, 차단 사유, 부분 조회 |
| 보조 속성 | 속성 영역 한 곳. 좁은 화면에서는 본문 뒤에 접어서 제공 | 설명·태그·형식·크기·관련 문서 |
| 처리·복구 정보 | 실제 상태 확인이나 다음 행동에 필요한 항목만 제공 | 저장 여부, 미완료 단계, 검사 이유, 변환 누락. 전체 응답 객체를 표시하지 않음 |
| 반복 안내 | 정상 화면에서 제거. 빈 상태·첫 입력·해당 오류에 배치 | 매 행의 ‘작성 정보 없음’, 정상 저장 절차 설명, 기능 소개 문단 |

- 주행동은 현재 작업 영역마다 하나를 우선 강조한다. 여러 독립 폼의 저장은 각각의 영역에 두되 화면 전체에 같은 강도의 버튼을 반복하지 않는다.
- 목록은 항목을 구별하는 정보, 상세는 이해할 정보, 편집은 입력과 검증, 검토는 근거와 판단, 진행 화면은 현재 단계와 가능한 행동을 우선한다.
- 복잡한 정보를 줄바꿈한 문장 하나로 나열하지 않는다. 동질 항목은 표·목록, 속성은 라벨/값, 선택 대상의 긴 내용은 상세 영역으로 표현한다.
- 원문 인용·조건·한정어는 요약 표시와 전체 확인 경로를 함께 둔다. 실제 본문이나 저장할 값을 디자인 목적으로 자르거나 정규화하지 않는다.
- 서버에 전달하거나 연결하기 위해 필요한 값이라는 이유만으로 화면에 표시하지 않는다. 접힌 영역도 같은 기준으로 선별하며, 내부 ID·해시·전체 JSON을 모아 두는 기술 정보 영역을 만들지 않는다. 원시 객체에만 있는 원문·조건·판단 이유·변경 전후 값은 읽기용 항목으로 옮겨 보존한다.

## 3. Base UI

### 3.1 크기·여백·정렬

수치는 CSS px, 100% 배율에서의 기준이다. 확대·사용자 글자 간격 설정에서는 내용이 잘리지 않도록 늘어난다. 높이는 border를 포함한 외곽 치수다.

| 항목 | 확정 규칙 |
| --- | --- |
| 기본 컨트롤 | 한 줄 Button/Input/Select 높이36, 글자13/줄 높이20, 모서리6, 경계1. 같은 행동 행은 같은 크기 사용 |
| 작은 컨트롤 | 조밀한 목록·보조 도구줄에서만 명시적으로32. 글자13/줄 높이20 유지. 공통 기본 스타일이 small을 덮지 않음 |
| 입력 내부 | 좌우12. 기본 세로7, 작은 세로5로20px 줄 높이와 경계를 합쳐36/32. 브라우저 기본 margin·font를 상속에 맡기지 않음 |
| Select | 텍스트 시작은 왼쪽12, 오른쪽에는36 확보. 16px 화살표 **박스의 오른쪽 끝**을 안쪽 경계에서12 떨어뜨림. 글리프 자체의 빈 공간과 박스 여백을 혼동하지 않음 |
| 버튼 | 텍스트 좌우12, 아이콘/텍스트 간격8. 아이콘 전용 버튼은36×36 또는32×32. 로딩 중에도 같은 폭·높이 유지 |
| Checkbox/Radio | 표시 크기16, 라벨과 간격8. 라벨을 함께 누를 수 있는 최소32px 높이 영역. 한 줄은 중앙, 여러 줄 라벨은 첫 줄 중심에 표시 정렬 |
| 간격 | 아이콘/텍스트·같은 행동 묶음8, 라벨/입력6, 필드 설명/오류4, 필드 사이16, 섹션 제목/내용12, 섹션 사이24 |
| 페이지 여백 | 주 작업 영역 폭900 이상은24, 미만은16. 페이지 소유자가 한 번 적용하며 자식 패널이 같은 외곽 여백을 중복 적용하지 않음 |
| 한 줄 행 | 컨트롤·아이콘·텍스트를 수직 중앙 정렬. 제목의 기본 margin을 제거하고 제목 줄 상자와 행동 줄 상자 정렬 |
| 여러 줄 속성 | 라벨80/값 나머지, 열 간격12, 최소 높이32. 첫 텍스트 줄을 맞춤. 입력 폭이 부족하면 라벨 위/값 아래로 전환 |
| 목록 밀도 | 일반 한 줄 행 최소44, 의미 있는 두 줄 문서 행 최소64, 검토함 두 줄 행 최소68. 고정 높이로 확대된 문자를 자르지 않음 |

컨트롤 전체가 높이36이어도 내부 input·버튼의 기준선이나 줄 높이가 다르면 실패다. 같은 도구줄을 함께 측정한다. flex/grid 자식에는 필요한 `min-width:0`을 두고 긴 값 하나가 다른 행동을 밀어내지 않게 한다.

### 3.2 문자와 아이콘

| 역할 | 기본 문자 크기/줄 높이·굵기 |
| --- | --- |
| 페이지·문서의 앱 제목 | 20/28·600. 제목은 줄바꿈 허용 |
| 섹션·패널 제목 | 14/20·600 |
| UI·컨트롤·목록 | 13/20·400, 이름·선택 강조는600 |
| 보조 속성·설명 | 12/18·400. 핵심 상태·행동을 작은 글자로 숨기지 않음 |
| 읽기 본문 | 16/26·400. 원문의 제목·목록·표 위계는 별도 Markdown 표현 유지 |

- UI는 시스템 서체를 공유한다. 원문 코드·터미널·기술 참조만 monospace를 사용한다. API 키나 파일 경로를 설명문과 같은 곳에 장식적으로 노출하지 않는다.
- 공통 Lucide 아이콘은16px, stroke1.75를 기본으로 한다. 탐색·페이지·상태에서 같은 행동은 같은 아이콘을 사용한다. 임의 문자 `^`, 이모지, 서로 다른 아이콘 세트를 섞지 않는다.
- 패널 열기/닫기는 좌우가 구별되는 패널 아이콘, 펼침은 chevron, 검색은 search, 새로고침은 refresh, 닫기는 x를 사용한다. 눈 아이콘을 패널 이동에 사용하지 않는다.
- 처음 접하는 업무 행동은 텍스트 버튼을 우선한다. 아이콘 전용 버튼은 접근 가능한 이름과 hover/focus 설명을 제공한다. 아이콘 크기와 클릭 영역 크기를 분리한다.
- 문장 안 링크는 본문의 줄 높이를 유지하는 유형이며 독립 버튼의36/32px 높이를 강제하지 않는다. 도움말은 focus로도 열리고 Escape로 닫을 수 있으며 내용을 확인하는 동안 사라지지 않는다.
- 목록의 긴 이름은 한 줄, 검토 요약은 두 줄까지 생략할 수 있다. focus/hover 및 상세에서 전체를 읽을 수 있어야 하며 `title` 속성만으로 해결하지 않는다. 입력·오류·의미 판단에 필요한 인용은 생략하지 않는다.

### 3.3 상태·입력·탭의 공통 표현

- default / hover / selected / focus / disabled / read-only / error / busy를 구별한다. selected+hover에서도 선택 표식을 보존하고 focus를 지우지 않는다. error+focus에서는 오류 경계·문구와 focus 표시를 함께 유지한다. disabled에는 hover·pressed 반응을 적용하지 않는다.
- 키보드 focus는 기본2px 외곽선과2px 간격으로 표현한다. 잘리는 컨테이너는 여백을 확보하거나 명시한 안쪽 표시를 사용한다. 색·면적의 최종 합성 결과를 검증한다.
- Field는 라벨·도움말·오류·필수 여부를 소유한다. placeholder는 라벨 대용이 아니다. 오류는 해당 입력의 경계와 짧은 문구를 함께 표시하고 연결된 설명으로 읽히게 한다. 여러 오류 제출 시 첫 오류로 이동하고 입력을 보존한다.
- 읽기 전용 값은 읽을 수 있는 대비를 유지하며 필요한 경우 선택·복사할 수 있다. 비활성은 현재 행동할 수 없다는 뜻이며 이유와 선행 행동을 근처에 둔다. 이유를 비활성 버튼의 tooltip에만 넣지 않는다.
- 탭은 같은 대상의 내용을 전환할 때 사용한다. 같은 목록을 좁히는 값은 필터다. 페이지 중간 탭도 페이지와 같은 바탕에 놓고 활성 글자+아래선으로 표시한다. 가짜 문서 탭·중복 탭 층은 만들지 않는다.
- 표는 머리와 셀의 출발선, 숫자 정렬, 행동 열의 위치를 맞춘다. 날짜/건수는 비교하기 쉬운 한 형식, 숫자는 오른쪽 정렬을 사용한다. 링크·버튼이 있는 행에 중첩 버튼을 만들거나 하위 행동이 행 열기를 함께 실행하게 하지 않는다.

## 4. Theme와 색상

### 4.1 색의 역할

- 페이지·제목·탭·도구줄·표 머리·일반 섹션은 하나의 작업 면으로 이어진다. 그룹은 제목·간격·정렬을 먼저 사용하고 필요한 구분선만 남긴다. 회색 띠, 카드 속 카드, 배경+테두리+그림자의 중복은 제거한다.
- 전역 탐색은 작업 면과 구별되는 중립색을 사용한다. 별도 패널은 하나의 경계로 나누며 펼침 메뉴처럼 실제로 떠 있는 면에만 그림자를 사용한다.
- hover는 중립색, 선택은 옅은 선택 면+선/체크, 주요 행동은 강조색 채움으로 구별한다. 선택 면을 정상 안내·모든 설명 상자에 재사용하지 않는다.
- 성공·주의·실패는 문구·아이콘을 함께 사용한다. 조치가 필요 없는 정상 설명에는 큰 상태색 상자를 쓰지 않는다. 오류·충돌·부분 결과의 의미는 색을 제거해도 전달되어야 한다.
- AI/전문가/후보 관계와 비교의 추가/삭제는 고유한 업무 의미를 유지한다. 일반 선택색으로 일괄 치환하지 않는다. 전문가 표시가 사실의 정확성·승인을 뜻하지 않는다.

### 4.2 제품에 반영한 공통 팔레트

| 선택 표시·링크·focus | `#B9431C` | `#4DAAFC` |
| 주요 버튼 배경 / 문자 | `#B9431C` / `#FFFFFF` | `#2563A6` / `#FFFFFF` |
| 주요 버튼 hover 배경 / 문자 | `#B03F1A` / `#FFFFFF` | `#2B70B8` / `#FFFFFF` |

주요 버튼의 활성 상태에서 전체 opacity/filter를 바꾸지 않는다. 순간적인 누름(`:active`)은 hover 배경과 안쪽1px의 currentColor 선을 사용하며 외곽 치수·위치는 바꾸지 않는다. 지속 선택 토글은 선택 면/표식과 `aria-pressed`를 함께 유지한다. disabled는 별도 상태이며 정상 설명까지 함께 흐리게 하지 않는다. selected+hover는 선택 면을 유지한다. destructive·성공·주의·실패·그래프 색은 기존 의미 토큰을 재사용하되 최종 문자/배경 대비를 통과해야 한다. 작은 후보 라벨처럼 기존 대비가 부족한 경우 선 색과 문자 역할을 분리한다. 테마를 바꾸어도 공간 위계와 상태 의미는 동일하다.

## 5. Layout과 공간 배분

주 작업 영역 폭 W는 전역 메뉴를 제외한 페이지 컨테이너의 border-box 너비이며 페이지 gutter를 빼기 전에 측정한다. 3절의 gutter와 아래900/1200 전환점은 모두 W를 사용한다. 본문·패널의 실제 너비는 gutter를 뺀 안쪽 공간에서 배분한다. 창 전체 viewport 폭 및 접근성 재배치 검사의320px와 혼동하지 않는다.

| 유형 | 확정 배치 |

| 공통 프레임 | 상단52, 단일 메뉴208/접힘60, 상태줄26 유지. 중복 탐색기·활동 표시줄과 미지원 MDI 제거 원칙 유지 |

- 좁아지면 글자·컨트롤을 축소하지 않고 배치를 바꾼다. 본문+보조영역은 주 작업 폭900 미만에서 본문 우선 한 열로 전환한다. 목록+상세 작업은 선택한 영역으로 전환하고 복귀 버튼을 제공한다.
- 세 영역 작업은1200 이상에서 모두 표시한다. 900~1199에서는 중심 내용과 선택 상세를 우선하고 목록은 명시적으로 전환한다. 900 미만에서는 현재 작업 한 영역을 표시한다. 현재 패널/선택/초안은 유지한다.
- 일반 폼의 제한 폭은 작업 영역 안에서 가운데 맞춘다. 의도적인 읽기 폭을 제외하고 오른쪽에 상시 빈 패널·무의미한 여백을 남기지 않는다. 없는 자료를 샘플 카드로 채우지 않는다.
- 관계도·줄 비교 등 공간을 사용하는 화면에 읽기 본문의760px 제한을 적용하지 않는다. 그래프의 출처 상자·선 폭은 일반 컨트롤과 역할이 다르다.

## 6. 조작·이동·초안

- 이름 링크는 이름에 해당하는 실제 대상을 연다. 문서 목록은 상세 페이지로, 검토함의 선택은 목록 옆 상세로, 상세의 업무 행동은 해당 대상의 기존 작업 화면으로 연결한다. 이름을 눌렀는데 다른 문서나 첫 개념을 대신 열지 않는다.
- 패널 제어는 움직이는 패널의 시작점·경계 또는 그 패널의 제목줄에 둔다. 왼쪽 목록을 오른쪽 끝 아이콘으로 제어하지 않는다. 닫힌 쪽에 열기 버튼, 열린 패널 제목줄에 닫기를 제공한다. 버튼 이름과 expanded 상태를 함께 갱신한다.
- 탐색 선택과 수정 시작을 구별한다. 항목 클릭만으로 편집·검토 저장·분석·재실행을 시작하지 않는다. 오른쪽 패널을 닫는 행동도 작업 중단·초안 폐기가 아니다.
- 주소·뒤로가기·직접 진입은 [IA 6·7절](INFORMATION_ARCHITECTURE.md#6-화면-이동-규칙)의 대상/복귀 계약을 따른다. 검색·필터·페이지·선택·읽던 위치는 같은 접근 범위 내에서 복원한다. 기능이 없는 정렬 상태는 추가하지 않는다.
- 패널/탭 전환·창 크기 변경으로 초안·기준 판본·선택·포커스를 초기화하지 않는다. 닫기/복귀 시 시작 버튼 또는 선택 항목으로 초점을 돌린다. 이미 없는 항목이면 목록 제목 등 유효한 위치를 사용한다.
- 접근 범위가 바뀌면 이전 자료·늦은 응답을 새 화면에 표시하지 않는다. 현재 표시·접근성 트리에서 제거하고 범위별 보호 세션·초안은 기존 계약에 따라 격리 보존한다. 모든 초안을 영구 삭제하거나 다른 공간에 복원하는 새 정책을 UI 변경으로 도입하지 않는다.
- 파괴적 변경·복원·초안 폐기는 대상과 효과를 해당 행동 옆 확인 영역에 표시하고 명시 실행한다. 기존 도메인 확인 절차를 유지하며 일반 읽기·탐색에 확인을 추가하지 않는다.
- 업무 모달을 다시 만들지 않는다. 짧은 메뉴·선택 팝오버와 OS 파일 선택/저장 창만 해당 용도로 사용한다. Escape는 입력 보조 메뉴 등 가장 가까운 열린 요소를 닫고, 저장·실행 취소·초안 폐기를 뜻하지 않는다.
- 현재 작업의 성공은 해당 대상과 결과 가까이에 표시한다. 다른 화면의 작업 완료가 현재 화면·입력·focus를 가로채지 않게 한다. 복구가 필요한 상태는 일시 알림만으로 숨기지 않는다.

## 7. 상태 화면과 복구

공통 컴포넌트의 색·간격은 공유하되 서로 다른 업무 상태를 단일 ‘처리 중/완료’로 합치지 않는다. 모든 메시지는 현재 상태와 가능한 다음 행동을 알려준다.

여러 패널로 나뉜 화면에서도 본문을 대신하는 로딩·빈 상태·오류는 공통 패널의 배경·테두리·모서리를 유지한다. 조회 안내·갱신 오류·누락 정보는 해당 패널의 제목/필터 뒤에 두고, 안내가 나타났다고 헤더를 아래로 밀거나 패널 밖에 띄우지 않는다. 좁은 화면에서 선택한 영역으로 전환해도 필요한 안내는 현재 보이는 영역에서 확인할 수 있어야 한다.

| 상태 | 표현·행동 |
| --- | --- |
| 첫 조회 | 내용 영역에 로딩 표시. 스켈레톤은 실제 결과의 표 열·행 밀도·패널·도구줄·읽기 폭과 반응형 배치를 재사용하고, 자료가 필요한 부분만 자리표시자로 바꾼다. 실제 완료율이 없으면 퍼센트/예상 시간 표시 금지 |
| 새로고침 | 같은 접근 범위의 읽던 내용을 유지하며 갱신 중임을 표시. 권한 회수된 내용은 유지하지 않음 |
| 처음부터 자료 없음 | 해당 자료의 첫 생성/등록 행동. 사용할 수 없는 기능은 제안하지 않음 |
| 검색 결과 없음 | 검색/필터 조건과 초기화. 전체 자료가 없다고 표시하지 않음 |
| 아직 실행하지 않음 | 실행 전 상태와 실제 준비 행동. 조회 오류·빈 결과와 구분 |
| 일부 조회·이전 자료 | 영향 범위와 다음 페이지/다시 읽기. ‘불러온 범위의 필터’·누락·제외를 짧게 유지 |
| 읽기 전용·차단 | 읽기 가능한 정보 유지, 제한 이유와 실제 준비/권한 확인 경로 |
| 입력 오류 | 해당 필드 문구·연결된 오류 상태. 입력 유지, 수정 후 재검증 |
| 미저장·저장 중 | 현재 작업 가까이 표시. 저장 중 중복 제출 방지, 다른 읽기/안전한 탐색은 계약에 따라 유지 |
| 저장 성공 | 저장된 대상과 후속 행동. 뒤이은 재조회 실패를 저장 실패로 바꾸지 않음 |
| 저장 성공+정리 경고 | 저장 완료와 정리 문제를 따로 표시. 자동 재저장 금지 |
| 충돌 | 내 초안과 최신 기준을 유지하고 기존 비교·재작성으로 연결. 기준 판본만 바꿔 재전송 금지 |
| 결과 미확인 | 원래 요청의 결과 확인 제공. 실패로 단정하거나 자동 재실행/재저장하지 않음 |
| 일부 완료 | 실제 보관/저장된 것과 미완료 단계를 구분. 원본 등록 성공을 Wiki 생성·추출 완료로 표시하지 않음 |
| 실행 중·중단·취소 | 기기 실행 중단과 서버 작업 취소의 대상/효과 구분. 중단 후에도 저장된 결과 보존 |
| 조회·실행 실패 | 해당 영역에서 이유와 허용된 복구 행동. 읽기 재시도와 변경 재요청을 구별 |
| 없는 대상·접근 불가 | 정확한 상태와 복귀/접근 재확인. 임의의 다른 문서·최신 주장을 대신 선택하지 않음 |

색 배지·상태 제목·설명에서 같은 문장을 세 번 반복하지 않는다. 성공/보조 설명은 짧게, 오류·충돌·불완전 조회·미저장처럼 판단을 바꾸는 정보는 해결 전까지 해당 작업에서 확인 가능하게 유지한다.

## 8. 용어·내용·데이터 표시

- 문서 제목, 원본 파일명, 주어·관계·목적어, 질문 제목처럼 사용자가 이해하는 이름을 먼저 표시한다. 서버 UUID·해시·작업/주장 ID를 제목·행·badge의 대체 이름으로 사용하지 않는다.
- 이름이 없으면 ‘제목 없는 문서’, ‘이전 검토 기록’처럼 종류를 밝히고 실제 인용·종류·제공된 날짜 등으로 구별한다. 없는 작성자·시간·판본 번호를 만들지 않는다. 접근 불가 대상은 이름 유추 없이 상태를 표시한다.
- 사용자가 직접 정하는 저장 파일명·경로, 원본 파일명, 설정의 서버 주소는 업무 정보다. 내부 ID와 혼동해 제거하지 않는다. 실제 참조 값과 저장 인자는 표시명 변경과 별개로 보존한다.
- 원문에 실제로 존재하는 정의 키·외부 식별자·코드와 원문 자체의 JSON 인용은 업무 내용으로 유지한다. 서버 소유 참조를 직접 입력하는 폼과 응답 객체 전체를 편집하는 폼은 사용자 업무 화면에 두지 않는다.
- ‘저장’은 저장 대상이 명확할 때만 사용한다. ‘개인 초안 저장’, ‘Markdown 내려받기’, ‘변경 저장’, ‘이 판본으로 복원’, ‘원문 검토’, ‘전문가 판단’은 효과가 다르므로 구별한다. 원문 기반 검토와 전문가 업무 판단의 권한·이유·이력도 합치지 않는다.
- ‘확인’, ‘적용’, ‘열기’만으로 대상이 불명확하면 대상/효과를 붙인다. ‘새로 읽기’와 ‘AI 다시 실행’을 구별한다. 기술 phase나 서버 오류 코드를 일반 상태 이름으로 그대로 사용하지 않는다.
- 원문·작성 당시 고정 근거·현재 문서·전문가 기록을 서로 바꾸어 표시하지 않는다. 출처·한정어·부분 범위는 시각적 단순화를 이유로 없애지 않는다. 의미를 판단할 전체 정보는 상세에서 읽을 수 있어야 한다.
- 날짜는 실제 제공된 값만 공통 형식으로 표시한다. 날짜 `YYYY.MM.DD`, 시각이 필요한 기록 `YYYY.MM.DD HH:mm`, 시간대는 사용자 환경 기준이며 전체 시각 확인 시 명시한다. 상대 시각만 단독 제공하지 않는다. 수량0·미확인·미제공을 구별한다.
- 오류 문장은 문제→가능한 행동 순서로 쓴다. 서버 오류 코드·stack trace·내부 참조를 그대로 표시하지 않으며 실제 원인·저장 상태·복구 행동은 유지한다. 정상 화면에 구현 설명·모델 내부 처리 안내를 상시 전시하지 않는다.

## 9. 반응형·스크롤·모션

- 전역 메뉴의 창 폭900 미만 기본 접힘은 유지한다. 내부 패널 전환은 5절의 주 작업 폭을 기준으로 한다. ‘좁은 화면’을 모든 곳에서 서로 다른 임의 media query로 정의하지 않는다.
- 일반 목록·문서 읽기·등록·설정은 페이지 안 주 스크롤 하나를 둔다. 외곽 페이지와 같은 방향의 내부 본문 스크롤을 중첩하지 않는다. 원본 미리보기처럼 자체 뷰어가 필요한 경우에만 내부 스크롤을 허용하고 해당 영역을 명확히 표시한다.
- 지도/목록/상세, 대화/근거, 이력/비교처럼 독립 탐색이 필요한 작업은 패널별로 스크롤할 수 있다. 이때 외곽 작업 공간은 같은 방향으로 함께 스크롤하지 않는다. 접힌 패널의 위치도 복원한다.
- 목록 도구·편집 행동을 고정할 때는 내용과 focus가 가려지지 않도록 한다. 여러 sticky header를 쌓지 않는다. 일반 도구줄은 줄바꿈/보조행을 사용하고 핵심 행동을 가로 스크롤 밖에 숨기지 않는다.
- 앱 전체 viewport320 CSS px에서 메뉴·여백을 포함해 재배치하고 일반 읽기·입력·행동의 누락과 페이지 전체 가로 스크롤이 없어야 한다. 메뉴를 제외한W만320으로 맞춰 검사하지 않는다. 200% 글자 확대도 별도로 확인한다. 본질적으로 이차원인 지도·비교 표는 해당 영역의 가로 이동을 허용하고 목록/텍스트 확인 경로를 유지한다. 좁은 화면에서 보조 열을 숨길 경우 상세나 재배치한 행에서 같은 정보·행동을 제공한다.
- hover 등 짧은 변화는 기존150ms를 기준으로 하며 레이아웃 이동을 장식으로 사용하지 않는다. 움직임 줄이기 설정에서는 불필요한 전환·점멸을 멈추고 정적 상태 표시는 유지한다. 진행 중임을 애니메이션만으로 전달하지 않는다.

## 10. 키보드와 접근성

검증 목표는 **WCAG 2.2 AA**다. 특정 라이브러리 사용·토큰 검사·아래 일부 항목 통과만으로 앱 전체 적합성을 주장하지 않는다. W3C 기준은 접근성 기준이며 색 조합의 미감이나 페이지의 구체적 padding을 지정하지 않는다. 아래 프로젝트 선택값과 표준 요구사항을 구분한다. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

- 일반 문자·보조문·placeholder는4.5:1 이상, 큰 문자는3:1 이상. 현재13px UI는 일반 문자다. hover·선택·오류가 합성된 실제 바탕에서 검사하며 판정 전에 반올림하지 않는다. 비활성 요소의 예외를 읽기 전용 본문에 적용하지 않는다. [1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 입력·선택·focus를 식별하는 데 필요한 시각 정보와 의미 있는 그래픽은 인접색 대비3:1 이상. 모든 장식선·패널 배경이나 기본색과 hover색 사이에3:1을 강제하는 규칙은 아니다. 색만으로 의미를 전달하지 않는다. [1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)
- 모든 조작은 키보드로 가능하고 focus가 보이며 제작한 고정 영역에 완전히 가려지지 않아야 한다. 프로젝트의2px/2px 표시는 구현 규칙이다. WCAG의 초점 면적에 관한2.4.13은 AAA이므로 AA 의무로 설명하지 않는다. [2.4.7](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
- AA 포인터 대상 기준은24×24 CSS px 또는 명시된 예외다. 프로젝트는 일반 버튼36/작은 버튼32를 사용하며 터치 주입력 환경에서는 독립 버튼의 누르는 영역44를 확보한다. 44를 WCAG AA 의무로 표시하지 않는다. [2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 일반 콘텐츠는 전체 viewport320 CSS px 폭에서 정보·기능 손실과 양방향 스크롤 없이 재배치한다. 본질적 이차원 영역의 예외는 그 영역에만 적용한다. 텍스트 간격 변경·200% 확대도 별도 확인한다. [1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- 확대는 사용 가능한 방식으로200%까지 정보·기능 손실이 없는지 검사하며 페이지 확대도 인정된다. 글자 전용 확대를 별도 시험했다면 그 결과를 구별한다. 사용자 간격은 줄1.5배·문단 뒤2배·글자0.12em·단어0.16em으로 변경해 누락·잘림·행동 접근을 확인한다. 이 간격을 제품 기본값으로 강제하는 요구는 아니다. [1.4.4](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), [1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)
- 네이티브 button/link/input/select를 우선하고 시각 순서와 읽기·focus 순서를 맞춘다. 제목 단계, 폼 라벨, 표 머리, 아이콘 이름, 선택·펼침·오류 상태를 프로그램으로 읽을 수 있게 한다. 숨긴 화면·패널에는 focus가 들어가지 않아야 한다.
- 탭은 tablist/tab/tabpanel 연결과 선택 상태를 갖는다. Tab은 선택 탭으로 진입한 뒤 패널로 나가고 방향키는 탭 사이를 이동한다. 지연 조회가 있는 탭은 Enter/Space로 활성화한다. 단순 필터를 tab 역할로 위장하지 않는다. [WAI-ARIA 탭 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)
- 완료·실패 같은 중요한 상태 변화는 화면을 가로채지 않고 보조기술에 알린다. 반복 진행 로그 전체를 계속 읽지 않는다. 메뉴·상세 닫기 후 focus 복귀, 포커스 함정 없음, 한글 조합 중 Enter 오발송 방지를 실제로 확인한다.

| `/settings` | 서버·계정·작업 공간, AI 선택, 프로그램 위치, 로그인/진단·사용량, 저장/연결 실패 | 실제 단위별 저장: 공간 선택 적용, AI 선택 즉시 요청, 프로그램 위치 별도 저장. 전역 저장 추가 금지 |
| `/guide` | 로그인 전후 진입, 실제 화면·조작 위치·단계 이동·확대, CLI 선행 설치와 공식 안내, 상세 설명·복귀 | 앱에 포함한 읽기 전용 안내. 업무 bridge·자료 접근 없이 읽으며 기존 업무 화면과 초안 보존 |

`/connections`는 기존 숨김·호환 이동을 유지하며 활성 메뉴로 복원하지 않는다. `/renewal/*`·루트·알 수 없는 주소는 현재 호환/오류 계약을 검증한다. 미지원 파일·웹 테스트 모드의 제한·읽기 전용 등 환경별 기능 차이도 실제 capability를 따라야 한다.

### 완료 판정

1. **공통 기반:** 같은 역할의 컨트롤·문자·여백·상태를 실제 계산된 스타일로 대조한다. 작은 크기, Select 양쪽 여백, 행 중심, 누름/선택/오류/비활성, 긴 값/한글을 포함한다. 해당 요소의 selected+hover, selected+focus, error+focus, disabled+hover, busy+focus 조합도 확인한다. 공통 수정 후 모든 사용처의 개별 override를 확인한다.
2. **화면별 흐름:** 위 표의 하위 작업마다 같은 자료·상태·창 크기로 전후를 비교한다. 주내용·주행동·보조 정보의 위치와 선택 맥락을 확인한다. 동일한 기능을 가진 실제 컴포넌트를 사용하고 모의 데이터 여부를 밝힌다.
3. **폭·테마·내용:** 밝음/어두움, viewport1440×900·1280×720·480px·320 CSS px 재배치와200% 글자 확대를 확인한다. 메뉴 기준 viewport899/900/901 및 내부 배치 기준W899/900/901·1199/1200/1201을 따로 측정한다. 짧은/긴 제목, 빈/여러 항목, 오류/부분 결과를 포함한다.
4. **기능과 접근성:** 목록→상세→편집/비교→저장/복원, 검토함→정확한 대상, 패널 전환/복귀, 키보드·focus·초안·기준 판본·접근 범위 보존을 확인한다. 색·컴포넌트 검사와 실제 업무 동선을 별도로 기록한다.
5. **판정 기록:** 작업한 범위의 화면·상태·테마·폭, 실제 검증 결과와 미실행 항목을 [HISTORY](HISTORY.md)에 남긴다. 빌드 성공·정상 화면 한 장만으로 디자인 완료라 하지 않는다. 남은 화면/상태가 있으면 적용 완료 범위를 제한한다.

예외나 실패가 발견되면 해당 공통 규칙 또는 구현을 고친 뒤 영향을 받은 화면을 다시 확인한다. 화면별 임시 스타일로 덮어 일관성 검증을 통과시키지 않는다. 토큰/공통 요소→화면 유형→하위 작업/예외 상태 순서로 적용하며 새 수정도 같은 검수 기준을 따른다.
