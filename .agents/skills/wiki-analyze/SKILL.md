# Wiki 분석 실행

이 스킬은 기존 분석 도구의 실행 순서를 안내한다. 추출 의미 기준과 제출 스키마는 서버의 발행 규약 또는 프로젝트의 기존 공통 지침을 사용한다.

## 실행 경로 선택

1. `access_context`로 tenant·권한·허용 profile을 확인하고 실제 노출된 도구를 확인한다. 조회만 가능한 연결에서는 초안·필요 작업을 설명하고 저장이나 권한 설정 변경을 대신 실행하지 않는다.
2. 사용자가 요청한 대상·산출물·저장 여부를 정한다. 이미 저장까지 요청했다면 다시 허락을 묻지 않는다. 새 원본의 등록·분석 작업 생성은 기존 등록 UI/API가 맡으며 존재하지 않는 MCP 등록 도구나 `job_id`를 만들지 않는다.
3. 등록된 `job_id`를 실행할 때는 [분석 작업 절차](references/analysis-job.md)를 읽는다. 작업에 속한 저장은 작업 전용 도구와 영수증을 사용한다.
4. 기존 Wiki 문서의 그래프만 생성·재생성하는 요청은 아래 절차를 사용한다. 서버 코드·스키마·추출 프롬프트 개발은 이 실행 절차의 범위가 아니다. 원문 분리 평가 세션에서는 부모가 정한 입력 제한을 우선하며 이 스킬이나 추가 프로젝트 문서를 자동 입력하지 않는다.

## 기존 문서의 온톨로지 생성

- `wiki_read`로 대상의 전체 본문과 revision을 함께 읽고 `ontology_review_query`로 현재 검토 상태를 확인한다. [온톨로지 규칙](../../../docs/domains/ontology/RULES.md)과 [공통 의미 지침](../../../.agent/ontology_semantics.md)을 적용한다.
- 최신 도구 스키마에서 지원하는 버전·타입·관계·필드를 확인한다. schema version 숫자만 올리거나 기본값을 최신 규약이라고 추정하지 않는다.
- 대상 전체 원문에서 추출한다. 참조 문서의 설명·예외는 해석에 사용하되 대상 원문 인용으로 위조하지 않는다. `effective_graph`·profile의 일부·조회 `focus`를 전체 생성 입력으로 쓰지 않는다.
- `ontology_generate`에는 실제 읽은 `expected_revision`과 전체 그래프를 전달한다. 검토 이력이 있으면 해당 조회의 `state_revision`을 `expected_state_revision`으로 함께 보낸다. 비어 있는 배열도 기존 그래프 전체를 교체하므로 추출 실패·부분 읽기의 대용으로 제출하지 않는다.
- 원문·그래프·검토 충돌은 최신 근거를 비교해 재추출한다. 이전 그래프의 버전값만 바꿔 재전송하거나 옛 승인을 이식하지 않는다.

## 결과 확인

저장 응답과 최신 그래프/검토 조회로 실제 저장 상태를 확인한다. 본문 저장, 그래프 저장, 자동 검사, 의미 정확성, 사람 검토는 별개다. 추출 주장은 저장만으로 승인되지 않는다. 대상·입력/출력 revision·누락·미검토 상태와 남은 단계를 보고한다.

성공 응답의 `cleanup_failures`는 정리 문제로 별도 보고하고 쓰기를 반복하지 않는다. 그래프 실패로 이미 저장된 위키를 다시 쓰지 않는다. 도구 응답을 잃었으면 먼저 현재 상태 또는 해당 요청 영수증을 조회하며 성공·실패를 임의로 단정하지 않는다.
