# Wiki 연결과 실행 준비 진단

프로젝트의 [실행 안내](../../../README.md)와 [기존 진단기](../../../tools/runtime_doctor.py)를 필요한 범위에서 사용한다. 앱 연결, 서버 권한, 개인 실행기, AI 제공자 상태를 구별하고 실제 실패한 계층을 확인한다.

## 확인할 범위

- 사용자 증상과 현재 설정에서 대상 서버·워크스페이스·개인 실행 경로를 확인한다. 토큰 원문을 출력하거나 문서에 복사하지 않는다. 현재 도구 목록과 저장소 구현은 다를 수 있다. 도구 누락만으로 서버 미구현이나 권한 부족 중 하나로 단정하지 않는다.
- 설치된 프로젝트 Python으로 `-m tools.runtime_doctor --help`에서 실제 옵션을 확인한다. macOS 프로젝트의 기본 예시는 `.venv/bin/python -m tools.runtime_doctor --skip-ai`이다. Python이 없으면 기존 실행 환경 위치를 확인하고 설치 명령으로 자동 전환하지 않는다.
- API/MCP 연결 검사에는 확인된 동일 백엔드의 `--server`, 기존 보호 파일의 `--token-file`을 함께 전달하고, 대상이 정해져 있으면 `--tenant`를 사용한다. profile은 필요할 때 실제 허용 값만 지정한다. 토큰을 명령 인자 자체에 넣지 않는다. 필수 연결 정보가 없으면 로컬 준비 상태부터 확인하고 필요한 값만 요청한다.
- 개인 AI 실행이 문제이면 현재 선택된 `--ai-provider codex|claude`와 확인한 `--ai-cli`를 사용한다. 연결 문제만 조사할 때는 `--skip-ai`로 관련 없는 제공자 확인을 생략한다. 실제 모델 호출, 로그인, 토큰 재발급, 패키지 설치, 서버 재시작은 진단의 부수 동작이 아니다.

## 결과 해석

- 의존성 일치, 변환기/OCR 준비, CLI 기능, 로그인 정보 존재, 인증 API 응답, MCP 초기화·도구 목록, 접근 맥락 대조 결과를 구분한다. 성공한 계층까지 실패로 묶지 않는다.
- 로그인 정보 존재는 실제 모델 호출 성공이나 남은 사용량을 뜻하지 않는다. API/MCP의 사용자·정책·소속 일치는 영구 백엔드 동일성 증명이 아니며 쓰기 시험도 아니다. `not_run`·`unavailable`을 성공이나 0으로 표시하지 않는다.
- 접근 거부·정책 오류는 현재 구성에서 보고한다. 다른 토큰·tenant·legacy로 우회하거나 오류 설정을 초기화하지 않는다. 수정까지 요청된 경우에만 원인에 맞는 최소 변경을 별도 범위로 진행한다.
- 실행한 진단과 실패 계층·사용자에게 필요한 다음 행동·미검증 범위를 짧게 보고한다. 원시 CLI/전송 로그에 비밀이 있을 수 있으므로 정제된 진단 결과를 우선한다.
