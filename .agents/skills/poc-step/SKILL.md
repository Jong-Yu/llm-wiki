# 요청한 단계 수행

## 범위와 읽기

- 실제 프로젝트 경로와 적용 AGENTS를 확인합니다. [루트 경로 표](../../../AGENTS.md#읽을-범위)에서 주 도메인을 정하고 `docs/domains/<도메인>/PLAN.md`의 현재 상태/완료 조건과 `DECISIONS.md`의 관련 절만 읽습니다.
- 도메인이 정해졌으면 루트 색인·다른 도메인·과거 기록을 반복해서 읽지 않습니다. 기존 구현/테스트를 필요한 범위에서 확인하고 요청한 한 단계만 진행합니다.
- 해당 동작을 다룰 때만 같은 폴더의 RULES와 실제로 영향을 주는 다른 도메인의 계약을 추가합니다. 질문·진단에는 구현/검증 절차를 자동 시작하지 않습니다.

## 작업 규모와 검증

| 규모 | 수행·검증 |
| --- | --- |
| 문구·스타일·작은 수정 | 직접 처리. 관련 내용·링크·표시/동작만 확인. 사소한 변경에 새 설계/결정/테스트를 만들지 않음 |
| 일반 기능 | 소유 PLAN의 완료 조건과 관련 정상·실패 경로를 실제 검증 |
| 저장·권한·공유 계약 | 관련 RULES/계약, 격리 데이터의 보존·충돌·실패·호환 검증. 위키 원문·원장·기존 사용자 파일로 쓰기 시험하지 않음 |

공통 영향·통합 이정표·원인 미확인 회귀가 있을 때만 전체 검증으로 넓힙니다. 이미 통과한 검증은 새 변경·실패·미해결 근거가 있을 때만 반복합니다. MCP 변경은 프로젝트 `.venv`와 README의 해당 명령을 사용합니다.

독립 전문 작업의 분리 이득이 있을 때만 [협업 규칙](../../../docs/domains/workflow/COLLABORATION.md)을 적용합니다. 추출/스키마/프롬프트 변경은 [의미·원문 분리 평가](../../../docs/domains/ontology/EVALUATION.md)와 ontology RULES를 따릅니다. 형식 통과와 의미 정확성, 실제 사람 판단과 모의를 구분합니다. 원문 분리 세션에는 부모가 필요한 규칙·허용 입력만 전달하며 일반 시작 문서 읽기를 요구하지 않습니다.

## 기록과 종료

- 완료 조건을 충족하면 해당 도메인 PLAN의 현재 상태를 교체합니다. 실제 검증/미실행/남은 한계는 같은 폴더 HISTORY에 짧게 추가하고 기존 기록을 보존합니다. 문서만 바뀌면 링크·구조·내용 검증으로 기록합니다.
- 중요한 선택만 소유 DECISIONS에 기록하고 전역 결정 색인에 유일한 번호를 등록합니다. 실행 방법이 달라졌을 때만 README를 갱신합니다.
- 이번 작업의 불필요한 임시 산출물만 정리합니다. 변경 파일·실제 검증·다음 작업을 간단히 보고하고 요청받지 않은 다음 단계는 시작하지 않습니다.
